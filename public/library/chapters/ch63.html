    TOPIC 63 / 64 · Alternative I/O Models

    Readiness is permission to try

    An edge-triggered event loop reads one chunk and never wakes for the remaining buffered data.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    select, poll, and epoll report readiness; they do not perform the application's transfer. Readiness can change before the application acts. Nonblocking I/O keeps a stale readiness observation from turning into an unintended wait. Completion APIs such as io_uring use another model with explicit request and buffer lifetimes.

    Contract and implementation boundary

    For edge-triggered epoll, drain until EAGAIN while enforcing fairness through a ready-work queue if a budget ends early. EOF and errors are outcomes to handle, not just data events. With level triggering, a still-ready descriptor is reported again. select modifies its fd sets and has descriptor-range constraints.

    Contract references: epoll.7 · poll.2 · select.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Doing only one read after an edge can strand data. Registering write readiness permanently can create a hot loop because healthy sockets are often writable. Reusing a descriptor number can invalidate an event's application identity if ownership is not tracked.
