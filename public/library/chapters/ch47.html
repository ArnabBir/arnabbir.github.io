    TOPIC 47 / 64 · System V Semaphores

    Semaphore sets can make atomic reservations

    A worker needs two resource permits and deadlocks by acquiring them separately.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    A System V semaphore set stores integer counters. semop can apply a vector of changes atomically, so a caller can request a compound reservation without exposing a half-acquired state. Negative operations consume availability, positive operations release it, and zero operations wait for zero.

    Contract and implementation boundary

    If a vector cannot complete, its changes are not partly committed. IPC_NOWAIT requests failure instead of waiting. SEM_UNDO tracks selected process adjustments for termination, but it is not a transaction log for application data. Initialization and readiness publication still need a creator protocol.

    Contract references: semop.2 · semget.2 · semctl.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    An undo adjustment cannot repair a half-written shared record. Holding unrelated resources while blocked can still form a deadlock outside the semaphore set. Do not infer success from a counter sample taken before semop.

    Worked reasoning trace

    Assumptions: Semaphore counters [1,0]; atomic two-decrement vector with IPC_NOWAIT.

    1. Starting state

      First counter alone could satisfy its decrement.

    2. Operation

      Second decrement cannot proceed.

    3. Expected observation

      The whole vector fails and counters remain [1,0].

    Tradeoff: Compound reservations prevent partial acquisition within the set, not every external deadlock.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Use two counters initially [1,0]. Evaluate the vector [-1,-1] with IPC_NOWAIT, then after adding one to the second counter. Explain why the failed first attempt must leave both counters unchanged.

    Check your understanding

    One operation in a semop vector cannot proceed. Are earlier operations in that vector committed?

    Explain the answer

    No. The vector is applied atomically or waits/fails without that partial update.

    The whole vector fails and counters remain [1,0].
