Chapter 33 — Threads: Further Details

Advanced thread topics: controlling stack size, the complex interaction of signals with threads, the danger of fork() in multithreaded programs, and the NPTL implementation that replaced the older LinuxThreads library.

These are the areas where subtle bugs hide in production: a signal delivered to the wrong thread, a fork() that leaves mutexes in unknown states, or a thread stack overflow that silently corrupts adjacent memory.

Invariant
Signal disposition is process-wide; signal mask is per-thread. Use pthread_sigmask + sigwait for clean signal handling in threaded programs.
Gotcha
fork() in a multithreaded program duplicates only the calling thread. Mutexes held by other threads are locked forever in the child.
Debugging
Check /proc/PID/task/TID/status for per-thread signal masks; use RLIMIT_STACK or pthread_attr_setstack to control stack sizes.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Each thread gets its own stack (default ~8 MB on Linux). Adjustable via pthread_attr_setstacksize or pthread_attr_setstack (provide your own memory). Guard pages detect overflow.
  • Signals + threads: signal dispositions (handlers, SIG_IGN, SIG_DFL) are process-wide. Signal masks are per-thread (pthread_sigmask). A signal sent to the process is delivered to an arbitrary thread that doesn't block it.
  • Best practice for signals in threaded programs: block all signals in all threads except a dedicated signal-handling thread that calls sigwait() or uses signalfd(). This avoids reentrancy hazards entirely.
  • fork() in a multithreaded program: only the calling thread survives in the child. All other threads vanish, but mutexes they held remain locked -- the child is in an unpredictable state.
  • Solutions to the fork+threads problem: (1) exec() immediately after fork, (2) use posix_spawn(), (3) use pthread_atfork() to reset mutex state, or (4) avoid fork in multithreaded programs entirely.
  • NPTL (Native POSIX Threads Library) uses clone(CLONE_VM|CLONE_THREAD|...) for 1:1 threading. Each thread is a kernel task. Replaced the older LinuxThreads which had many non-conformances.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Thread stacks
  • Default stack is ~8 MB virtual (not all committed). Guard pages (typically 1 page) detect overflow by causing SIGSEGV.
  • Creating thousands of threads with default stacks exhausts virtual address space on 32-bit systems. Use smaller stacks for lightweight workers.
  • pthread_attr_setstack lets you supply your own mmap'd memory. You are responsible for alignment and guard pages.
  • Stack overflow past the guard page corrupts adjacent memory silently. Recursive functions and large stack allocations (alloca, VLAs) are common triggers.
Signals and threads
  • Signal dispositions (handlers) are process-wide: sigaction in any thread affects all threads.
  • Signal masks are per-thread: each thread independently blocks/unblocks signals via pthread_sigmask.
  • A process-directed signal (kill(pid, sig)) is delivered to an arbitrary thread that has the signal unblocked. Thread-directed signals (pthread_kill, tgkill) go to a specific thread.
  • Best practice: block all signals in all threads at startup, then create one dedicated thread that calls sigwait() in a loop. This avoids async-signal-safety problems entirely.
fork() in multithreaded programs
  • After fork(), only the calling thread exists in the child. All other threads are gone -- but mutexes they held remain locked.
  • If the forking thread did NOT hold a mutex, but another thread did, the child will deadlock if it tries to acquire that mutex.
  • pthread_atfork handlers: prepare locks all mutexes (before fork), parent unlocks (in parent after fork), child unlocks (in child). This is fragile and doesn't scale to large codebases.
  • The safe patterns: (1) fork+exec immediately (exec resets all state), (2) use posix_spawn, (3) fork only before creating threads.
NPTL vs. LinuxThreads
  • NPTL provides true 1:1 threading: each thread is a kernel task created with clone(CLONE_VM|CLONE_THREAD|CLONE_SIGHAND|...).
  • LinuxThreads (pre-2003) used clone without CLONE_THREAD; each thread had a different PID, signal handling was broken, and getpid() returned different values per thread.
  • NPTL: all threads share the same PID (getpid() is consistent), signal delivery is POSIX-conformant, and thread groups are properly supported.
  • Visible in /proc/PID/task/: each TID corresponds to one thread. The PID equals the TID of the initial (main) thread.

Code patterns (C / POSIX)

Dedicated signal-handling thread using sigwait. 
// Dedicated signal-handling thread with sigwait
#include <pthread.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>

static volatile int shutdown_flag = 0;

void *sig_thread(void *arg){
  sigset_t *set = (sigset_t*)arg;
  int sig;
  while(1){
    sigwait(set, &sig);
    if(sig == SIGINT || sig == SIGTERM){
      printf("Caught signal %d, shutting down\n", sig);
      shutdown_flag = 1;
      break;
    }
  }
  return NULL;
}

int main(void){
  sigset_t set;
  sigemptyset(&set);
  sigaddset(&set, SIGINT);
  sigaddset(&set, SIGTERM);
  // Block signals in all threads (inherited by new threads)
  pthread_sigmask(SIG_BLOCK, &set, NULL);

  pthread_t t;
  pthread_create(&t, NULL, sig_thread, &set);

  // ... create worker threads here ...
  // Workers check shutdown_flag periodically

  pthread_join(t, NULL);
  printf("Clean shutdown complete\n");
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Block all signals in all threads; use a dedicated sigwait thread or signalfd for signal handling.
  • If you must fork in a multithreaded program, exec immediately after or use posix_spawn.
  • Set thread stack sizes explicitly for high-thread-count services (e.g., 256 KB or 512 KB for I/O workers).
  • Register pthread_atfork handlers in libraries that hold mutexes, or document that fork is not supported after init.
  • Verify NPTL with `getconf GNU_LIBPTHREAD_VERSION`; understand /proc/PID/task/ for debugging.
