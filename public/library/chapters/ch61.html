    Advanced socket features preserve partial progress

    An optimized scatter/gather sender repeats a prefix after a short sendmsg.

    The underlying idea

    Vectored I/O presents several buffers as one logical byte sequence but does not guarantee that every byte is accepted at once. Ancillary data, socket options, and zero-copy techniques add separate lifetime and error rules. Optimization should follow a correct framing and backpressure implementation.

    Contract and implementation boundary

    Advance iovec entries by the positive returned byte count, consuming complete entries and adjusting the partially consumed entry. For stream sends, use a deliberate SIGPIPE policy such as Linux MSG_NOSIGNAL where appropriate. Datagram truncation must be detected using the receive interface's flags and documented length semantics.

    Contract references: sendmsg.2 · recvmsg.2 · socket.7. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Retrying the original iovec after a short success duplicates bytes. SO_LINGER can change close behavior but cannot promise business-level delivery. A socket timeout is not automatically an end-to-end deadline across a multi-call exchange.

    Worked reasoning trace

    Assumptions: iovec lengths [4,6,2]; sendmsg returns 7.

    1. Starting state

      Twelve bytes were pending.

    2. Operation

      Consume the first vector and three bytes of the second.

    3. Expected observation

      Retry starts at second-buffer + 3 with lengths [3,2].

    Tradeoff: Gathering avoids copying but needs a cursor spanning vector boundaries.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    For vectors of lengths [4,6,2], trace a send returning 7: discard the first vector, advance three bytes into the second, retain the final vector. Then handle EAGAIN without losing the updated cursor.

    Check your understanding

    sendmsg accepts 7 bytes from vectors [4,6,2]. How many remain?

    Explain the answer

    Five bytes: three from the second vector and two from the third.
