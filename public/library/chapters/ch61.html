Chapter 61 — Sockets: Advanced Topics

Advanced socket topics — handling partial I/O, graceful shutdown with shutdown(2), disabling Nagle with TCP_NODELAY, connection health with SO_KEEPALIVE, and scatter-gather I/O with sendmsg/recvmsg.

Once basic socket communication works, production demands mastery of partial reads/writes, per-operation flags like MSG_PEEK and MSG_DONTWAIT, corking writes with TCP_CORK, and the nonblocking connect dance with EINPROGRESS.

Invariant
Partial reads/writes are NORMAL on sockets — always loop until the full message is sent or received.
Gotcha
shutdown(fd, SHUT_WR) sends FIN without closing the fd — you can still read; close() does both.
Debugging
TCP_NODELAY disables Nagle; TCP_CORK batches — misusing both causes latency spikes or tiny packets.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Partial reads/writes are NORMAL on stream sockets — the kernel may transfer fewer bytes than requested; you must loop (write_all / read_exact patterns).
  • shutdown(fd, SHUT_WR) sends a FIN to the peer without closing the file descriptor — the process can still read incoming data (half-close).
  • TCP_NODELAY disables the Nagle algorithm: each write() becomes a packet immediately, reducing latency for small interactive messages at the cost of bandwidth efficiency.
  • TCP_CORK (Linux) batches small writes into fewer packets — set cork, write multiple chunks, then uncork to flush; useful for HTTP headers + body.
  • SO_KEEPALIVE enables periodic probes on idle connections to detect dead peers; tunable via TCP_KEEPIDLE, TCP_KEEPINTVL, TCP_KEEPCNT.
  • sendmsg/recvmsg support scatter-gather I/O (multiple buffers in one syscall) and ancillary data (fd passing over Unix sockets, IP_PKTINFO).
  • Nonblocking connect returns EINPROGRESS; poll/epoll for writability, then getsockopt(SO_ERROR) to check success.
  • MSG_PEEK reads data without consuming it from the receive buffer; MSG_DONTWAIT makes a single operation nonblocking without changing the fd.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Partial reads and writes
  • write() on a TCP socket may return fewer bytes than requested — the kernel send buffer may be full or the segment size limits the transfer.
  • read() likewise returns whatever is available, which may be less than requested — you must loop (read_exact pattern) for fixed-size messages.
  • On nonblocking sockets, EAGAIN/EWOULDBLOCK means "try again later" — not an error. Resume when poll/epoll reports readiness.
  • EINTR means a signal interrupted the call before any data transferred — retry immediately.
shutdown vs close
  • close(fd) decrements the fd reference count; the connection may persist if another process shares the fd (fork).
  • shutdown(fd, SHUT_WR) sends FIN immediately regardless of reference count — the peer sees EOF on read.
  • After SHUT_WR you can still read from the socket — this is the half-close pattern used in HTTP/1.0 length detection.
  • shutdown(fd, SHUT_RD) causes further reads to return 0 (EOF) and may send RST if data arrives.
TCP_NODELAY, TCP_CORK, and Nagle
  • Nagle algorithm (default on): coalesce small writes until ACK received or MSS worth of data buffered. Reduces small-packet overhead.
  • TCP_NODELAY disables Nagle: each write becomes a segment immediately. Essential for interactive protocols (SSH, gaming, RPC).
  • TCP_CORK (Linux): hold all data until cork is removed or MSS is reached. Ideal for writev-like batching (HTTP response headers + body).
  • Nagle + delayed ACK interaction causes 40ms latency spikes when doing write-write-read patterns — set TCP_NODELAY or use writev.
Nonblocking connect and MSG flags
  • Nonblocking connect() returns -1/EINPROGRESS. Poll for POLLOUT, then getsockopt(SOL_SOCKET, SO_ERROR) — 0 means connected, nonzero is the errno.
  • Connect may succeed immediately (returns 0) for loopback or cached routes — handle both paths.
  • MSG_PEEK reads data without removing it from the receive queue — useful for protocol sniffing or framing decisions.
  • MSG_DONTWAIT makes a single send/recv nonblocking without fcntl(O_NONBLOCK) — convenient for optional reads.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// write_all: loop to handle partial writes
ssize_t write_all(int fd, const void *buf, size_t len) {
    size_t sent = 0;
    while (sent < len) {
        ssize_t n = write(fd, (char*)buf + sent, len - sent);
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;  // EAGAIN: caller should poll
        }
        sent += n;
    }
    return sent;
}

// Nonblocking connect pattern
int fd = socket(AF_INET, SOCK_STREAM|SOCK_NONBLOCK|SOCK_CLOEXEC, 0);
int rc = connect(fd, (struct sockaddr*)&addr, sizeof(addr));
if (rc == 0) { /* connected immediately (loopback) */ }
else if (errno == EINPROGRESS) {
    struct pollfd pfd = {fd, POLLOUT, 0};
    poll(&pfd, 1, 5000);  // 5s timeout
    int err; socklen_t sl = sizeof(err);
    getsockopt(fd, SOL_SOCKET, SO_ERROR, &err, &sl);
    if (err) { errno = err; /* connect failed */ }
} else { perror("connect"); }

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always loop on partial writes (write_all pattern); never assume write() sends everything in one call.
  • Use shutdown(SHUT_WR) for graceful half-close; don't rely on close() for signaling EOF to peer.
  • Set TCP_NODELAY for latency-sensitive protocols; use TCP_CORK or writev for batched responses.
  • Enable SO_KEEPALIVE with tuned intervals to detect dead peers on long-lived connections.
  • Handle nonblocking connect correctly: EINPROGRESS + poll + SO_ERROR; include a connect timeout.
