    TOPIC 4 / 64 · File I/O: The Universal I/O Model

    Byte transfer without wishful thinking

    A copy loop loses the tail of a file when a write transfers fewer bytes than requested.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    read and write transfer bytes, not application records. A positive short result is progress. Advance the buffer by the returned count and keep the remainder. An empty pipe with writers is different from a pipe with no writers. A zero-count request is different again: its zero result is not evidence of EOF.

    Contract and implementation boundary

    For a positive read request on a regular file, zero means the current offset is at or beyond its current end; later growth can make data readable. For a stream, zero normally reports orderly end after buffered bytes drain. Noncanonical terminal reads and zero-length datagrams have additional zero-result meanings. EINTR before transfer is retryable when policy allows; EAGAIN means wait for readiness.

    Contract references: read.2 · write.2 · recv.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Retrying every failure spins on permanent errors. Treating a positive short write as failure duplicates bytes if the entire buffer is resent. A successful write does not establish persistence on storage.

    Worked reasoning trace

    Assumptions: Eight-byte output; first write successfully transfers three bytes.

    1. Starting state

      Buffer contains ABCDEFGH; cursor is zero.

    2. Operation

      Advance cursor to three and request the remaining five.

    3. Expected observation

      The second request begins with D, avoiding a duplicate ABC.

    Tradeoff: Explicit cursors add state but preserve partial progress.
