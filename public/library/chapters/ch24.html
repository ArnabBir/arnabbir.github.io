    TOPIC 24 / 64 · Process Creation

    Fork: copied state, shared references

    A child changes a variable, but the parent sees only a changed file offset.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    fork creates a child with a logically separate address space, commonly implemented using copy-on-write. Descriptor tables are copied, but their entries refer to the same open file descriptions. This explains why ordinary variables diverge while file offsets can remain shared. Scheduling order is unspecified.

    Contract and implementation boundary

    fork returns the child PID in the parent, zero in the child, and -1 on failure with no child created. In a multithreaded parent, the child contains only the calling thread, while inherited memory may contain locks held by vanished threads. Restrict child work to async-signal-safe operations until exec.

    Contract references: fork.2 · pthread_atfork.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    A sleep is not a synchronization protocol. Assuming the child runs first creates timing-dependent output. Calling complex library functions after a multithreaded fork can deadlock on inherited lock state.

    Worked reasoning trace

    Assumptions: Single-threaded parent; shared inherited descriptor; calls serialized.

    1. Starting state

      Parent integer is 7 and file offset is zero.

    2. Operation

      Child changes its integer to 9 and reads one byte.

    3. Expected observation

      Parent integer remains 7; shared file offset becomes one.

    Tradeoff: fork isolates ordinary memory but shares some kernel references.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Run processes.c. The child changes its copied integer to 9 and uses _exit(9); the parent retains 7 and decodes status 9. Extend only in a single-threaded local variant to compare a copied integer with a shared descriptor offset.

    Check your understanding

    Does fork give the child an independent file offset for each inherited descriptor?

    Explain the answer

    No. The inherited entries reference the parent's open file descriptions.

    Parent integer remains 7; shared file offset becomes one.
