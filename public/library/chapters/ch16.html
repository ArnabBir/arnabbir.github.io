    TOPIC 16 / 64 · Extended Attributes

    Extended attributes are separate data

    A backup restores file contents but silently drops an application's metadata.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Extended attributes associate named byte values with filesystem objects. Namespaces such as user, trusted, security, and system carry different policy. Values are not necessarily text, and support depends on filesystem and mount configuration. Copying file bytes does not automatically copy these attributes.

    Contract and implementation boundary

    getxattr can first query a size, then retrieve the value. Another writer can change the size between calls, so handle ERANGE with bounded retries. Distinguish absence from unsupported operation and permission denial. The fgetxattr variant anchors access to an open object.

    Contract references: xattr.7 · getxattr.2 · setxattr.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Treating an attribute as a NUL-terminated string can overread binary data. Copying security attributes blindly across trust boundaries can be inappropriate even if the caller has permission.

    Assumptions: An xattr writer races the reader.

    Original practice problem

    On a disposable file, set a small user.lesson attribute, retrieve its exact byte length, and remove it. If the filesystem rejects the operation, record that as a capability result rather than fabricating output.

    Is a size query followed by getxattr immune to concurrent changes?
