    TOPIC 44 / 64 · Pipes and FIFOs

    Pipes are byte streams with reference-counted ends

    A reader waits forever even though its intended producer has exited.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    A pipe has a read end, a write end, and a finite kernel buffer. EOF depends on every write-end reference being closed, including accidental copies inherited by other children. Data already buffered is returned before EOF. FIFO names add rendezvous through the filesystem, not message boundaries.

    Contract and implementation boundary

    For a positive read request, an empty pipe with a live writer blocks or reports EAGAIN in nonblocking mode. Without writers it returns zero. Writes no larger than PIPE_BUF have a noninterleaving guarantee relative to other writers under the documented rules; reads need not return one whole write. With no readers, writing generates SIGPIPE and fails with EPIPE if execution continues.

    Contract references: pipe.7 · pipe.2 · fifo.7. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Leaving the parent's spare write end open suppresses EOF. Equating pipe capacity with PIPE_BUF confuses buffering with atomicity. Splitting a record over several writes can interleave it even when each individual write is small.
