    TOPIC 13 / 64 · File I/O Buffering

    Three stages of a write

    A log line appeared in memory but disappeared after a crash.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    stdio can buffer bytes in user space. write can put bytes into the kernel's page cache. Persistence needs the relevant filesystem and device synchronization guarantees. fflush moves a stream's pending output toward its descriptor; it is not a storage-durability operation. Metadata and directory entries have their own persistence requirements.

    Contract and implementation boundary

    Check fflush and fclose results. For a durable replacement protocol on a suitable local filesystem, write a temporary file in the target directory, synchronize the file, rename it, and synchronize the directory. Failure handling must retain enough information for recovery; filesystem and hardware behavior still matter.

    Contract references: stdio.3 · fflush.3 · fsync.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    fork copies unflushed user-space stdio buffers, so two later exit paths can flush duplicate output. Mixing stdio and raw descriptor I/O requires explicit coordination of buffering and offsets.

    Assumptions: Suitable local filesystem; all synchronization steps succeed.

    1. Starting state

    2. Operation

    Tradeoff: Durability adds latency; batching changes the acceptable loss window.

    Print a line without a newline before fork in a bounded helper. Compare flushing before fork with letting both processes call exit. Repeat with output redirected to a file because terminal buffering can mask the effect.
