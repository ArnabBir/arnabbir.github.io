    TOPIC 9 / 64 · Process Credentials

    Credentials are authority, not labels

    A helper changes its effective UID but unexpectedly regains privilege later.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Real, effective, and saved IDs serve different purposes. Supplementary groups also contribute to authorization. Linux has filesystem IDs and capabilities as additional mechanisms. A temporary privilege switch differs from an irreversible drop. Ordering matters because changing UID can remove authority needed to change groups.

    Contract and implementation boundary

    setresuid and setresgid explicitly manipulate ID sets subject to privilege rules. For a dedicated privileged helper, establish the intended supplementary groups before permanently dropping group and user IDs, check every call, then verify the resulting authority. Exact capability behavior must be considered too.

    Contract references: credentials.7 · setresuid.2 · access.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Ignoring a failed privilege-drop call is a security defect even when failure seems impossible. access checks using real IDs do not safely authorize a later open: pathname changes can race the two operations.

    Worked reasoning trace

    Assumptions: A helper requires an irreversible authority drop.

    1. Starting state

      Supplementary groups still include a privileged group.

    2. Operation

      Attempt group setup before dropping user authority; check every result.

    3. Expected observation

      If required setup fails, abort the privileged operation.

    Tradeoff: Permanent reduction limits damage but prevents later privileged work.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    As an unprivileged user, print real/effective/saved IDs with getresuid on Linux. Attempt no root transition. Sketch a helper's ordered setup and explain what must happen if any step fails.

    May a privileged helper continue normally after its required privilege drop fails?

    Explain the answer

    No. Abort the privileged operation and report the failed transition.
