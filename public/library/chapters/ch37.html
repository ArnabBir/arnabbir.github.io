    TOPIC 37 / 64 · Daemons

    Services need a lifecycle contract

    A supervisor thinks a daemon exited even though a detached grandchild is still running.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Traditional daemonization detached from a terminal and adjusted working directory, masks, and descriptors. A modern supervisor commonly expects a foreground process whose lifetime it can track directly. Startup, readiness, liveness, shutdown, and restart are separate lifecycle events.

    Contract and implementation boundary

    setsid detaches session relationships subject to its constraints. umask is process-wide. chdir and descriptor closure must be deliberate, preserving logging and control channels. A shutdown handler should request ordinary control flow to stop accepting work, drain within a deadline, and release resources.

    Contract references: daemon.7 · daemon.3 · setsid.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Blind double-forking under a foreground supervisor obscures process ownership. Closing every descriptor can destroy an intentionally inherited activation socket. A PID file alone is subject to stale contents and PID reuse.

    Worked reasoning trace

    Assumptions: Supervisor expects one foreground service process.

    1. Starting state

      Worker initializes but has not yet bound its socket.

    2. Operation

      Publish readiness only after initialization and binding succeed.

    3. Expected observation

      Process existence and service readiness are different observations.

    Tradeoff: Foreground supervision simplifies ownership; readiness still needs a protocol.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Specify a foreground worker's lifecycle: initialize, bind, declare ready, accept bounded work, stop admission, drain, exit. For each state, define what an external supervisor should observe. Use no background orphan process in the lab.
