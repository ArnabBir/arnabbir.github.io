    TOPIC 32 / 64 · Threads: Thread Cancellation

    Cancellation is an unwinding protocol

    A canceled worker leaves a mutex locked and the process hangs.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Cancellation is a request whose delivery depends on state, type, and cancellation points. Deferred cancellation is easier to reason about than asynchronous cancellation, which can strike while almost any invariant is broken. Cooperative stop flags often provide a clearer application lifecycle.

    Contract and implementation boundary

    pthread_cancel requests cancellation; it does not join the thread or prove completion. Cleanup handlers run on cancellation and can release acquired resources when correctly paired. pthread_cleanup_push/pop may be macros requiring matching lexical scope. Disable cancellation around short critical ownership transitions when necessary.

    Contract references: pthread_cancel.3 · pthread_cleanup_push.3 · pthread_setcancelstate.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Installing cleanup before acquiring a mutex can attempt an invalid unlock on another path. Forgetting that pthread_cond_wait reacquires the mutex before cancellation cleanup can produce a leak. Async cancellation makes most ordinary library operations unsafe.

    Worked reasoning trace

    Assumptions: Deferred cancellation; thread is waiting on a condition variable.

    1. Starting state

      The wait released its mutex.

    2. Operation

      Cancellation occurs and the wait reacquires the mutex before cleanup.

    3. Expected observation

      An installed cleanup handler can release that owned mutex.

    Tradeoff: Cooperative stop is often clearer; cancellation requires audited cleanup boundaries.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Draw ownership states for acquire, install cleanup, wait, remove cleanup, release. Choose a disciplined ordering that covers each cancellation point. Prefer a cooperative bounded worker in runnable examples rather than trying to demonstrate undefined behavior.
