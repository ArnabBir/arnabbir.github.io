Chapter 29 — Threads: Introduction

Threads share the address space within a process -- cheaper than fork but sharing means synchronization is mandatory. A thread is essentially a kernel task created with CLONE_VM that shares the parent's heap, globals, file descriptors, and credentials while maintaining its own stack, TID, errno, and signal mask.

This chapter covers the lifecycle: pthread_create spawns a thread, pthread_join reaps it, and pthread_detach lets it clean up autonomously. Understanding what is shared vs. private is the foundation for every subsequent threads chapter.

Invariant
Threads share heap, globals, and file descriptors; each thread has its own stack, TID, errno, and signal mask.
Gotcha
If the main thread calls return from main(), the process exits (calls exit()), terminating all threads -- use pthread_exit() instead to let other threads continue.
Debugging
Use /proc/PID/task/ to enumerate thread TIDs; gdb's "info threads" lists all threads in the process.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • A thread is a kernel schedulable entity (task_struct) that shares the address space via CLONE_VM -- it is not a separate process.
  • pthread_create spawns a new thread; it returns 0 on success and an error number (not -1) on failure -- always check the return value.
  • pthread_join is to threads what waitpid is to child processes: it blocks until the target thread terminates and retrieves its return value.
  • Each thread has its own stack (default ~8 MB), TID (gettid()), errno (thread-local macro), and signal mask.
  • Shared between threads: heap memory (malloc), global/static variables, file descriptors, process ID, credentials (UID/GID), and working directory.
  • Detached threads (pthread_detach) release their resources automatically on termination -- they cannot be joined.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Thread creation pitfalls
  • Passing a pointer to a loop variable as arg is a classic race: by the time the thread reads it, the loop may have advanced. Allocate per-thread data or cast to (void*)(intptr_t)i.
  • pthread_create can fail with EAGAIN if you hit RLIMIT_NPROC or the system-wide thread limit (/proc/sys/kernel/threads-max). Always check the return value.
  • Thread attributes (stack size, detach state, scheduling) default to sensible values; only customize when you understand the tradeoff.
  • Creating thousands of threads with default 8 MB stacks can exhaust virtual address space on 32-bit systems.
Joining and detaching
  • Every joinable thread must be joined exactly once, or you leak resources (similar to zombie processes).
  • A detached thread cannot be joined -- calling pthread_join on it yields EINVAL.
  • Joining a thread that has already been joined is undefined behavior.
  • If main() returns without joining or detaching threads, exit() is called and all threads are killed immediately.
Shared vs. private state
  • Heap, globals, static locals, and file descriptors are shared -- concurrent access without synchronization is a data race (undefined behavior).
  • Stack variables are private to each thread (each thread gets its own stack).
  • errno is thread-local (macro expanding to a per-thread location) so it is safe to check after a failed call.
  • The signal mask is per-thread (pthread_sigmask), but signal dispositions (handlers) are process-wide.
Thread termination
  • A thread terminates by: returning from start_routine, calling pthread_exit(), being cancelled, or any thread calling exit()/_exit().
  • Do not return a pointer to a stack-local variable from a thread -- the stack is freed on thread exit.
  • If the main thread calls pthread_exit() instead of return/exit(), the process continues until all other threads finish.
  • Calling exit() from any thread terminates the entire process.

Code patterns (C / POSIX)

pthread_create + join pattern with error checking. 
// Thread creation and joining with error checking
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void *worker(void *arg){
  int id = (int)(intptr_t)arg;        // safe cast from void*
  printf("thread %d running (tid=%ld)\n", id, (long)gettid());
  return (void*)(intptr_t)(id * 10);   // return value
}

int main(void){
  enum { N = 4 };
  pthread_t thr[N];
  for(int i = 0; i < N; i++){
    int s = pthread_create(&thr[i], NULL, worker,
                           (void*)(intptr_t)i);
    if(s != 0){ fprintf(stderr,"create: %s\n",strerror(s)); exit(1); }
  }
  for(int i = 0; i < N; i++){
    void *res;
    int s = pthread_join(thr[i], &res);
    if(s != 0){ fprintf(stderr,"join: %s\n",strerror(s)); exit(1); }
    printf("thread %d returned %ld\n", i, (long)(intptr_t)res);
  }
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always check pthread_create return value; handle EAGAIN gracefully (back off, log, retry).
  • Join every joinable thread exactly once, or detach threads that should self-clean.
  • Never pass pointers to stack locals across thread boundaries unless the creating thread outlives the child.
  • Use pthread_exit() in main if you want other threads to keep running after main's work is done.
  • Set thread names (pthread_setname_np) for debuggability in gdb and /proc/PID/task/TID/comm.
