    TOPIC 29 / 64 · Threads: Introduction

    Threads share ownership problems

    A thread receives a pointer to a stack object that no longer exists.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Threads share address space and process resources but each has its own stack, execution state, and signal mask. Passing a pointer shares access, not lifetime management. The caller must keep the pointed-to object alive until the receiver is finished. Thread creation does not define which side executes first.

    Contract and implementation boundary

    pthread_create returns an error number and starts a function with signature void *(*)(void *). A joinable thread should be joined exactly once or detached. pthread_join establishes completion and retrieves the returned pointer; it does not make a pointer to a dead thread's stack valid.

    Contract references: pthread_create.3 · pthread_join.3 · pthread_self.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Passing the address of a changing loop variable to every worker gives them a race on one object. Leaking joinable thread resources is distinct from leaking heap memory. Use pthread_equal rather than assuming a portable integer representation for pthread_t.

    Worked reasoning trace

    Assumptions: Two workers each increment 1000 times under one mutex.

    1. Starting state

      Shared counter starts at zero; argument storage survives both joins.

    2. Operation

      Join both successfully completed workers.

    3. Expected observation

      The final counter is 2000 regardless of scheduling order.

    Tradeoff: Locking gives correctness but can serialize a hot counter.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Run threads.c with two bounded workers and one shared mutex-protected counter. Each worker receives stable storage. Verify the final total after both joins instead of guessing the interleaving from print order.

    Check your understanding

    May a thread safely return a pointer to its automatic local variable for the joiner to use?

    Explain the answer

    No. Its automatic storage lifetime ends with the thread's function.
