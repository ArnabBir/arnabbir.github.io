    TOPIC 48 / 64 · System V Shared Memory

    Shared-memory addresses are not portable references

    A pointer stored by one process crashes a second process attached to the same segment.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    shmat attaches a System V shared-memory segment into a process address space. The same shared bytes can appear at different virtual addresses in different processes. Use validated offsets relative to the mapping base for in-segment references, and define a synchronization mechanism for publication and reuse.

    Contract and implementation boundary

    shmat reports failure as (void *) -1, not NULL. shmdt detaches one mapping. IPC_RMID marks a segment for removal, with destruction delayed until the last attachment is gone. Linux permits some operations on marked segments that should not be assumed portable.

    Contract references: shmget.2 · shmop.2 · shmctl.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    A mapped struct with a native pointer is not an interprocess format. Even an offset needs bounds and alignment checks. A creator crashing halfway through initialization leaves an application recovery problem, not merely a mapping problem.

    Worked reasoning trace

    Assumptions: Segment bases 0x100000 and 0x700000; valid byte offset 128.

    1. Starting state

      Both processes read offset 128 from the header.

    2. Operation

      Each adds the offset to its own mapping base.

    3. Expected observation

      Addresses are 0x100080 and 0x700080, naming the same shared bytes.

    Tradeoff: Offsets support relocation but still need bounds and alignment validation.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Design a 4096-byte segment with a versioned header and a payload offset of 128. Show the address calculation for bases 0x100000 and 0x700000. Reject an offset-plus-length beyond the segment before dereferencing.
