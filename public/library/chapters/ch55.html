    TOPIC 55 / 64 · File Locking

    File locks have different ownership rules

    Closing an unrelated descriptor unexpectedly drops a process's record locks.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Advisory locks coordinate cooperating applications; they do not force every writer to participate. Traditional fcntl record locks are process-associated and have surprising close semantics. Linux open-file-description locks instead attach to the open file description. flock is another interface with its own semantics and filesystem caveats.

    Contract and implementation boundary

    With traditional record locks, closing any descriptor for that file in the process releases that process's locks on it. OFD locks survive until the last reference to their open file description closes, and duplicated descriptors share that ownership. F_SETLK requests nonblocking acquisition; F_SETLKW can wait and be interrupted.

    Contract references: fcntl_locking.2 · F_OFD_SETLK.2const · flock.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Mixing lock families without understanding their interaction can provide no exclusion. A lock around one write does not create a crash-safe multi-write update. Network filesystems may change locking behavior and failure modes.

    Worked reasoning trace

    Assumptions: Traditional process-associated record lock; two descriptors to one file.

    1. Starting state

      fd 3 acquired the lock; fd 4 was a separate open.

    2. Operation

      The same process closes fd 4.

    3. Expected observation

      Its traditional record locks on that file are released too.

    Tradeoff: OFD locks offer different lifetime semantics but are Linux-specific.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Draw two descriptors produced by separate opens and two produced by dup. Place the lock owner on the process for traditional locks and on the description for OFD locks. Predict which closes release each lock.

    Check your understanding

    Does a traditional fcntl record lock belong only to the descriptor used to acquire it?

    Explain the answer

    No. It is process-associated, including the any-close release rule.
