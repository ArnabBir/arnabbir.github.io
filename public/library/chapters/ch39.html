    TOPIC 39 / 64 · Capabilities

    Capabilities divide privilege, imperfectly

    A service gets CAP_SYS_ADMIN to solve one error and gains far more authority than intended.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Linux capabilities split traditional root powers into sets associated with threads and executable files. Effective, permitted, inheritable, bounding, and ambient sets participate in transitions. A capability is meaningful within user-namespace and target-resource rules; it is not a universally scoped permission token.

    Contract and implementation boundary

    Inspect capabilities before and after exec and UID changes rather than assuming they survive unchanged. no_new_privs constrains privilege gain across exec. File capabilities require filesystem support and deployment review. Prefer the narrow capability actually needed over broad administrative authority.

    Contract references: capabilities.7 · PR_SET_NO_NEW_PRIVS.2const. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Dropping one effective bit may leave permitted authority that can restore it. Containers and user namespaces alter the scope of apparent privilege. CAP_SYS_ADMIN covers many unrelated operations and is rarely a minimal default.

    Worked reasoning trace

    Assumptions: A capability remains in a thread's permitted set.

    1. Starting state

      Its effective bit is cleared.

    2. Operation

      The program later attempts to make it effective again.

    3. Expected observation

      Clearing only effective authority need not make the reduction permanent.

    Tradeoff: Capabilities narrow authority better than blanket root, but transition rules are complex.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Read /proc/self/status capability masks and map only the bits you need using capabilities(7). Write a transition table for launch, setup, and steady state. Do not grant capabilities to the lab binaries just to make a demonstration succeed.

    Check your understanding

    Does clearing only an effective capability always make the privilege permanently unrecoverable?

    Explain the answer

    No. Other sets and transition rules can allow it to become effective again.
