    TOPIC 34 / 64 · Process Groups, Sessions, and Job Control

    Job control separates sessions and groups

    Pressing Ctrl-C terminates a pipeline's workers rather than only the shell's immediate child.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    A process group collects related processes for signaling and terminal job control. A session contains process groups and may have a controlling terminal. The terminal's foreground process group receives terminal-generated signals. Parent-child structure and process-group membership are different relationships.

    Contract and implementation boundary

    setpgid establishes process-group membership subject to session and lifecycle constraints. setsid creates a new session when permitted; a process-group leader cannot simply call it successfully. tcsetpgrp selects a foreground group under terminal rules. kill with a negative group ID targets a group.

    Contract references: credentials.7 · setpgid.2 · setsid.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    A background process reading its controlling terminal can receive SIGTTIN. Treating process groups as security boundaries is incorrect. Shell launch code often sets group membership in both parent and child to close scheduling races.

    Worked reasoning trace

    Assumptions: Foreground terminal group contains both workers of a pipeline.

    1. Starting state

      Shell is a different process group.

    2. Operation

      Terminal receives its configured interrupt character with ISIG enabled.

    3. Expected observation

      SIGINT targets the foreground group rather than just one immediate child.

    Tradeoff: Groups simplify job control but are not security isolation.

    This is a hand-authored prediction, not captured runtime output.
