    TOPIC 27 / 64 · Program Execution

    Exec is an image replacement boundary

    A helper inherits a database socket that its parent never intended to share.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    execve replaces code, data, heap, and stack with a new image. Many process attributes survive, including identity and descriptors not marked close-on-exec. Caught signal dispositions reset, while ignored dispositions and the signal mask have specified inheritance behavior. Every inherited descriptor is a transfer of authority.

    Contract and implementation boundary

    execve accepts a path and NULL-terminated argv and envp vectors. On success it never returns; on ordinary failure it returns -1. Set close-on-exec at descriptor creation to avoid a race with another thread executing a new image. PATH-searching exec variants introduce a separate executable-resolution policy.

    Contract references: execve.2 · exec.3 · open.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Setting FD_CLOEXEC in a later fcntl can race a concurrent fork/exec. A sanitized argv does not sanitize the environment. Never treat a shell command string as equivalent to an argument vector for untrusted values.
