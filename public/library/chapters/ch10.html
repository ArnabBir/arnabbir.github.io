Chapter 10 — Time

Time in Linux spans two fundamentally different domains: wall-clock time (calendar time tied to UTC and time zones) and monotonic time (a steadily advancing counter immune to NTP adjustments). Understanding which clock to use—and why—prevents an entire class of production bugs involving timeouts, intervals, and timestamps.

The kernel exposes multiple clock sources via clock_gettime(). CLOCK_REALTIME reflects the system’s best guess at UTC and can jump forward or backward due to NTP step corrections. CLOCK_MONOTONIC never goes backward and is the correct choice for measuring elapsed time. CPU time accounting uses CLOCK_PROCESS_CPUTIME_ID or the older clock() function.

Invariant
CLOCK_MONOTONIC never goes backward—even across NTP adjustments or admin time changes. It is always safe for interval measurement.
Gotcha
time_t is a signed 32-bit integer on many 32-bit systems and overflows on 2038-01-19. NTP can jump CLOCK_REALTIME forward or backward at any moment.
Debugging
clock_getres() reveals the actual resolution of each clock source. On modern kernels this is typically 1 ns, but check—do not assume.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • CLOCK_REALTIME is wall-clock time (calendar/UTC). It can jump due to NTP step corrections or manual adjtime/settimeofday calls. Use it only when you need a timestamp that corresponds to human-readable date/time.
  • CLOCK_MONOTONIC advances at a steady rate and never goes backward. Use it for measuring intervals, timeouts, and elapsed durations. It is adjusted by NTP frequency slewing (rate correction) but never stepped.
  • CLOCK_MONOTONIC_RAW excludes even NTP frequency adjustment—it reflects raw hardware counter ticks. Useful for micro-benchmarks where NTP rate correction would distort results.
  • Process CPU time can be measured via clock() (returns CLOCKS_PER_SEC units) or clock_gettime(CLOCK_PROCESS_CPUTIME_ID). The latter gives nanosecond resolution and separates user/system time.
  • nanosleep() sleeps against CLOCK_REALTIME by default and can be affected by time jumps. clock_nanosleep() with CLOCK_MONOTONIC and TIMER_ABSTIME provides jump-immune absolute deadline sleeps.
  • timerfd_create() creates a file descriptor that becomes readable when a timer expires, integrating timer events into epoll/select event loops without signals.
  • strftime() and localtime_r() convert time_t to human-readable strings. Always use the _r (reentrant) variants in multithreaded code. Time zone is controlled by TZ environment variable and /etc/localtime.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Y2038 problem
  • On 32-bit systems, time_t is a signed 32-bit integer. It overflows on 2038-01-19 03:14:07 UTC, wrapping to a large negative value (December 1901).
  • 64-bit systems use a 64-bit time_t and are not affected. Modern 32-bit Linux kernels (5.6+) support 64-bit time_t internally, but userspace must be compiled with _TIME_BITS=64.
  • Embedded systems and IoT devices running old 32-bit kernels are the primary risk. Audit any system that stores or compares time_t values.
  • Filesystems that store 32-bit timestamps (ext3, old ext4) will also overflow. ext4 extended timestamps reach year 2446.
NTP and clock jumps
  • NTP can perform a step correction on CLOCK_REALTIME, jumping the clock forward or backward by seconds or even hours. This breaks any timeout or interval measured against CLOCK_REALTIME.
  • NTP also performs frequency slewing (rate adjustment), which affects CLOCK_MONOTONIC. CLOCK_MONOTONIC_RAW is the only clock completely unaffected by NTP.
  • adjtime() gradually slews the clock; settimeofday() steps it immediately. Both affect CLOCK_REALTIME.
  • Containers inherit the host’s clock. A time jump on the host affects all containers.
Timer coalescing and time zones
  • The kernel may coalesce timer expirations to reduce wakeups and save power (timer slack). For timerfd and nanosleep, the actual wakeup may be slightly later than requested.
  • Use timerfd_settime with TFD_TIMER_ABSTIME for absolute deadlines; relative timers accumulate drift over repeated iterations.
  • localtime_r() depends on /etc/localtime and the TZ environment variable. In containers, TZ may not be set, causing UTC fallback. Always use localtime_r (reentrant), never localtime.
  • Daylight saving transitions can cause local times to repeat or skip. Store and compare times in UTC; convert to local only for display.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// --- Measure elapsed time with CLOCK_MONOTONIC ---
struct timespec t0, t1;
clock_gettime(CLOCK_MONOTONIC, &t0);
do_work();
clock_gettime(CLOCK_MONOTONIC, &t1);
double elapsed = (t1.tv_sec - t0.tv_sec)
               + (t1.tv_nsec - t0.tv_nsec) / 1e9;
printf("elapsed: %.6f s\n", elapsed);

// --- timerfd: periodic timer integrated with epoll ---
#include <sys/timerfd.h>
int tfd = timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK | TFD_CLOEXEC);
struct itimerspec its = {
    .it_interval = { .tv_sec = 1, .tv_nsec = 0 },  // period
    .it_value    = { .tv_sec = 1, .tv_nsec = 0 }    // initial
};
timerfd_settime(tfd, 0, &its, NULL);
// add tfd to epoll; read(tfd, &expirations, 8) returns count

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Use CLOCK_MONOTONIC for all timeouts, intervals, and elapsed-time measurements. Never use CLOCK_REALTIME for durations.
  • Use clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, ...) for periodic tasks to avoid drift accumulation.
  • Audit all time_t storage on 32-bit targets for Y2038 overflow. Compile with _TIME_BITS=64 where supported.
  • Prefer timerfd_create over POSIX signal-based timers (timer_create) in event-driven architectures using epoll.
  • Always use localtime_r and gmtime_r in multithreaded code. The non-_r variants use a shared static buffer.
  • Store timestamps in UTC. Convert to local time only at display boundaries.
