    TOPIC 17 / 64 · Access Control Lists

    ACLs and the effective permission mask

    An ACL grants a named user write permission but the user still cannot write.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Linux POSIX-style access ACLs extend owner/group/other permissions with named users and groups. The ACL mask caps effective permissions for named users and the group class, but not the owning user or other entry. Default directory ACLs influence inheritance and are distinct from the directory's own access ACL.

    Contract and implementation boundary

    Use getfacl to inspect both requested and effective rights and setfacl only on disposable files. chmod can change the ACL mask through group-class bits. Linux POSIX ACLs reflect the historical draft model; do not claim that this interface is a mandatory POSIX.1-2024 feature.

    Contract references: acl.5 · acl_get_file.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Looking only at one named entry misses the mask. A recursive permission change can unexpectedly alter effective rights inherited by a tree. Authorization also needs search permission on ancestor directories.

    Worked reasoning trace

    Assumptions: Named-user ACL entry rw; ACL mask r; ancestor search allowed.

    1. Starting state

      The named user attempts a write through that entry.

    2. Operation

      Intersect the entry with the mask.

    3. Expected observation

      Effective rights are r, so that entry does not authorize write.

    Tradeoff: ACLs express fine-grained policy but require reviewing effective permissions.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    In an optional ACL-enabled filesystem lab, create a named-user entry with rw and a mask of r. Read getfacl's effective annotation. Do not modify another user's real files to perform this experiment.

    Check your understanding

    A named user has rw, while the ACL mask is r. What is effective through that entry?

    Explain the answer

    Read only, because the mask caps the named-user entry.

    Effective rights are r, so that entry does not authorize write.
