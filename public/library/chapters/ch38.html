    TOPIC 38 / 64 · Writing Secure Privileged Programs

    Privileged code narrows its inputs

    A privileged helper opens a path after checking it, but an attacker swaps a directory entry.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Authority amplifies ordinary bugs. Treat paths, environment variables, inherited descriptors, locale, arguments, and working directory as inputs. Reduce privileged operations to a narrow phase, use handle-based operations where possible, and make ownership explicit before dropping authority.

    Contract and implementation boundary

    Use atomic creation with O_EXCL or a suitable temporary-file API in a trusted directory. openat2 can constrain Linux path resolution. Never use access followed by open as an authorization transaction. Avoid invoking a shell to interpret untrusted text and check every credential transition.

    Contract references: access.2 · openat2.2 · secure_getenv.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Sanitizing only the filename leaves environment-driven loader or program behavior unaddressed. A symlink check can itself race. Logging a secret or privileged file's content during error handling can create a second vulnerability.

    Worked reasoning trace

    Assumptions: An adversary can replace a pathname between two operations.

    1. Starting state

      access approves the current object.

    2. Operation

      The entry changes before open.

    3. Expected observation

      The later operation can address another object; the check was not a reservation.

    Tradeoff: Directory-handle-based operations reduce name races but require explicit policy.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Threat-model a helper that replaces one configuration file. Enumerate trusted directory handles, accepted relative names, allowed modes, inherited descriptors, and the point of irreversible privilege drop. Test rejection paths unprivileged.

    Explore the model bench to distinguish predicted state from observed system behavior.

    Check your understanding

    Does checking a pathname with access make a later open race-free?

    Explain the answer

    No. Resolve and operate on a securely acquired object instead.
