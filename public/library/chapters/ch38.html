Chapter 38 — Writing Secure Privileged Programs

Writing secure privileged code means minimizing the window of privilege, validating all inputs, avoiding TOCTOU races, and never trusting the environment. A setuid binary inherits attacker-controlled state through environment variables, file descriptors, signal dispositions, and the filesystem itself.

Privilege is a liability, not an asset. The secure program acquires privileges late, drops them early, holds them briefly, and verifies the drop succeeded before processing untrusted data.

Invariant
Privilege is a liability — acquire late, drop early, hold briefly. Every line of code running with elevated rights expands the attack surface.
Gotcha
TOCTOU: checking access() then calling open() creates a race window an attacker can exploit by swapping the target via symlink between the two calls.
Debugging
strace -e trace=setresuid,setresgid,openat plus checking /proc/PID/status UID fields reveals the actual privilege state at each point in execution.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Principle of least privilege: drop privileges immediately after acquiring the resource that requires them; use setresuid(uid,uid,uid) to permanently discard the saved-set-user-ID so privilege cannot be regained.
  • TOCTOU races on the filesystem: never stat a path then open it — instead open first (with O_NOFOLLOW) then fstat the file descriptor; the fd pins the inode regardless of subsequent path manipulation.
  • Environment sanitization: clear PATH, IFS, LD_PRELOAD, LD_LIBRARY_PATH, and all LD_* variables before doing any work; rebuild environ from a known-safe whitelist of values.
  • Input validation: enforce strict length bounds, reject unexpected encodings, detect embedded null bytes that truncate C strings, and block path traversal sequences (../) before any use.
  • Secure temporary files: use mkstemp() which atomically creates and opens with a unique name, or O_TMPFILE (Linux 3.11+) for anonymous inodes; never use the deprecated mktemp() which is inherently racy.
  • Avoid shell invocations in privileged code: system() and popen() spawn /bin/sh which interprets PATH, IFS, and metacharacters; use execve() with an absolute path and a fully sanitized environment array instead.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
TOCTOU filesystem attacks
  • The canonical exploit: attacker runs a tight loop doing symlink("/etc/shadow", "/tmp/target") while the setuid program does access("/tmp/target") then open("/tmp/target"). The race window is typically microseconds but wins reliably with repetition.
  • Mitigation pattern: open the file first with O_NOFOLLOW|O_RDONLY, then fstat() the fd to verify ownership and permissions on the actual opened inode, not the path.
  • In /tmp directories, use O_TMPFILE to create anonymous files that have no directory entry to race against, or use mkstemp() which creates and opens atomically.
  • Even openat() is not immune if you allow symlinks in intermediate path components; combine with O_NOFOLLOW and resolve each component explicitly for maximum safety.
LD_PRELOAD, setuid, and signal handlers
  • glibc detects AT_SECURE (set by the kernel for setuid/setgid exec) and ignores LD_PRELOAD, LD_LIBRARY_PATH, and LD_AUDIT. However, statically linked binaries or programs using alternative loaders do not get this protection.
  • Signal handlers installed before privilege drop remain active during privileged execution. An attacker who can send signals (same UID pre-exec) may trigger handlers at critical moments, corrupting state.
  • Minimize signal handler work in privileged code: set a volatile sig_atomic_t flag and check it in the main loop rather than performing complex operations in the handler itself.
  • Core dumps from setuid processes can leak sensitive data (passwords, keys); the kernel disables dumps by default for setuid but calling prctl(PR_SET_DUMPABLE, 0) makes this explicit.
Inherited state and privilege windows
  • File descriptors are inherited across exec: an attacker may pass open fds to unexpected files. Use close_range(3, UINT_MAX, 0) or closefrom(3) immediately on startup to close all unexpected descriptors.
  • The current working directory is attacker-controlled if the setuid binary is invoked from an arbitrary location. Use chdir("/") or a known-safe directory before any relative path operations.
  • umask is inherited: always call umask(077) explicitly before creating files in privileged context to prevent world-readable permissions.
  • Resource limits (RLIMIT_FSIZE, RLIMIT_NOFILE) are inherited and can cause unexpected failures during privileged operations; check or reset critical limits at startup.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// Environment sanitization + privilege drop + secure temp file
#include <unistd.h>
#include <stdlib.h>
#include <stdio.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <grp.h>

extern char **environ;

static void sanitize_environment(void) {
    static char *clean_env[] = {
        "PATH=/usr/bin:/bin",
        "IFS= \t\n",
        NULL
    };
    environ = clean_env;  // discard all inherited variables
}

static void drop_privs_permanently(uid_t uid, gid_t gid) {
    if (setgroups(0, NULL) < 0)              _exit(1);
    if (setresgid(gid, gid, gid) < 0)       _exit(1);
    if (setresuid(uid, uid, uid) < 0)        _exit(1);

    // Verify: if any ID is still 0, abort immediately
    uid_t r, e, s;
    getresuid(&r, &e, &s);
    if (r == 0 || e == 0 || s == 0) _exit(1);
}

static int create_secure_temp(void) {
    // O_TMPFILE: anonymous inode, no directory entry to race
    int fd = open("/tmp", O_TMPFILE | O_RDWR, 0600);
    if (fd < 0) {
        char tmpl[] = "/tmp/secure_XXXXXX";
        fd = mkstemp(tmpl);  // fallback: atomic create+open
        unlink(tmpl);        // immediately unlink name
    }
    return fd;
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Sanitize environment completely on startup: wipe environ and rebuild with only PATH=/usr/bin:/bin and IFS defaults.
  • Close all inherited file descriptors above stderr using close_range(3, ~0U, 0) before processing any inputs.
  • Drop privileges permanently with setresuid/setresgid (all three IDs identical) and verify with getresuid afterward; abort on failure.
  • Never invoke system(), popen(), or execlp() in privileged code paths; use execve() with absolute paths and the sanitized environment.
  • Create temporary files exclusively with mkstemp() or O_TMPFILE; never use mktemp() or predictable paths in world-writable directories.
