Chapter 41 — Fundamentals of Shared Libraries

Shared libraries reduce memory usage and enable updates without relinking — the .text segment is loaded once into physical memory via mmap and mapped into multiple process address spaces simultaneously. The runtime linker (ld.so) handles symbol resolution at load time or lazily through the PLT/GOT mechanism.

Static linking embeds all library code into the executable at build time, producing self-contained binaries at the cost of disk/memory duplication and inability to pick up library patches. Shared linking defers binding to runtime, requiring careful version management through the soname convention.

Invariant
Shared library .text is loaded once (mmap MAP_PRIVATE) and shared read-only across all processes; data segments are per-process via copy-on-write.
Gotcha
Soname mismatches (binary needs libfoo.so.1 but only libfoo.so.2 exists) cause runtime load failures even though the file is on disk.
Debugging
Use ldd to list dependencies, readelf -d for NEEDED/SONAME/RPATH, and LD_DEBUG=libs to trace the loader's search decisions.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Static linking embeds code in the executable — simple deployment but no shared memory savings and no security patch propagation without rebuild.
  • Shared linking maps .so files at runtime — ld.so reads NEEDED entries from the ELF dynamic section and loads each dependency.
  • Soname (e.g., libfoo.so.1) provides ABI versioning: the real file is libfoo.so.1.2.3, the soname symlink is libfoo.so.1, and the linker name is libfoo.so.
  • Position-Independent Code (-fPIC) uses PC-relative addressing and the GOT so .text can be loaded at any virtual address without text relocations.
  • PLT/GOT enable lazy symbol binding: first call goes through PLT stub to ld.so resolver, which patches the GOT entry for subsequent direct jumps.
  • ld.so (the runtime linker, e.g., /lib64/ld-linux-x86-64.so.2) resolves symbols at load time; it searches RPATH, LD_LIBRARY_PATH, RUNPATH, /etc/ld.so.cache, then default paths.
  • ldconfig scans library directories and updates /etc/ld.so.cache with soname-to-path mappings for fast runtime lookup.
  • RPATH is searched before LD_LIBRARY_PATH (considered deprecated); RUNPATH is searched after, allowing user overrides.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Static vs shared linking trade-offs
  • Static binaries are fully self-contained: deploy anywhere without dependency concerns. But they cannot benefit from shared library security patches without a full rebuild.
  • Shared libraries save physical memory (shared .text pages) and disk space, but introduce runtime dependency resolution failures.
  • On glibc, fully static linking is problematic: NSS, iconv, and DNS resolution may internally dlopen() plugins, breaking in static builds.
  • musl libc supports clean fully-static binaries since it avoids internal dlopen usage.
Soname versioning pitfalls
  • The soname (libfoo.so.1) represents a stable ABI contract. Bump the major number when you break binary compatibility.
  • The linker name (libfoo.so) is a symlink used only at build time; the soname is what gets recorded in the executable's NEEDED entry.
  • ldconfig creates the soname symlink (libfoo.so.1 -> libfoo.so.1.2.3). Without running ldconfig, ld.so cannot find the library via cache.
  • Multiple ABI versions (libfoo.so.1 and libfoo.so.2) can coexist on disk, allowing gradual migration.
PLT/GOT and security hardening
  • With lazy binding (default), PLT stubs invoke ld.so on first call, then patch the GOT for direct subsequent calls. This means the GOT is writable during execution.
  • Full RELRO (-Wl,-z,relro,-z,now) resolves all symbols at load time and marks the GOT read-only, preventing GOT-overwrite exploits.
  • LD_BIND_NOW=1 achieves the same effect at runtime; useful for testing without relinking.
  • Text relocations (non-PIC .so) prevent page sharing across processes and produce security warnings. Always use -fPIC.

// === mathlib.c — a simple shared library ===
#include <math.h>
double circle_area(double r) { return M_PI * r * r; }
int factorial(int n) { return (n <= 1) ? 1 : n * factorial(n - 1); }

// === Build the shared library with soname ===
// $ gcc -fPIC -c mathlib.c -o mathlib.o
// $ gcc -shared -Wl,-soname,libmathlib.so.1 -o libmathlib.so.1.0.0 mathlib.o -lm
// $ ln -sf libmathlib.so.1.0.0 libmathlib.so.1   # soname symlink
// $ ln -sf libmathlib.so.1 libmathlib.so          # linker symlink

// === main.c — link against the library ===
// extern double circle_area(double);
// printf("area = %f\n", circle_area(5.0));

// $ gcc main.c -L. -lmathlib -Wl,-rpath,'$ORIGIN' -o main
// $ ./main

// === Inspect the result ===
// $ ldd ./main                          # shows libmathlib.so.1 dependency
// $ readelf -d ./main | grep NEEDED     # NEEDED libmathlib.so.1
// $ readelf -d libmathlib.so.1.0.0 | grep SONAME  # SONAME libmathlib.so.1

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always compile shared libraries with -fPIC; verify no TEXTREL entries with readelf -d.
  • Set sonames correctly (-Wl,-soname,libfoo.so.MAJOR) and bump major version on ABI-breaking changes.
  • Run ldconfig after installing to system paths; verify with ldconfig -p | grep libfoo.
  • Use -Wl,-z,relro,-z,now for security-sensitive binaries to enable full RELRO (read-only GOT).
  • Prefer RUNPATH over RPATH — RUNPATH respects LD_LIBRARY_PATH ordering and is the modern convention.
