    TOPIC 15 / 64 · File Attributes

    Metadata is a snapshot

    A file passes a pathname permission check, then the opened object differs.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    stat follows a pathname to metadata; lstat reports the symbolic link itself; fstat examines the already-open object. Permission bits include type-dependent meanings: directory execute grants search, while directory write controls changes to names subject to other rules. File write permission is not the same as permission to remove its name.

    Contract and implementation boundary

    Use S_ISREG and related macros to interpret mode types. umask masks requested creation permissions; it does not add permissions. Prefer checking an opened descriptor when the operation must refer to that same object. Timestamps can have filesystem-specific precision and update policy.

    Contract references: stat.2 · umask.2 · inode.7. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    stat followed by open is vulnerable to name replacement. Sticky directories add deletion restrictions, and ACLs or security modules can further change authorization. A mode-bit-only explanation is incomplete.

    Worked reasoning trace

    Assumptions: No default ACL; requested mode 0666; umask 0077.

    1. Starting state

      No file exists at a private test path.

    2. Operation

      Create the file successfully.

    3. Expected observation

      Permission bits are 0600, before any later chmod.

    Tradeoff: A restrictive default prevents exposure but collaborators need deliberate grants.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Create a file with requested mode 0666 in a private directory while a child uses umask 0077. Inspect the resulting mode and restore any modified process state. Compare fstat with lstat on a symlink.

    Check your understanding

    With no default ACL, what permission bits result from mode 0666 and umask 0077?

    Explain the answer

    0600: the mask removes group and other permissions.

    Permission bits are 0600, before any later chmod.
