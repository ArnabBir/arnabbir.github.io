Chapter 15 — File Attributes

Every file has metadata stored in its inode — type, permissions, ownership, size, timestamps. stat() is how you read it. The struct stat is your window into the inode: it tells you the file type (regular, directory, symlink, device), permission bits, owner/group, size, and three timestamps (atime, mtime, ctime).

Understanding st_mode bit layout, the difference between the three timestamps, how umask affects file creation, and when to use lstat vs stat vs fstat is essential for writing correct file-handling code and debugging permission issues.

Invariant
stat() returns an inode metadata snapshot; st_mode encodes both file type and permission bits in a single field.
Gotcha
ctime is inode-change time (not creation time); any metadata change (chmod, chown, link) updates ctime.
Debugging
Use stat(1) command for human-readable output; strace stat/lstat calls to see which path variant is used.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • stat() returns a snapshot of inode metadata; the file can change between stat() and subsequent operations (TOCTOU).
  • st_mode encodes file type in upper 4 bits (S_ISREG, S_ISDIR, S_ISLNK macros) and permissions in lower 12 bits (rwx for u/g/o + setuid/setgid/sticky).
  • Three timestamps: atime (last access/read), mtime (last data modification), ctime (last inode change — permissions, links, etc). There is no portable creation time (use statx for birth time on Linux 4.11+).
  • umask is a per-process mask that filters OUT permission bits at file creation: effective_mode = requested_mode & ~umask.
  • The sticky bit on directories restricts deletion: only file owner, directory owner, or root can unlink files within.
  • lstat() does NOT follow symlinks (returns symlink inode); stat() follows symlinks; fstat() operates on an already-open fd.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
atime performance impact and mount options
  • Default atime updates on every read cause write I/O on read-only workloads — significant performance cost.
  • relatime (default since Linux 2.6.30): only updates atime if atime < mtime or atime is >24h old.
  • noatime: never updates atime — best performance, but breaks programs that depend on atime (e.g., mutt).
  • lazytime: batches timestamp updates in memory, writes them lazily — good compromise.
stat vs lstat and symlink handling
  • stat() follows symlinks: you get metadata of the target. If the target is missing, stat() returns ENOENT.
  • lstat() returns metadata of the symlink itself: st_size is the length of the target path string.
  • fstat() on an fd always returns the file the fd points to (symlinks already resolved at open time).
  • chmod on a symlink path changes the TARGET's permissions; there is no portable way to chmod the link itself.
Permission checking subtleties
  • Permission checks use effective UID/GID, not real UID/GID (matters for setuid programs).
  • Root (UID 0) bypasses read/write checks but NOT execute check unless at least one x bit is set.
  • Setuid bit: on exec, effective UID becomes file owner. Cleared by chown. Security-critical.
  • New files inherit GID from parent directory if setgid is set on the directory (BSD semantics).
Birth time and statx
  • Traditional stat has no creation/birth time. Linux 4.11+ statx() provides stx_btime if the filesystem supports it.
  • ext4, XFS, Btrfs all store birth time; tmpfs does not.
  • statx() also allows requesting only specific fields (STATX_BASIC_STATS, STATX_BTIME) for efficiency.
  • statx() provides stx_mnt_id for identifying which mount a file belongs to.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// Read file metadata with stat
struct stat sb;
if (stat("/etc/passwd", &sb) == -1) { perror("stat"); exit(1); }
printf("Type: %s\n", S_ISREG(sb.st_mode) ? "regular" : "other");
printf("Size: %lld\n", (long long)sb.st_size);
printf("Perms: %04o\n", sb.st_mode & 07777);
printf("Links: %ld\n", (long)sb.st_nlink);

// Set permissions safely (preserve type bits)
mode_t new_mode = (sb.st_mode & S_IFMT) | 0640;
if (chmod("/etc/passwd", 0640) == -1) perror("chmod");

// Set timestamps with nanosecond precision
struct timespec times[2];
times[0].tv_nsec = UTIME_OMIT;  // don't change atime
times[1] = sb.st_mtim;          // preserve mtime
utimensat(AT_FDCWD, path, times, 0);

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Use fstat() on already-open fds rather than stat() on paths to avoid TOCTOU races.
  • Always check S_ISLNK with lstat() before operating on untrusted paths in privileged code.
  • Set umask explicitly in daemons (umask(027) or stricter) — don't inherit a permissive shell umask.
  • Remember: chown clears setuid/setgid bits; re-apply them deliberately if needed after ownership change.
  • Use noatime or relatime mount options for performance-sensitive workloads unless atime semantics are required.
