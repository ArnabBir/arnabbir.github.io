Chapter 22 — Signals: Advanced Features

Beyond basic signals — real-time signals provide queuing and ordering, sigsuspend atomically waits for signals, and signalfd converts signals into file descriptor events for clean epoll integration.

Standard signals have a fundamental limitation: they do not queue. If the same signal is delivered multiple times while blocked, only one instance is recorded as pending. Real-time signals (SIGRTMIN through SIGRTMAX) solve this with proper queuing, priority ordering, and the ability to carry an integer or pointer payload via sigqueue().

Invariant
Real-time signals are queued and delivered in signal-number order (lowest first); standard signals coalesce.
Gotcha
The RT signal queue has a finite depth (RLIMIT_SIGPENDING); sigqueue returns EAGAIN on overflow.
Best practice
Use signalfd for event-loop integration: block signals, read them as structured data from an fd.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Standard signals (1-31) are NOT queued: multiple deliveries while blocked collapse to one pending instance. You cannot count occurrences.
  • Real-time signals (SIGRTMIN to SIGRTMAX) ARE queued: each sigqueue() call enqueues a separate instance with guaranteed delivery.
  • Delivery order: lower-numbered RT signals have higher priority; within the same signal number, FIFO order is preserved.
  • sigqueue() sends a signal with a union sigval payload (integer or pointer); the receiver gets it via siginfo_t in an SA_SIGINFO handler.
  • sigsuspend() atomically replaces the signal mask and suspends the thread; this eliminates the race window between sigprocmask and pause.
  • signalfd() creates a file descriptor that delivers signal information via read(); the signal must be blocked (SIG_BLOCK) to be received via signalfd rather than the default disposition.
  • pidfd_send_signal() (Linux 5.1+) sends a signal to a process identified by pidfd, eliminating PID-reuse races that plague kill().

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Real-time signal queue overflow
  • The kernel maintains a per-user queue of pending signals, bounded by RLIMIT_SIGPENDING (check with ulimit -i).
  • When the queue is full, sigqueue() fails with EAGAIN. The signal is NOT delivered. This is a silent data loss vector.
  • Standard signals sent via kill() are not affected (they don't queue anyway), but sigqueue() for any signal uses the queue.
  • Production fix: monitor queue depth, design protocols that tolerate lost signals, or use alternative IPC for high-rate communication.
sigsuspend atomicity: why pause() is broken
  • The classic race: unblock signal with sigprocmask(), then call pause(). Signal can arrive between the two calls, before pause() sleeps.
  • Result: pause() sleeps forever because the signal already fired and won't fire again.
  • sigsuspend() solves this by atomically replacing the mask AND suspending in a single syscall; no window for the signal to slip through.
  • Pattern: block signal, check condition, if not met call sigsuspend with mask that unblocks the signal.
signalfd and default disposition interaction
  • If a signal is NOT blocked when signalfd is used, the default disposition fires (e.g., SIGTERM kills the process) and signalfd never sees it.
  • You MUST block the signal via sigprocmask/pthread_sigmask before it can be received through signalfd.
  • signalfd reads return struct signalfd_siginfo (128 bytes) with fields like ssi_signo, ssi_pid, ssi_int (sigqueue data).
  • Multiple pending signals of the same standard signal still coalesce to one read; RT signals produce one read per queued instance.
Signal delivery order guarantees
  • Among different pending RT signals, lower signal numbers are delivered first (SIGRTMIN before SIGRTMIN+1).
  • Among multiple instances of the same RT signal, FIFO order is guaranteed.
  • Standard signals have no ordering guarantee relative to each other or to RT signals.
  • After sigsuspend/sigwaitinfo returns, re-check all conditions; multiple signals may have become pending simultaneously.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// signalfd + epoll integration pattern
#include <sys/signalfd.h>
#include <sys/epoll.h>
#include <signal.h>
#include <unistd.h>

void run_signal_loop(void) {
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGRTMIN);
    sigprocmask(SIG_BLOCK, &mask, NULL);  // must block first

    int sfd = signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);
    int epfd = epoll_create1(EPOLL_CLOEXEC);
    struct epoll_event ev = { .events = EPOLLIN, .data.fd = sfd };
    epoll_ctl(epfd, EPOLL_CTL_ADD, sfd, &ev);

    for (;;) {
        struct epoll_event events[8];
        int n = epoll_wait(epfd, events, 8, -1);
        for (int i = 0; i < n; i++) {
            struct signalfd_siginfo si;
            read(events[i].data.fd, &si, sizeof(si));
            if (si.ssi_signo == SIGINT) break;
            // si.ssi_int contains sigqueue payload
        }
    }
}

// sigqueue with data payload
union sigval val = { .sival_int = 42 };
sigqueue(target_pid, SIGRTMIN, val);

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Use signalfd for event-loop servers; avoid signal handlers in multi-threaded code entirely.
  • Block signals before creating signalfd; verify with /proc/self/status SigBlk field.
  • Handle EAGAIN from sigqueue gracefully; design for queue overflow in high-throughput scenarios.
  • Use sigsuspend (not pause) when waiting for signals; document the mask atomicity requirement.
  • Prefer pidfd_send_signal over kill() in process supervisors to eliminate PID reuse races.
