    TOPIC 64 / 64 · Pseudoterminals

    A PTY includes a terminal line discipline

    A terminal emulator writes Ctrl-C to its master but the application receives a signal rather than a literal byte.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    A pseudoterminal pairs a master with a terminal-like slave. Input written at the master passes through the slave's terminal processing; output written at the slave becomes readable at the master. With ISIG enabled and a foreground process group established, the configured interrupt character generates SIGINT for that group. Canonical buffering and echo can change what each side observes.

    Contract and implementation boundary

    The UNIX 98 sequence is posix_openpt, grantpt, unlockpt, ptsname, then opening the slave, checking each result. Session creation and controlling-terminal setup are additional work for a shell launcher. A PTY master is not itself a terminal emulator: screen escape sequences still need a user-space interpreter.

    Contract references: pty.7 · posix_openpt.3 · grantpt.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Treating a PTY as a transparent socket ignores echo, CR/LF translation, signal generation, and canonical input. A master read after slave shutdown has platform-specific details; do not teach one observed errno as universal POSIX behavior. Terminal setup belongs to an explicit session/job-control protocol.

    Worked reasoning trace

    Assumptions: Canonical PTY; echo enabled; ISIG enabled; foreground group established.

    1. Starting state

      Master writes a; slave line buffer holds a.

    2. Operation

      Master writes newline.

    3. Expected observation

      Slave can receive a plus newline; echo is separate output visible at the master.

    Tradeoff: A PTY supports terminal programs but is not a transparent byte transport.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Use the PTY model with echo on/off and canonical/noncanonical input. Type a, then newline; inspect delivery versus echo. Send the interrupt character with ISIG enabled and disabled. The model reports a signal event but does not launch or signal any real process.

    Check your understanding

    Does writing the configured interrupt character to a PTY master always deliver that byte unchanged?

    Explain the answer

    No. With ISIG and appropriate terminal setup it can generate a foreground-group signal.
