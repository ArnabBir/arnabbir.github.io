    TOPIC 31 / 64 · Threads: Thread Safety and Per-Thread Storage

    Thread-local storage is not object isolation

    A supposedly thread-safe helper returns a pointer that changes after a later call.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Thread safety describes allowed concurrent use, not necessarily independent result storage. Reentrancy is another property. Thread-local storage supplies one value per thread, useful for error state and caches, but any pointers stored there may still refer to shared objects.

    Contract and implementation boundary

    pthread_key_create creates a key shared across threads; pthread_setspecific assigns that thread's value. A destructor can release per-thread heap storage on thread exit subject to destructor iteration rules. C thread-local objects have storage semantics distinct from heap ownership.

    Contract references: pthread_key_create.3 · pthread_setspecific.3 · attributes.7. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Deleting a pthread key does not automatically free all values stored by existing threads. A thread-local pointer to a global mutable buffer does not remove the underlying race. Static-result functions can invalidate earlier pointers even in a single thread.

    Worked reasoning trace

    Assumptions: One thread stores a pointer to a shared global buffer in thread-local storage.

    1. Starting state

      A second thread holds another pointer to that same buffer.

    2. Operation

      Both modify the pointed-to bytes without synchronization.

    3. Expected observation

      Thread-local pointer variables do not remove the shared-data race.

    Tradeoff: Caller-owned buffers make ownership clearer than hidden reusable storage.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Design a formatter whose caller supplies a buffer, then compare it with one returning thread-local storage. State whether two consecutive calls in the same thread can retain both results. Make the lifetime part of the API documentation.

    Check your understanding

    Does making a pointer thread-local make the shared object it points to thread-local too?

    Explain the answer

    No. Pointer storage and pointed-to object ownership are separate.

    Thread-local pointer variables do not remove the shared-data race.
