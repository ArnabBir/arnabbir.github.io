    TOPIC 18 / 64 · Directories and Links

    Directory traversal without name races

    A recursive tool accidentally follows a symlink outside its intended tree.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    A hard link is another directory entry for an inode; a symbolic link stores a path interpreted during lookup. Relative symlink targets are resolved relative to the link's containing directory. An open directory descriptor can anchor relative operations even when the working directory changes.

    Contract and implementation boundary

    openat takes a directory descriptor and a relative path; an absolute path ignores that descriptor. O_NOFOLLOW protects the final component, not every earlier component. Linux openat2 offers resolution constraints such as RESOLVE_BENEATH when a stronger traversal policy is required.

    Contract references: openat2.2 · open.2 · readdir.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    readdir's d_type can be DT_UNKNOWN, so robust tools cannot require it to contain a type. readlink returns a byte count and does not append a terminating NUL. chdir is process-wide and can interfere with other threads.

    Worked reasoning trace

    Assumptions: The final component is ordinary, but an earlier component is a symlink.

    1. Starting state

      root/link/file traverses link to an outside directory.

    2. Operation

      open uses only O_NOFOLLOW.

    3. Expected observation

      Final-component protection alone does not confine the entire lookup.

    Tradeoff: openat2 resolution constraints are stronger but Linux-specific.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Draw a tree with a relative symlink pointing to ../outside. Resolve it component by component. Compare a final-component O_NOFOLLOW policy with a beneath-root policy and identify which one rejects intermediate traversal.

    Check your understanding

    Does O_NOFOLLOW alone forbid symlinks in every pathname component?

    Explain the answer

    No. Its ordinary open behavior concerns the final component.

    Final-component protection alone does not confine the entire lookup.
