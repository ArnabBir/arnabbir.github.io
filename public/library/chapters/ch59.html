Chapter 59 — Sockets: Internet Domains

Internet domain sockets implement TCP/IP networking — socket()+bind()+listen()+accept() on the server side, socket()+connect() on the client side. This is the concrete API for building networked services.

getaddrinfo() provides protocol-independent name resolution, replacing the obsolete gethostbyname(). Combined with SO_REUSEADDR and proper error handling, these primitives form the foundation for both iterative and concurrent TCP servers.

Invariant
Server pattern: socket → setsockopt(SO_REUSEADDR) → bind → listen → accept loop. Client: socket → connect → read/write → close.
Gotcha
Without SO_REUSEADDR before bind(), restarting a server hits EADDRINUSE due to TIME_WAIT sockets from the previous instance.
Debugging
Use getaddrinfo() with AI_PASSIVE for server bind; iterate the result list to support both IPv4 and IPv6. Always call freeaddrinfo().

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Server lifecycle: socket() creates the fd; bind() assigns a local address:port; listen(backlog) marks it passive and sets the accept queue size; accept() blocks until a client connects and returns a new connected fd.
  • Client lifecycle: socket() creates the fd; connect() initiates the TCP handshake to the server address:port; on success, read/write on the fd; close() when done.
  • getaddrinfo() replaces gethostbyname/getservbyname — it handles IPv4/IPv6, numeric/hostname, and service name/port lookup in one call. Returns a linked list; try each result until connect/bind succeeds.
  • SO_REUSEADDR must be set before bind() — it allows binding to an address that has sockets in TIME_WAIT, which is essential for server restarts.
  • An iterative server handles one client at a time in the accept loop. Simple but blocks other clients during service.
  • Concurrent approaches: fork() per connection (isolation, resource-heavy), pthread_create per connection (shared state, lighter), or event-driven with epoll (highest throughput).
  • SO_REUSEPORT allows multiple sockets to bind the same address:port — kernel distributes incoming connections across them for multi-accept scaling.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
getaddrinfo pitfalls and best practices
  • getaddrinfo() can block for DNS resolution (seconds). In event-driven servers, use async DNS (c-ares, getaddrinfo_a) or resolve in a thread pool.
  • Always set hints.ai_socktype (SOCK_STREAM or SOCK_DGRAM) — otherwise getaddrinfo returns duplicate entries for each socket type.
  • EAI_AGAIN means temporary DNS failure; retry with backoff. EAI_NONAME means the hostname doesn't exist.
  • The returned addrinfo list is heap-allocated; failing to call freeaddrinfo() leaks memory.
SO_REUSEADDR and TIME_WAIT
  • After a TCP connection closes, the side that sends the final FIN enters TIME_WAIT for 2*MSL (~60s). Without SO_REUSEADDR, bind() fails with EADDRINUSE during this window.
  • SO_REUSEADDR allows binding over TIME_WAIT sockets but NOT over an actively listening socket on the same port.
  • Always set SO_REUSEADDR before bind() on server sockets. This is so universal it should be automatic in your server template.
  • For graceful shutdown, close the listen socket first, then drain existing connections, then exit.
Server accept loop patterns
  • Iterative: accept() in a loop, handle client, close client fd, loop back to accept. One client at a time — fine for quick requests.
  • Concurrent fork: accept() then fork(). Parent closes client fd, child handles it. Simple isolation but fork() is expensive (copy page tables).
  • Concurrent threads: accept() then pthread_create(). Shared address space — be careful with data races. Thread pool avoids creation overhead.
  • Event-driven: single thread with epoll. All fds nonblocking. Highest throughput but complex state management per connection.
Connection failures and error handling
  • ECONNREFUSED: the peer host is reachable but nothing is listening on the port. Check server is running and bound to the right address.
  • ETIMEDOUT: no response at all. Likely a firewall dropping packets or the host is down. Distinguish from EHOSTUNREACH (ICMP unreachable).
  • EMFILE on accept(): process fd limit reached. Options: raise ulimit, close idle connections, or temporarily stop accepting.
  • Partial writes on TCP: send/write may return less than requested. Always loop until all bytes are sent or an error occurs.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// getaddrinfo + TCP client connecting to a server
#include <sys/socket.h>
#include <netdb.h>
#include <string.h>
#include <unistd.h>
#include <stdio.h>

int tcp_connect(const char *host, const char *port) {
    struct addrinfo hints, *res, *rp;
    memset(&hints, 0, sizeof(hints));
    hints.ai_family   = AF_UNSPEC;    // IPv4 or IPv6
    hints.ai_socktype = SOCK_STREAM;  // TCP

    int err = getaddrinfo(host, port, &hints, &res);
    if (err) { fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(err)); return -1; }

    int fd = -1;
    for (rp = res; rp; rp = rp->ai_next) {
        fd = socket(rp->ai_family, rp->ai_socktype | SOCK_CLOEXEC, rp->ai_protocol);
        if (fd == -1) continue;
        if (connect(fd, rp->ai_addr, rp->ai_addrlen) == 0) break;  // success
        close(fd); fd = -1;
    }
    freeaddrinfo(res);
    return fd;  // -1 on failure, valid fd on success
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always set SO_REUSEADDR before bind() on server sockets to handle TIME_WAIT after restart.
  • Use getaddrinfo() with AF_UNSPEC and iterate results — support both IPv4 and IPv6 transparently.
  • Set listen backlog to at least 128 (or SOMAXCONN) for production servers to handle burst connections.
  • Use accept4() with SOCK_CLOEXEC|SOCK_NONBLOCK to avoid fd leaks and races.
  • Handle partial writes: loop send() until all bytes are written or a real error occurs (not EINTR).
