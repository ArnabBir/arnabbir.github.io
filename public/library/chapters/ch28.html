Chapter 28 — Process Creation and Program Execution in More Detail

Beyond fork+exec — system() for shell commands, popen() for bidirectional pipe+exec, clone() for fine-grained task creation (the foundation of both threads and containers), and process accounting for auditing resource usage.

These higher-level and lower-level interfaces bracket the fork/exec primitives: system() is dangerously convenient, while clone() gives you scalpel-level control over what parent and child share.

Invariant
system() = fork + exec("/bin/sh", "-c", cmd) + waitpid. popen() = pipe + fork + exec + fdopen. clone() = fork with selective sharing.
Gotcha
system() passes strings to /bin/sh — shell injection via unsanitized input is trivial. Never use with user-controlled data.
Debugging
Use strace -f to trace system()/popen() — you'll see the fork, exec of /bin/sh, and the actual command execution underneath.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • system(cmd) = fork + exec("/bin/sh", "-c", cmd) + waitpid. Convenient but dangerous: shell metacharacters are interpreted, signals must be handled carefully.
  • system() blocks SIGCHLD and ignores SIGINT/SIGQUIT in the parent during execution (per POSIX). This interacts poorly with custom SIGCHLD handlers.
  • popen(cmd, mode) = pipe + fork + exec("/bin/sh", "-c", cmd) with one end wrapped in a FILE*. Mode "r" reads child stdout; "w" writes to child stdin.
  • pclose(fp) closes the pipe and calls waitpid — you MUST use pclose (not fclose) to avoid zombie leaks and get the exit status.
  • clone(fn, stack, flags, arg) is the Linux-specific syscall underlying both fork (SIGCHLD only) and pthread_create (CLONE_VM|CLONE_FILES|...).
  • clone flags select what to share: CLONE_VM (address space), CLONE_FILES (fd table), CLONE_NEWNS (mount namespace), CLONE_NEWPID (PID namespace), etc.
  • unshare(flags) is the post-creation version: dissociate the calling process from specified shared resources without forking.
  • CLONE_NEWPID creates a PID namespace — the first process inside is PID 1 and must handle orphan reaping (like init).
  • Process accounting (acct(2)) writes a record per terminated process: CPU time, memory high-water, command name. Useful for auditing and billing.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Shell injection via system()
  • system("grep " + user_input + " /etc/passwd") — if user_input is "; rm -rf /", you execute arbitrary commands.
  • system() invokes /bin/sh -c, so all shell metacharacters (;, |, &, $, `, etc.) are interpreted.
  • Fix: never pass unsanitized input to system(). Use fork+execvp with an explicit argv array instead.
  • If you must use system(), validate input against a strict allowlist (alphanumeric only) and quote arguments.
system() and SIGCHLD handler interaction
  • POSIX requires system() to block SIGCHLD during execution. If you have a SIGCHLD handler, it won't fire for the system() child.
  • But: if your SIGCHLD handler calls waitpid(-1, ...), it can accidentally reap system()'s child before system() does, causing system() to return -1/ECHILD.
  • Fix: use waitpid with a specific PID in your handler, or avoid mixing system() with SIGCHLD handlers.
  • Better: avoid system() entirely in programs that manage child processes.
popen and SIGPIPE
  • If you popen("cmd", "w") and the child exits early, writing to the FILE* generates SIGPIPE (default: terminate).
  • Handle or ignore SIGPIPE if using popen in write mode: signal(SIGPIPE, SIG_IGN) and check write/fflush errors.
  • popen streams are fully buffered — data may not reach the child until you fflush() or pclose().
  • pclose() returns the child's wait status; check it for errors (the command may have failed silently).
clone with CLONE_NEWPID — PID 1 responsibilities
  • The first process in a new PID namespace becomes PID 1 inside that namespace. It has special responsibilities.
  • If PID 1 in a namespace dies, all other processes in the namespace are killed with SIGKILL.
  • PID 1 must reap orphaned children (just like system init). Failing to do so creates zombies inside the namespace.
  • Container runtimes (Docker, runc) often use tini or dumb-init as PID 1 to handle signal forwarding and reaping.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// Safe command execution (avoiding system() injection) + popen pattern
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/wait.h>
#include <unistd.h>

// SAFE: explicit argv, no shell interpretation
int run_safe(const char *prog, const char *arg) {
    pid_t pid = fork();
    if (pid == 0) {
        execlp(prog, prog, arg, (char*)NULL);
        _exit(127);
    }
    int status;
    waitpid(pid, &status, 0);
    return WIFEXITED(status) ? WEXITSTATUS(status) : -1;
}

// popen pattern: read command output into buffer
char *capture_output(const char *cmd) {
    FILE *fp = popen(cmd, "r");
    if (!fp) return NULL;
    char *buf = NULL; size_t len = 0;
    ssize_t n = getline(&buf, &len, fp);
    int status = pclose(fp);  // MUST use pclose, not fclose
    if (n < 0 || !WIFEXITED(status) || WEXITSTATUS(status) != 0) {
        free(buf); return NULL;
    }
    buf[strcspn(buf, "\n")] = '\0';  // strip trailing newline
    return buf;  // caller must free()
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Never pass untrusted input to system() or popen(). Use fork+execvp with explicit argv for user-controlled commands.
  • Always use pclose() (not fclose()) with popen streams to reap the child and get the exit status.
  • Handle SIGPIPE when using popen in write mode — the child may exit before you finish writing.
  • If using clone() for namespaces, ensure PID 1 in the namespace handles reaping and signal forwarding.
  • Prefer posix_spawn() over system() when you need convenience but don't need shell interpretation.
