Chapter 40 — Login Accounting

Login accounting tracks who logged in, when, and from where. The utmp file records current active sessions, wtmp accumulates the full login/logout history, and lastlog stores the most recent login for each user. Together they form the observability backbone for multi-user systems.

Programs like login, sshd, and terminal emulators are responsible for writing utmp/wtmp entries on session start and clearing them on logout. Commands like who, w, and last consume these databases to report session state.

Invariant
Every login creates a utmp entry keyed by ut_line (terminal); logout must clear that same entry or stale sessions appear.
Gotcha
If a program crashes without writing a DEAD_PROCESS record, utmp shows a ghost session — who reports a user that isn't actually logged in.
Debugging
Use utmpdump /var/run/utmp to inspect raw records; last -f /var/log/wtmp to trace historical sessions.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • utmp records current sessions (/var/run/utmp) — each entry corresponds to one active login, keyed by ut_line (the terminal device).
  • wtmp (/var/log/wtmp) is an append-only log of all login and logout events; it grows indefinitely unless rotated.
  • lastlog (/var/log/lastlog) is a fixed-size file indexed by UID, storing only the most recent login time, terminal, and remote host per user.
  • getutxent() iterates through utmp entries sequentially; setutxent() rewinds; endutxent() closes.
  • pututxline() writes or updates an entry — it searches for a matching ut_line slot before appending.
  • Login programs write USER_PROCESS; logout writes DEAD_PROCESS to the same ut_line slot, marking the session ended.
  • who and w read utmp for current sessions; last reads wtmp for historical login/logout pairs.
  • On modern systems, systemd-logind provides session tracking via D-Bus, but utmp/wtmp are still maintained for compatibility with traditional tools.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Stale utmp entries (ghost sessions)
  • If a terminal emulator or SSH session crashes without writing a DEAD_PROCESS record, utmp retains the old USER_PROCESS entry.
  • who will report a user as logged in even though no process owns that session anymore.
  • Fix: a cleanup daemon or login program should check if the PID in ut_pid is still alive before trusting the entry.
  • On systemd systems, logind handles session lifecycle and cleans up, but utmp may still lag behind.
wtmp rotation and file size
  • wtmp is append-only and grows without bound. logrotate typically rotates it monthly.
  • last reads wtmp sequentially from the end; a very large wtmp slows queries.
  • Corrupted wtmp (partial writes during crash) can confuse last — it may skip entries or report garbage.
  • Some distributions use wtmp.1, wtmp.2 etc. for rotated files; last -f reads specific files.
lastlog sparse file behavior
  • lastlog is indexed by UID — seeking to offset UID * sizeof(struct lastlog). UIDs with large values create a sparse file.
  • A system with UID 65534 (nobody) causes lastlog to appear huge on disk but uses minimal blocks (filesystem holes).
  • cp or tar without sparse-awareness can inflate the file to its apparent size; use cp --sparse=always.
  • The lastlog command reads this file to display per-user last login info.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// List active login sessions from utmp (similar to 'who')
#include <utmpx.h>
#include <stdio.h>
#include <time.h>

int main(void) {
    struct utmpx *ut;
    setutxent();
    while ((ut = getutxent()) != NULL) {
        if (ut->ut_type != USER_PROCESS)
            continue;
        time_t t = ut->ut_tv.tv_sec;
        printf("%-8s %-12s %s",
               ut->ut_user, ut->ut_line, ctime(&t));
    }
    endutxent();
    return 0;
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always write a DEAD_PROCESS entry on session exit — even in signal handlers and crash paths.
  • Fill all required utmpx fields: ut_type, ut_pid, ut_line, ut_user, ut_tv, and ut_host for remote logins.
  • Rotate wtmp with logrotate to prevent unbounded growth; verify with last after rotation.
  • Handle lastlog sparse file correctly in backup/restore scripts (use sparse-aware tools).
  • On systemd systems, integrate with logind for session tracking; maintain utmp/wtmp for compatibility with traditional tools (who, last, finger).
