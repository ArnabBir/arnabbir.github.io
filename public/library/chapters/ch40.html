    TOPIC 40 / 64 · Login Accounting

    Login records are accounting, not authority

    A tool treats a login-record entry as proof that a user is currently authenticated.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    utmp-style records describe login and session accounting conventions. They are mutable records maintained by cooperating programs, not a complete authoritative view of every process or authentication event. Containers, remote services, and graphical sessions may not fit a simple terminal-login model.

    Contract and implementation boundary

    Use documented utmpx interfaces and respect fixed-size fields that may not be NUL-terminated. Record timestamps and terminal names are data requiring validation. Do not edit the system accounting database for an educational experiment; work with a private copy or synthetic record.

    Contract references: utmp.5 · getutent.3 · getutxent.3. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Assuming every active user has a record can omit sessions. Assuming every record is fresh can count stale sessions. Binary layouts and time-field widths can vary by ABI, so raw structs are a poor cross-machine interchange format.

    Worked reasoning trace

    Assumptions: A synthetic fixed-width username field has no terminating NUL.

    1. Starting state

      The decoder receives exactly the record's documented field length.

    2. Operation

      Print with an explicit bound rather than scanning as an unlimited C string.

    3. Expected observation

      No bytes beyond the field are consumed.

    Tradeoff: Binary accounting is compact but ABI-dependent and not proof of authentication.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Create a synthetic bounded record decoder that prints fixed-size fields with explicit lengths. Explain how you would distinguish no record, stale record, and a permission failure without presenting any of them as authentication proof.

    Check your understanding

    Is a utmp entry sufficient evidence to authorize a privileged operation?

    Explain the answer

    No. Accounting records are not an authentication or authorization decision.
