Chapter 08 — Users and Groups

Identity management in Linux — how the kernel maps UIDs to names, password storage and hashing, NSS (Name Service Switch), and safe credential lookup patterns. The kernel operates entirely on integer UIDs/GIDs; translating between names and numbers is a user-space concern handled by NSS and the passwd/group databases.

Invariant
The kernel only knows UIDs/GIDs as integers; name→UID mapping is purely user-space (NSS).
Gotcha
getpwnam/getpwuid return pointers to static buffers — not thread-safe; use the _r variants in any multithreaded code.
Debugging
id(1), groups(1), and getent passwd/group query the actual NSS sources — use them to verify what your process will see.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • UIDs and GIDs are kernel-level integers. Every permission check, file ownership test, and signal delivery uses raw numeric IDs — never strings.
  • Names are a user-space convention resolved via NSS. The Name Service Switch (/etc/nsswitch.conf) determines where lookups go: local files, LDAP, SSSD, NIS, etc.
  • /etc/passwd has a fixed 7-field format: login:x:uid:gid:gecos:home:shell. The x in the password field means "look in /etc/shadow".
  • The shadow file separates password hashes from the world-readable passwd file. Only root (or shadow group) can read /etc/shadow, preventing offline brute-force by unprivileged users.
  • Supplementary groups extend the primary GID. A process can belong to up to NGROUPS_MAX groups (typically 65536 on Linux); all are checked during permission evaluation.
  • NSS plugins (files, ldap, sss) control where lookups go. Ordering in nsswitch.conf matters — a slow or failing LDAP backend can stall getpwnam() for every login.
Key terms & kernel objects
Term / objectMeaning
UIDUser ID — 32-bit unsigned integer identifying a user to the kernel. Stored in process credentials and inode metadata.
GIDGroup ID — 32-bit unsigned integer for group membership. Primary GID comes from /etc/passwd; supplementary GIDs from /etc/group.
/etc/passwdWorld-readable user database (7 colon-separated fields). Does not contain actual password hashes on modern systems.
/etc/shadowRoot-readable file storing password hashes, aging info, and account expiry. Keyed by username.
NSSName Service Switch — glibc framework that dispatches getpw*/getgr* calls to configured backends (files, LDAP, SSSD).
getpwnam_rThread-safe reentrant version of getpwnam(). Caller supplies the buffer; no static data races.
crypt(3)One-way password hashing function. Supports multiple algorithms via prefix ($6$ = SHA-512, $y$ = yescrypt).
Supplementary groupsAdditional GIDs beyond the primary GID. Set via initgroups()/setgroups(); checked by the kernel on every access() and open().

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Thread safety of passwd/group functions
  • getpwnam(), getpwuid(), getgrnam(), getgrgid() all return pointers to a single static struct — a second call from any thread overwrites the previous result.
  • Even in single-threaded code, calling getpwnam() inside a loop where you also call getgrnam() can corrupt the first result since they may share internal buffers.
  • Always use the _r (reentrant) variants in libraries and multithreaded programs. Start with sysconf(_SC_GETPW_R_SIZE_MAX) for initial buffer size, and retry on ERANGE.
  • setpwent()/getpwent()/endpwent() for iteration are inherently non-reentrant — serialize access or use fgetpwent_r() on a private FILE*.
NSS ordering and failures
  • nsswitch.conf controls lookup order: passwd: files sss ldap. Each source is tried in order until a definitive answer is found.
  • Action items like [NOTFOUND=return] or [UNAVAIL=continue] control fallback behavior — misconfiguration here causes silent lookup failures.
  • A hung LDAP/SSSD backend blocks getpwnam() — this can stall login, sudo, and any daemon doing user lookups. Set timeouts in SSSD/nslcd config.
  • NSS modules are loaded as shared libraries into the calling process. A buggy NSS module can crash your application.
UID overflow and sentinel values
  • Linux UIDs are 32-bit (0 to 4294967294). UID 65534 is conventionally "nobody" — used by NFS and the kernel when no valid mapping exists.
  • Some legacy systems and protocols (NFSv2) only support 16-bit UIDs (0–65535). Files owned by UIDs >65535 appear as "nobody" on these systems.
  • UID 0 is always root — this is hardcoded in the kernel, not configurable via NSS.
  • (uid_t)-1 (== 4294967295) is reserved as an error sentinel by setuid/setgid and should never be assigned to a real user.
  • The "nobody" user (65534) and "nogroup" group (65534) are kernel fallback values — do not use them for application service accounts.

Code patterns (C / POSIX)

Thread-safe user lookup with getpwnam_r and supplementary group enumeration. 
/* ch08: Thread-safe user lookup + supplementary group check */
#include <pwd.h>
#include <grp.h>
#include <errno.h>
#include <stdlib.h>
#include <stdio.h>
#include <unistd.h>

/* Lookup user by name — reentrant, safe for threads */
int lookup_user(const char *name) {
    struct passwd pwd, *result;
    long bufsize = sysconf(_SC_GETPW_R_SIZE_MAX);
    if (bufsize == -1) bufsize = 16384;   /* fallback */

    char *buf = malloc((size_t)bufsize);
    if (!buf) { perror("malloc"); return -1; }

    int s;
    while ((s = getpwnam_r(name, &pwd, buf, (size_t)bufsize, &result)) == ERANGE) {
        bufsize *= 2;
        char *nb = realloc(buf, (size_t)bufsize);
        if (!nb) { free(buf); perror("realloc"); return -1; }
        buf = nb;
    }
    if (s != 0)      { errno = s; perror("getpwnam_r"); free(buf); return -1; }
    if (!result)      { fprintf(stderr, "user '%s' not found\n", name); free(buf); return -1; }

    printf("user=%s  uid=%u  gid=%u  home=%s  shell=%s\n",
           pwd.pw_name, pwd.pw_uid, pwd.pw_gid, pwd.pw_dir, pwd.pw_shell);

    /* Enumerate supplementary groups */
    int ngroups = 32;
    gid_t *groups = malloc(sizeof(gid_t) * (size_t)ngroups);
    if (getgrouplist(name, pwd.pw_gid, groups, &ngroups) == -1) {
        groups = realloc(groups, sizeof(gid_t) * (size_t)ngroups);
        getgrouplist(name, pwd.pw_gid, groups, &ngroups);
    }
    printf("supplementary groups (%d):", ngroups);
    for (int i = 0; i < ngroups; i++) printf(" %u", groups[i]);
    putchar('\n');

    free(groups);
    free(buf);
    return 0;
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Use getpwnam_r / getgrnam_r (never the non-reentrant versions) in any multithreaded or library code.
  • Handle ERANGE from _r functions by retrying with a larger buffer — do not assume sysconf gives a sufficient size.
  • Distinguish "not found" (result == NULL, return == 0) from "error" (return != 0) in getpwnam_r results.
  • Never hardcode UID/GID values — resolve at runtime via NSS. Exception: UID 0 is always root.
  • Verify NSS configuration (nsswitch.conf) and set timeouts on remote backends (LDAP/SSSD) to avoid stalling user lookups.
  • Use crypt() with strong salt prefixes ($6$ for SHA-512 or $y$ for yescrypt) — never MD5 ($1$) or DES.
  • Log the resolved UID/GID at process startup for debuggability in production incidents.

Exercises

Hands-on tasks to make the chapter "stick". These are intentionally practical and debugging-heavy.
  • Write a C program that calls getpwnam_r for the current user and prints all 7 passwd fields. Run it under strace and confirm it opens /etc/passwd (or contacts SSSD).
  • Demonstrate the static-buffer bug: call getpwnam("root"), save the pointer, call getpwnam("nobody"), then print the first pointer's pw_name. Explain the result.
  • Use getent passwd and getent group to enumerate all NSS-visible users/groups. Compare with raw cat /etc/passwd — note any entries from LDAP/SSSD that only appear via getent.
  • Write a program that calls getgrouplist() for a user and prints all supplementary group names (resolve each GID via getgrgid_r).
  • Modify /etc/nsswitch.conf (in a VM) to put a nonexistent source first (passwd: notreal files). Observe login behavior and strace output.
