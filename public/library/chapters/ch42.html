Chapter 42 — Advanced Features of Shared Libraries

dlopen enables plugin architectures — load code at runtime, resolve symbols dynamically, and control visibility. This is the foundation of extensible applications: database engines loading storage backends, web servers loading protocol modules, and audio frameworks loading codec plugins.

LD_PRELOAD enables transparent function interposition — inject wrapper libraries that intercept malloc, open, write, or any other function without modifying or relinking the target binary. Combined with constructor/destructor attributes and symbol versioning, these mechanisms provide fine-grained control over shared library behavior.

Invariant
dlopen() returns a handle to a loaded shared object; dlsym() resolves symbols within that scope. Always check dlerror() after both calls.
Gotcha
dlclose() can unload code while threads still hold function pointers into it — use-after-unload causes silent corruption or SIGSEGV.
Debugging
Use LD_DEBUG=bindings to trace runtime symbol resolution; nm -D to list exported symbols; objdump -T for symbol versions.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • dlopen(path, RTLD_LAZY|RTLD_NOW) loads a shared library at runtime, returning an opaque handle. RTLD_LAZY defers symbol resolution; RTLD_NOW resolves all symbols immediately (fail-fast).
  • dlsym(handle, "name") looks up a symbol in the loaded library. Returns a void pointer — cast to the appropriate function pointer type. Always call dlerror() first to clear, then check after.
  • dlclose() decrements the reference count; the library is unmapped when it reaches zero. Dangerous if callbacks, threads, or function pointers still reference the code.
  • RTLD_GLOBAL makes a library's symbols available for subsequent dlopen() calls' symbol resolution; RTLD_LOCAL (default) keeps them private to that handle.
  • LD_PRELOAD interposes functions: the preloaded library's symbols take priority in the global scope. Useful for malloc debugging, fd leak tracking, and testing.
  • __attribute__((constructor)) and __attribute__((destructor)) mark functions to run at library load and unload — analogous to C++ global constructors.
  • -fvisibility=hidden hides all symbols by default; selectively export with __attribute__((visibility("default"))) for a clean, minimal public API.
  • Symbol versioning (via version scripts or .symver directive) allows multiple ABI-incompatible implementations of the same symbol to coexist in one library.

API quick reference

A compact map of the APIs and their sharp edges. Always verify details with man 2/3.
API Signature / shape Common errno Notes
dlopenvoid *dlopen(const char *filename, int flags);—flags: RTLD_LAZY, RTLD_NOW, RTLD_GLOBAL, RTLD_LOCAL. NULL filename returns handle to main program. Check dlerror() on NULL return.
dlsymvoid *dlsym(void *handle, const char *symbol);—RTLD_DEFAULT searches global scope; RTLD_NEXT finds next occurrence (for interposition wrappers). Clear dlerror() before calling.
dlcloseint dlclose(void *handle);—Returns 0 on success. Library not unloaded if other handles or RTLD_NODELETE prevent it. Never dlclose if threads may still call into it.
dlerrorchar *dlerror(void);—Returns human-readable error string for last dl* failure, or NULL if no error. Clears the error state on each call.
Tip: always call dlerror() once before dlsym() to clear stale errors, then check it again after to detect real failures (since dlsym can legitimately return NULL).

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
dlopen/dlclose lifecycle hazards
  • dlclose() can unmap code while threads still execute it — this causes SIGSEGV or silent memory corruption. In practice, many plugin systems never call dlclose().
  • RTLD_NODELETE flag (or __attribute__((constructor)) with persistent state) prevents unloading even after dlclose().
  • If a library's constructor fails (e.g., resource allocation), there's no standard way to report the error — dlopen() still succeeds. Use an explicit init function instead.
  • Recursive dlopen() from within a constructor can deadlock on the dynamic linker's internal lock on some implementations.
LD_PRELOAD interposition patterns
  • LD_PRELOAD loads libraries before all others, making their symbols take priority in the flat global namespace.
  • Use RTLD_NEXT in the wrapper to call the original function: real_malloc = dlsym(RTLD_NEXT, "malloc").
  • LD_PRELOAD is ignored for setuid/setgid binaries (security measure by ld.so).
  • Common uses: memory leak detectors (replacing malloc/free), fd leak tracking (wrapping open/close), and test mocking (faking time(), random()).
Symbol visibility and versioning
  • -fvisibility=hidden makes all symbols internal by default; explicitly export only the public API with __attribute__((visibility("default"))).
  • Fewer exported symbols means faster load time (less work for ld.so) and a cleaner ABI surface.
  • Symbol versioning (via linker version scripts) lets you ship libfoo.so.1 with both foo_v1() and foo_v2() implementations bound to the same symbol name "foo" for different version tags.
  • Applications linked against the old version continue to resolve foo@VER_1; new applications get foo@VER_2 — no soname bump needed.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// Plugin system using dlopen/dlsym with proper error handling
#include <dlfcn.h>
#include <stdio.h>
#include <stdlib.h>

typedef int (*plugin_init_fn)(const char *config);
typedef void (*plugin_shutdown_fn)(void);

int load_plugin(const char *path) {
    dlerror();  // clear any stale error
    void *handle = dlopen(path, RTLD_NOW | RTLD_LOCAL);
    if (!handle) {
        fprintf(stderr, "dlopen failed: %s\n", dlerror());
        return -1;
    }
    dlerror();  // clear before dlsym
    plugin_init_fn init = (plugin_init_fn)dlsym(handle, "plugin_init");
    const char *err = dlerror();
    if (err) {
        fprintf(stderr, "dlsym failed: %s\n", err);
        dlclose(handle);
        return -1;
    }
    return init("default_config");
}

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always check dlerror() after dlopen() and dlsym() — NULL return from dlsym may be a valid symbol value.
  • Use RTLD_NOW for plugins in production to fail fast on missing symbols rather than crashing later on first call.
  • Prefer RTLD_LOCAL to avoid polluting the global symbol namespace with plugin internals.
  • Never dlclose() a library if any thread might still hold function pointers or callbacks into it.
  • Use -fvisibility=hidden and explicit exports to minimize your library's public ABI surface and improve load performance.
