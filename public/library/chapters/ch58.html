Chapter 58 — Sockets: Fundamentals of TCP/IP Networks

TCP/IP is the network protocol stack that underlies the internet. IP routes packets between hosts, TCP provides reliable ordered byte streams on top, and UDP provides lightweight unreliable datagrams. Understanding the layered architecture is essential for socket programming.

This chapter covers IP addressing, port numbers, the distinction between TCP and UDP, network byte order conversions, and the socket address structures (sockaddr_in, sockaddr_in6) that tie it all together at the system call level.

Invariant
Addresses and ports must be in network byte order (big-endian) in all socket structures — use htonl/htons/ntohl/ntohs consistently.
Gotcha
Forgetting byte-order conversion silently corrupts addresses/ports. On little-endian hosts, port 80 (0x0050) becomes 20480 (0x5000) without htons().
Debugging
Use inet_ntop() to print binary addresses as strings; getaddrinfo() for protocol-independent resolution; tcpdump to verify on-wire byte order.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • Four layers: link (Ethernet/WiFi frames), network (IP datagrams — routing between hosts), transport (TCP/UDP — multiplexing via ports), application (HTTP, DNS, etc.).
  • IP addresses identify hosts on the network; ports identify services within a host. Together they form a socket address.
  • TCP provides a reliable, ordered, bidirectional byte stream with flow control and congestion control. Connection-oriented: requires a 3-way handshake.
  • UDP provides unreliable datagrams: no connection setup, no ordering guarantees, no retransmission. Lower overhead, used for DNS, gaming, video.
  • Network byte order is big-endian. All multi-byte fields in socket address structures (addresses, ports) must be converted: htonl() for 32-bit, htons() for 16-bit.
  • struct sockaddr_in holds IPv4 (sin_family=AF_INET, sin_port, sin_addr). struct sockaddr_in6 holds IPv6. Both cast to generic struct sockaddr for syscalls.
  • MTU (Maximum Transmission Unit) limits packet size at the link layer (typically 1500 bytes for Ethernet). IP fragments oversized packets; TCP uses MSS to avoid fragmentation.
Key terms & kernel objects
Term / objectMeaning
TCPTransmission Control Protocol. Reliable, ordered byte stream over IP. Connection-oriented with handshake, retransmission, and flow control.
UDPUser Datagram Protocol. Unreliable, connectionless datagrams. No ordering, no retransmission — application must handle loss.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Byte order pitfalls
  • On x86 (little-endian), forgetting htons(80) stores 0x5000 (20480) instead of 0x0050 (80). Connections silently go to the wrong port.
  • htonl/htons are no-ops on big-endian architectures but must still be used for portability.
  • INADDR_ANY (0) and INADDR_LOOPBACK (127.0.0.1) still need htonl() wrapping in sockaddr_in.sin_addr.s_addr.
  • The same byte-order rules apply to IPv6 addresses in sockaddr_in6, though inet_pton handles conversion for you.
IPv4 vs IPv6 dual-stack
  • AF_INET6 sockets can accept IPv4 connections via IPv4-mapped addresses (::ffff:a.b.c.d) if IPV6_V6ONLY is not set.
  • IPV6_V6ONLY (default varies by OS) controls whether an AF_INET6 socket also accepts IPv4. Set explicitly for predictable behavior.
  • getaddrinfo() with AI_V4MAPPED returns IPv4-mapped IPv6 addresses when no native IPv6 address exists.
  • Always use getaddrinfo() instead of hard-coding AF_INET — it handles dual-stack resolution transparently.
TCP vs UDP trade-offs
  • TCP guarantees delivery and ordering but adds latency (handshake, retransmission timeouts, congestion windows).
  • UDP has no connection state — each sendto() is independent. Application must handle loss, reordering, and duplication.
  • TCP head-of-line blocking: one lost segment delays all subsequent segments in the stream. QUIC (UDP-based) avoids this per-stream.
  • UDP has no built-in flow control. Sending faster than the receiver can process leads to kernel buffer overflow and silent packet drops.
MTU, fragmentation, and path MTU discovery
  • Ethernet MTU is typically 1500 bytes. IP packets larger than MTU are fragmented (IPv4) or rejected with ICMP Packet Too Big (IPv6).
  • TCP uses MSS negotiation to avoid fragmentation: MSS = MTU - 40 (IPv4) or MTU - 60 (IPv6) for headers.
  • Path MTU Discovery (PMTUD) sets DF (Don't Fragment) flag and relies on ICMP responses. Firewalls blocking ICMP break PMTUD — a common cause of "black hole" connections.
  • UDP applications sending large datagrams risk fragmentation and reassembly failures. Keep UDP payloads under 1400 bytes for reliability.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// Filling sockaddr_in + address conversion with inet_pton
#include <arpa/inet.h>
#include <string.h>
#include <stdio.h>

struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_port   = htons(8080);  // always convert port

if (inet_pton(AF_INET, "192.168.1.10", &addr.sin_addr) != 1) {
    perror("inet_pton"); return 1;
}
// addr is now ready for connect() or bind()

// Print it back:
char buf[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &addr.sin_addr, buf, sizeof(buf));
printf("addr=%s port=%d\n", buf, ntohs(addr.sin_port));

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Use htons/htonl for every port and address assignment — even constants like INADDR_ANY.
  • Use inet_pton/inet_ntop instead of deprecated inet_aton/inet_ntoa for thread safety and IPv6 support.
  • Use getaddrinfo() for all name resolution — it handles IPv4/IPv6, service names, and AI_PASSIVE for servers.
  • Always memset sockaddr structures to zero before filling to avoid undefined padding bytes.
  • Explicitly set IPV6_V6ONLY when using AF_INET6 sockets to control dual-stack behavior portably.
