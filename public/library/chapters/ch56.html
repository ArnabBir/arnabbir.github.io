    TOPIC 56 / 64 · Sockets: Introduction

    Sockets separate endpoints from application messages

    A receiver gets a header and only half the body in one recv call.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    A socket combines an address family, a communication type, and protocol behavior. Stream sockets carry ordered bytes without preserving send boundaries. Datagram sockets preserve datagram boundaries but have different loss, size, and zero-length rules. A listening socket accepts new connected sockets; it is not the connection used for application payload.

    Contract and implementation boundary

    socket, bind, listen, accept, and connect each establish a different stage. send can accept fewer bytes than requested. recv returning zero for a positive-size stream request indicates an orderly receive-side end after queued bytes are consumed. shutdown changes a direction of the connection; close releases a local descriptor reference.

    Contract references: socket.2 · socket.7 · recv.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Reading one C struct directly from a stream assumes framing, layout, endian, and complete delivery. A zero-length datagram is valid and is not stream EOF. A successful send does not prove the peer application processed the bytes.

    Worked reasoning trace

    Assumptions: Stream peer sends six payload bytes and shuts down its write side.

    1. Starting state

      Receiver has a two-byte buffer.

    2. Operation

      Drain three successful reads, then read again.

    3. Expected observation

      Zero reports receive-side end after the six bytes; reverse-direction sending can still be possible.

    Tradeoff: Half-close expresses directional completion but needs protocol agreement.

    Run sockets.c with a local socketpair and a write-side shutdown. Design a length-prefixed frame with a maximum payload of 1024 bytes. Trace a header delivered as two separate reads and reject an excessive advertised length before allocation.
