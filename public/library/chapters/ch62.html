Chapter 62 — Terminals

Terminals are the interface between users and processes — line disciplines control echo and editing, canonical mode provides line buffering, raw mode gives per-character input. Pseudo-terminals enable SSH, tmux, and terminal emulators.

The terminal subsystem is a layered stack: hardware or pty device, line discipline for input processing, and the termios API for configuration. Understanding the three I/O modes (canonical, noncanonical, raw) is essential for writing editors, shells, and interactive tools.

Invariant
Terminal = tty device + line discipline + process group. The line discipline decides what the process sees.
Gotcha
Failing to restore termios on exit (or crash) leaves the terminal in raw mode — breaking the user's shell.
Debugging
stty -a shows all termios flags; strace on tcsetattr reveals exactly what your program changes.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • A terminal is a tty device + line discipline + associated process group. The line discipline sits between the device driver and user-space reads/writes.
  • Canonical mode (ICANON): the kernel buffers input until newline or EOF — the line discipline handles backspace, Ctrl-U, and other editing. This is the default mode.
  • Noncanonical mode (~ICANON): input is available based on VMIN (minimum bytes) and VTIME (timeout in tenths of a second). Four combinations: blocking read (VMIN>0, VTIME=0), timed read, polling read (both 0), etc.
  • Raw mode: no processing at all — no echo, no signal generation, no CR/NL translation. Used by editors (vim), shells (zsh line editor), and SSH. Achieved by cfmakeraw() which clears ICANON, ECHO, ISIG, IEXTEN, and sets CS8.
  • The termios struct controls all attributes across four flag fields: c_iflag (input), c_oflag (output), c_cflag (control), c_lflag (local). tcgetattr/tcsetattr read and modify these.
  • Key c_lflag bits: ECHO (echo input), ICANON (canonical mode), ISIG (generate signals from Ctrl-C/Ctrl-Z/Ctrl-\).
  • A pseudo-terminal pair (master + slave) virtualizes a terminal: the master side (via /dev/ptmx) is controlled by an application; the slave (/dev/pts/N) looks like a real terminal to the child process.
  • PTYs are the foundation of remote shells (sshd), terminal multiplexers (tmux/screen), the script(1) command, and expect-like automation tools.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Canonical vs noncanonical vs raw
  • Canonical mode: read() blocks until a full line (newline, EOF, or EOL). The line discipline handles backspace, Ctrl-W (word erase), and Ctrl-U (line kill).
  • Noncanonical mode: VMIN=1, VTIME=0 gives single-character blocking reads. VMIN=0, VTIME>0 gives timed polling. VMIN=0, VTIME=0 gives pure polling (returns immediately with 0 if nothing available).
  • Raw mode (cfmakeraw): disables everything — ICANON, ECHO, ISIG, IEXTEN, ICRNL, OPOST, etc. Bytes arrive exactly as typed. You must handle Ctrl-C yourself.
  • tcsetattr with TCSAFLUSH is safest when switching modes — it drains output and discards pending input to avoid stale characters.
VMIN and VTIME combinations
  • VMIN>0, VTIME=0: blocking read, returns when at least VMIN bytes available. Most common for character-at-a-time input.
  • VMIN=0, VTIME>0: pure timed read — returns after VTIME*0.1 seconds even if no data. Returns 0 on timeout.
  • VMIN>0, VTIME>0: interbyte timer — VTIME starts after first byte; returns when VMIN reached OR timer expires.
  • VMIN=0, VTIME=0: polling mode — returns immediately with whatever is available (0 bytes if nothing).
Controlling terminal and signals
  • A session has at most one controlling terminal. The first tty opened by the session leader (after setsid) typically becomes the controlling terminal.
  • Ctrl-C generates SIGINT, Ctrl-Z generates SIGTSTP, Ctrl-\ generates SIGQUIT — all sent to the foreground process group by the tty driver.
  • Background processes that try to read from the controlling terminal receive SIGTTIN; writing may trigger SIGTTOU if TOSTOP is set.
  • Daemons call setsid() + close all ttys to detach from the controlling terminal — no more job control signals.
Pseudo-terminals overview
  • A pty master/slave pair emulates a terminal: writes to master appear as input on slave; writes to slave appear as output on master.
  • The slave side supports full termios: the child process can call tcgetattr/tcsetattr, isatty() returns true, and line discipline processing applies.
  • sshd creates a pty per session: remote keystrokes go to master, program output comes back through master to the network.
  • tmux creates one pty per pane: the master side is managed by the tmux server, each pane's shell sees a real terminal.

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// Raw mode setup + restore for a line editor
#include <termios.h>
#include <unistd.h>
#include <stdlib.h>

static struct termios orig;

void restore_term(void) { tcsetattr(STDIN_FILENO, TCSAFLUSH, &orig); }

void enable_raw(void) {
    tcgetattr(STDIN_FILENO, &orig);
    atexit(restore_term);           // restore on normal exit
    struct termios raw = orig;
    raw.c_iflag &= ~(ICRNL | IXON | BRKINT | INPCK | ISTRIP);
    raw.c_oflag &= ~(OPOST);       // disable output processing
    raw.c_lflag &= ~(ECHO | ICANON | ISIG | IEXTEN);
    raw.c_cflag |= CS8;
    raw.c_cc[VMIN] = 1;            // read returns after 1 byte
    raw.c_cc[VTIME] = 0;           // no timeout
    tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw);
}

// Usage: enable_raw(); then read(STDIN_FILENO, &c, 1) per keypress

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always save original termios with tcgetattr before modification; restore via atexit() AND signal handlers (SIGINT, SIGTERM).
  • Use TCSAFLUSH when switching to raw mode to discard any buffered input from canonical mode.
  • Set VMIN/VTIME deliberately — document which of the four noncanonical behaviors you intend.
  • Test that isatty(fd) returns true before calling tcgetattr — pipes and redirections are not terminals.
  • For pty-based tools, handle SIGWINCH to propagate terminal resize events from master to slave.
