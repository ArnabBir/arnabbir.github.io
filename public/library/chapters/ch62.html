    TOPIC 62 / 64 · Terminals

    Terminal input is a configurable protocol

    A read waits for a newline even though a user has already typed several characters.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    The terminal line discipline can edit input, echo characters, translate bytes, and generate signals. Canonical mode generally assembles lines. Noncanonical mode uses VMIN and VTIME to control availability and timing. A terminal is not just a pipe connected to a keyboard.

    Contract and implementation boundary

    Read current attributes with tcgetattr, change only intended fields, and use tcsetattr with an explicit timing choice. Preserve the original state for restoration. With noncanonical VMIN=0 and VTIME=0, read can return zero immediately when no input is available; this is not proof of permanent EOF.

    Contract references: termios.3 · read.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Leaving echo disabled after an error makes the user's shell confusing. Treating every zero terminal read as stream shutdown mishandles configured timing. Ctrl-D in canonical mode is a line-discipline control operation, not a byte that means the terminal device has closed.

    Worked reasoning trace

    Assumptions: Noncanonical terminal; VMIN=0, VTIME=0; no queued input.

    Tradeoff: Polling-style reads avoid waits but require an event or pacing strategy.

    Check your understanding

    Does a zero noncanonical read with VMIN=0 and VTIME=0 necessarily mean the terminal closed?

    Explain the answer

    No. It can mean no input was available for this request.
