    TOPIC 36 / 64 · Process Resources

    Resource limits are failure inputs

    An accept loop repeatedly fails because the process has no descriptor slots left.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Resource limits cap selected process resources; cgroups impose additional group-level policy. Soft and hard limits differ, and inherited limits shape helper programs. Usage counters describe accumulated work or high-water marks, not necessarily instantaneous utilization.

    Contract and implementation boundary

    getrlimit/setrlimit inspect and adjust limits under privilege rules. RLIMIT_NOFILE bounds descriptor-number allocation and can produce EMFILE. getrusage reports CPU time and other counters; ru_maxrss is a maximum, with platform-specific units. Linux reports it in kilobytes.

    Contract references: getrlimit.2 · getrusage.2 · accept.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Retrying accept immediately on EMFILE can create a hot error loop. A reserved descriptor strategy may help reject a pending connection, but admission control and leak diagnosis are still required. Raising limits without memory budgeting moves the failure elsewhere.

    Worked reasoning trace

    Assumptions: Child has a low RLIMIT_NOFILE and already-open standard descriptors.

    1. Starting state

      The numeric limit is 16.

    2. Operation

      Repeated new opens reach EMFILE before 16 additional successes.

    3. Expected observation

      Existing slots consume part of the budget.

    Tradeoff: Limits contain damage but require backpressure and error handling.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    In a child only, lower a descriptor limit to a modest bound and open /dev/null until failure, retaining handles for cleanup. Count successful opens rather than assuming the limit equals new capacity; standard and inherited descriptors already occupy slots.

    Check your understanding

    Does RLIMIT_NOFILE equal the number of additional files a process can always open?

    Explain the answer

    No. Existing descriptors and other system constraints affect available capacity.
