Chapter 57 — Sockets: UNIX Domain

UNIX domain sockets are the most versatile local IPC mechanism — bidirectional, supporting both stream and datagram semantics, and capable of passing file descriptors and credentials between processes. They bypass the network stack entirely, making them significantly faster than TCP loopback for same-host communication.

AF_UNIX sockets bind to filesystem paths or Linux abstract namespace entries. socketpair() creates a pre-connected pair ideal for parent-child communication. Ancillary data (cmsg) enables passing open file descriptors (SCM_RIGHTS) and process credentials (SCM_CREDENTIALS) out-of-band.

Invariant
AF_UNIX sockets are local-only; they use filesystem paths (or abstract names) instead of IP:port, and support fd passing via ancillary data.
Gotcha
Filesystem-bound sockets leave a socket file after close — you must unlink() it before re-binding, or use the abstract namespace to avoid cleanup.
Debugging
Use ss -x to list UNIX domain sockets; ls -l on the socket path shows socket type (s); lsof shows which processes hold each end.

Mental model

Internalize these bullets. If you can explain them clearly, you can debug most real-world incidents in this area.
  • AF_UNIX sockets bind to filesystem paths (sun_path in struct sockaddr_un) or to the Linux abstract namespace (sun_path[0] = '\0').
  • SOCK_STREAM provides connection-oriented, reliable, ordered byte streams — like TCP but purely local, with no network overhead.
  • SOCK_DGRAM provides connectionless, reliable, message-preserving datagrams — like UDP but with guaranteed delivery on the same host.
  • socketpair() creates a connected pair of sockets (like pipe() but bidirectional) — ideal for parent-child IPC after fork().
  • Ancillary data via sendmsg/recvmsg cmsg enables passing file descriptors (SCM_RIGHTS) and caller credentials (SCM_CREDENTIALS) between processes.
  • Abstract namespace sockets (Linux-specific) avoid filesystem cleanup: no unlink() needed, automatically removed when all references close.
  • No network stack overhead — AF_UNIX bypasses IP/TCP layers, making it faster than 127.0.0.1 loopback for local communication.

Edge cases & invariants

This is where production bugs live. Expand each panel and treat the bullets as test cases.
Socket file lifecycle and binding
  • bind() creates a socket file in the filesystem. If the path already exists, bind fails with EADDRINUSE — you must unlink() the stale socket file first.
  • Closing a socket does NOT remove the socket file. You must unlink() explicitly (or use atexit/signal handlers).
  • Abstract namespace sockets (sun_path[0] = '\0') avoid this problem entirely: no filesystem entry, automatic cleanup when all fds close.
  • sun_path is limited to 108 bytes. Long paths silently truncate on some systems — always check addrlen.
File descriptor passing with SCM_RIGHTS
  • sendmsg() with SCM_RIGHTS ancillary data duplicates the fd into the receiver's fd table — it's like the kernel calls dup() across process boundaries.
  • The receiver must allocate a msg_control buffer (use CMSG_SPACE macro) and iterate with CMSG_FIRSTHDR/CMSG_NXTHDR.
  • Received fds are new fd numbers in the receiver's process; the sender can close its copy independently.
  • If recvmsg's msg_control buffer is too small, ancillary data is silently truncated and fds are leaked into the receiver's table without being reported.
Credential passing with SCM_CREDENTIALS
  • The sender fills a struct ucred (pid, uid, gid) in the cmsg. The kernel verifies the credentials — unprivileged processes cannot forge them.
  • The receiver must enable SO_PASSCRED on its socket before credentials are delivered.
  • This is used by D-Bus, systemd, and other services for authentication over UNIX sockets.
  • Only available on Linux; BSD uses LOCAL_PEERCRED or getpeereid() instead.
SOCK_DGRAM vs SOCK_STREAM for AF_UNIX
  • SOCK_DGRAM preserves message boundaries (each send is one recv) and is reliable on AF_UNIX — no packet loss possible since there's no network.
  • SOCK_STREAM is a byte stream: message boundaries are not preserved. Use length-prefixed or delimited framing.
  • SOCK_SEQPACKET combines connection-oriented semantics with message boundaries — often the best choice for structured IPC.
  • SOCK_DGRAM senders must bind() their own address if they want to receive replies (the receiver needs a return address).

Code patterns (C / POSIX)

These are compact patterns to internalize. Treat them as starting points: add proper error handling, timeouts, and logging. 
// socketpair + fd passing via SCM_RIGHTS
#include <sys/socket.h>
#include <sys/un.h>
#include <unistd.h>
#include <string.h>
#include <stdio.h>

void send_fd(int sock, int fd_to_send) {
    char buf[1] = {'F'};
    struct iovec iov = { .iov_base = buf, .iov_len = 1 };
    char cmsgbuf[CMSG_SPACE(sizeof(int))];
    struct msghdr msg = {0};
    msg.msg_iov = &iov;  msg.msg_iovlen = 1;
    msg.msg_control = cmsgbuf;  msg.msg_controllen = sizeof(cmsgbuf);
    struct cmsghdr *cmsg = CMSG_FIRSTHDR(&msg);
    cmsg->cmsg_level = SOL_SOCKET;
    cmsg->cmsg_type  = SCM_RIGHTS;
    cmsg->cmsg_len   = CMSG_LEN(sizeof(int));
    memcpy(CMSG_DATA(cmsg), &fd_to_send, sizeof(int));
    sendmsg(sock, &msg, 0);
}
// Usage: socketpair(AF_UNIX, SOCK_STREAM|SOCK_CLOEXEC, 0, sv);
// fork(); parent sends fd via sv[0], child recvmsg on sv[1]

Production checklist

If you are shipping code in this area, try to satisfy each checklist item explicitly.
  • Always unlink() the socket path before bind(), or use abstract namespace to avoid stale socket files.
  • Use SOCK_CLOEXEC on socketpair/socket/accept to prevent fd leaks across exec().
  • When passing fds via SCM_RIGHTS, always send at least 1 byte of payload data alongside ancillary data.
  • Size msg_control with CMSG_SPACE() macro; undersized buffers silently lose ancillary data and leak fds.
  • Prefer SOCK_SEQPACKET over SOCK_STREAM when you need message boundaries with connection semantics.
