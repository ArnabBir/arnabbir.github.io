    TOPIC 57 / 64 · Sockets: UNIX Domain

    UNIX sockets can transfer authority

    A local broker passes a descriptor to a less-privileged worker.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    AF_UNIX sockets communicate locally using pathname or Linux abstract addresses, and can carry ancillary data. SCM_RIGHTS passes a reference to an open file description, not a pathname to reopen. The receiver gets its own descriptor number but shares relevant underlying state such as the offset.

    Contract and implementation boundary

    Use sendmsg/recvmsg with properly sized control buffers and CMSG macros. Check MSG_CTRUNC and close unexpected received descriptors to avoid leaks. Linux MSG_CMSG_CLOEXEC requests close-on-exec on received descriptors. Validate peer credentials and protocol authorization; locality alone is not trust.

    Contract references: unix.7 · sendmsg.2 · recvmsg.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Passing an open writable file bypasses the need for the recipient to resolve its pathname. A small payload can therefore convey substantial authority. Pathname permissions and abstract-socket visibility differ; do not assume filesystem permissions protect abstract addresses.

    Worked reasoning trace

    Assumptions: Sender passes one descriptor through SCM_RIGHTS; receiver accepts it safely.

    1. Starting state

      Sender fd 8 has offset zero.

    2. Operation

      Receiver obtains local fd 5 and reads one byte.

    3. Expected observation

      The shared description's offset advances for sender fd 8 too.

    Tradeoff: Descriptor passing avoids reopening names but transfers authority and shared state.

    Specify a broker response containing one read-only descriptor and a versioned status record. Reject responses with extra descriptors or truncated control data. Trace shared offsets after the broker and worker each read one byte.

    Check your understanding

    Does SCM_RIGHTS guarantee the same descriptor integer in sender and receiver?

    Explain the answer

    No. It transfers an open reference, with a receiver-local descriptor number.
