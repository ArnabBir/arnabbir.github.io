    TOPIC 46 / 64 · System V Message Queues

    System V queues select typed messages

    A receiver waits while the queue contains messages of another type.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Each System V message starts with a positive long type followed by application bytes. Selection by type makes the queue more than a FIFO stream. A receiver can deliberately skip older messages that do not match its selection. Capacity and selection rules jointly determine whether producers or consumers block.

    Contract and implementation boundary

    msgsnd and msgrcv take a payload size that excludes the leading long. A zero receive type selects the first message; a positive type normally selects that exact type; a negative type selects the lowest eligible type up to the absolute bound. Without MSG_NOERROR an undersized receive buffer fails with E2BIG and leaves the message queued.

    Contract references: msgop.2 · msgget.2 · msgctl.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Using sizeof(struct) as the payload size can include the type or unwanted padding. Retrying an E2BIG receive unchanged makes no progress. Sending raw pointer values cannot transfer pointed-to objects between unrelated address spaces.

    Worked reasoning trace

    Assumptions: Fresh queue contains message types 5, 2, 4 in that order.

    1. Starting state

      Receiver chooses selector -4.

    2. Operation

      Find the lowest type at most four.

    3. Expected observation

      Type 2 is received; selection is not oldest-message FIFO in this mode.

    Tradeoff: Typed selection routes work conveniently but can starve unselected types.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Trace a queue containing types 5, 2, 4. Predict receives for selectors 0, 4, and -4 on independent fresh copies. Specify a fixed-width payload encoding and reject malformed lengths before decoding.

    Check your understanding

    Does the msgsnd payload-size argument include the leading long message type?

    Explain the answer

    No. It counts only the message text bytes.
