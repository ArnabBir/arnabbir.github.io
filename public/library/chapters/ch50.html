    TOPIC 50 / 64 · Virtual Memory Operations

    Virtual-memory policy has granularity

    A program tries to protect half an object and unexpectedly affects adjacent data.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Memory protection and residency policies operate at page granularity. Virtual address space, resident pages, and locked memory are different resources. mprotect changes access permissions; madvise communicates usage advice; mlock attempts to keep pages resident subject to limits and privilege rules.

    Contract and implementation boundary

    Use the runtime page size and satisfy alignment requirements. Check every mprotect and mlock result. Advice is not generally a guarantee that a page is resident, absent, or durable. Establish memory ownership before changing permissions so another thread does not access a page during an incompatible phase.

    Contract references: mprotect.2 · madvise.2 · mlock.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    A successful mlock does not prevent all copies of secrets in other buffers or dumps. Protecting an allocator page can break unrelated allocations sharing that page. Use dedicated mappings for protection experiments.

    Worked reasoning trace

    Assumptions: 4096-byte pages; dedicated mapping begins at an aligned address.

    1. Starting state

      Two application objects occupy one page.

    2. Operation

      mprotect removes write permission from that page.

    3. Expected observation

      Both objects are affected because the page is the protection unit.

    Tradeoff: Dedicated mappings allow isolation but increase fragmentation and bookkeeping.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    Extend mappings.c locally with a read-only phase using mprotect, then restore write permission before changing the marker. Do not deliberately dereference an inaccessible page in the default lab. Explain which pages a rounded range covers.

    Check your understanding

    Can mprotect generally isolate one byte in the middle of an ordinary page?

    Explain the answer

    No. Protection is applied to page-sized regions.
