    TOPIC 11 / 64 · System Limits and Options

    Limits must be interpreted

    sysconf returns -1 and the program reports a bogus fatal error.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Limits can be compile-time minima, runtime system values, per-file values, or process resource ceilings. A standard minimum is not the current machine's capacity. Some queries permit an indeterminate limit. Resource limits and cgroup controls can both restrict a workload without being interchangeable.

    Contract and implementation boundary

    Set errno to zero before sysconf or pathconf when -1 can mean either indeterminate or error, then inspect errno only on that result. getrlimit exposes soft and hard limits; applications may generally lower their own soft limits but cannot assume authority to raise hard limits.

    Contract references: sysconf.3 · pathconf.3 · getrlimit.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Allocating a PATH_MAX-sized buffer and assuming every path fits is not a universal pathname strategy. A queried value can also change for some resource classes; correct code still handles operation failure.

    Original practice problem

    Query _SC_OPEN_MAX and RLIMIT_NOFILE, then explain why neither tells you the number of descriptors currently open. Use a child process if experimenting with a lower limit so the parent shell remains unaffected.

    Check your understanding

    sysconf returns -1 with errno still zero after you cleared it. Is this necessarily an error?

    Explain the answer

    No. For applicable queries it can report an indeterminate limit.

    Represent the limit as indeterminate, not a diagnosed syscall failure.
