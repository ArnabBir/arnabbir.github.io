Appendix D — Kernel Configuration

Kernel configuration determines which features and drivers are compiled in. Understanding /proc/config.gz and /boot/config helps debug "feature not available" errors -- when epoll_create1 returns ENOSYS or inotify_init fails, the first question is whether the kernel was built with that feature enabled.

This appendix covers the .config file format, key CONFIG_* options for systems programmers, and tools for inspecting and changing kernel configuration (make menuconfig, modprobe, lsmod).

Invariant
CONFIG_*=y means built-in; =m means loadable module; "not set" means feature is disabled entirely.
Gotcha
/proc/config.gz only exists if CONFIG_IKCONFIG_PROC=y; otherwise check /boot/config-$(uname -r).
Debugging
zcat /proc/config.gz | grep CONFIG_EPOLL instantly tells you if epoll support is compiled in.

Deep dive

Practical panels: finding config, key options for systems programmers, and module management.
Finding the running kernel's configuration
  • /proc/config.gz: the running kernel's config, compressed. Use: zcat /proc/config.gz | grep CONFIG_EPOLL.
  • /boot/config-$(uname -r): installed by most distros even when /proc/config.gz is unavailable.
  • modprobe configs: if CONFIG_IKCONFIG is set to =m, you may need to load the configs module first: modprobe configs.
  • Some embedded/minimal systems have neither; in that case, check the build system or distro's kernel package.
Key CONFIG_* options for systems programmers
  • CONFIG_EPOLL: enables epoll_create/epoll_wait. Almost always =y on modern kernels.
  • CONFIG_INOTIFY_USER: enables inotify_init/inotify_add_watch for filesystem event monitoring.
  • CONFIG_POSIX_MQUEUE: enables POSIX message queues (mq_open, mq_send, mq_receive).
  • CONFIG_NAMESPACES: master switch for Linux namespaces (PID, NET, MNT, UTS, IPC, USER, CGROUP).
  • CONFIG_CGROUPS: enables control groups for resource limiting and isolation.
  • CONFIG_SECCOMP: enables seccomp syscall filtering for sandboxing.
Module management
  • lsmod: shows loaded modules, their size, and use count. Equivalent to reading /proc/modules.
  • modprobe <name>: loads a module and its dependencies. Uses /lib/modules/$(uname -r)/ for module files.
  • modprobe -r <name>: removes a module (if use count is 0).
  • modinfo <name>: shows module metadata (description, parameters, dependencies, license).
  • /etc/modprobe.d/: configuration files for module options, blacklisting, and aliases.

Code patterns

Checking kernel config for specific features. 
# Check if epoll is compiled in (from /proc/config.gz)
zcat /proc/config.gz | grep CONFIG_EPOLL

# Check from /boot if /proc/config.gz is unavailable
grep CONFIG_INOTIFY_USER /boot/config-$(uname -r)

# Check namespace support
zcat /proc/config.gz | grep CONFIG_NAMESPACES

# Check POSIX message queue support
zcat /proc/config.gz | grep CONFIG_POSIX_MQUEUE

# List loaded modules and search for a specific one
lsmod | grep nf_tables

# Load a module and verify
sudo modprobe configs
lsmod | grep configs

# Show module info (parameters, dependencies)
modinfo ext4

Production checklist

Practices for managing kernel configuration in systems work.
  • When a syscall returns ENOSYS, check whether the feature's CONFIG_* option is enabled before debugging code.
  • Record kernel version (uname -r) and relevant CONFIG_* values in bug reports and incident postmortems.
  • For containerized deployments, remember the kernel is shared -- container config depends on the host kernel's .config.
  • Use modinfo to check module parameters before loading; some modules have security-relevant defaults.
  • Keep /boot/config-* files when building custom kernels; they are essential for reproducing builds.
