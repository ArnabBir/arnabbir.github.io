    APPENDIX D / F · Kernel Configuration

    Kernel configuration is part of the environment

    An API header exists but the running environment rejects the operation.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    Kernel release, build configuration, enabled modules, namespaces, security policy, and runtime limits all affect interface availability. A header describes what the toolchain can express; it does not prove the running kernel supports or permits the operation. Containers normally share a host kernel rather than shipping an independent one.

    Contract and implementation boundary

    Record uname output and distribution information, then inspect configuration only where exposed, such as /proc/config.gz or distribution-provided boot config files. Absence of a readable config is not proof that a feature is disabled. Test actual operations with explicit error handling and distinguish ENOSYS, EOPNOTSUPP, and permission failures.

    Contract references: uname.2 · proc.5 · seccomp.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Changing kernel parameters on a shared machine to make a tutorial pass invalidates a safe default lab. A seccomp filter can alter the observed failure, so errno alone may not identify the kernel's compile-time configuration.

    Build an environment report containing kernel release, architecture, libc version, namespace context, and the result of one harmless feature probe. Do not rebuild or reboot the kernel for this companion. List what remains unknown when configuration files are inaccessible.
