Appendix E — Further Sources of Information

Beyond TLPI -- essential resources for Linux systems programming: man pages, kernel documentation, LWN.net, kernel source, LKML archives, and key reference books. When you hit a subtle behavior that no tutorial covers, these primary sources are where the truth lives.

This appendix organizes resources by the kind of question you're answering: API semantics (man pages), kernel internals (source + docs), historical rationale (LKML), and broader systems knowledge (books).

Invariant
Man pages (sections 2, 3, 7) are the primary API reference; the kernel source is the ultimate truth.
Gotcha
Man pages can be outdated; cross-check with kernel source for recently added syscalls or changed semantics.
Debugging
man7.org mirrors the latest man-pages project; use it when your distro's pages are stale.

Deep dive

Practical panels: how to use each resource effectively.
Man pages: the first stop
  • man 2 open: syscall interface. man 3 fopen: libc wrapper. man 7 signal: conceptual overview.
  • Always read the ERRORS section -- it defines the API contract for failure modes.
  • The NOTES section contains Linux-specific behavior, glibc wrapper differences, and version history.
  • Use man -k keyword (apropos) to search for relevant pages when you don't know the exact name.
  • man7.org/linux/man-pages/ hosts the latest upstream versions; your distro may be months behind.
Kernel documentation and source
  • The kernel tree's Documentation/ directory contains subsystem guides (e.g., Documentation/filesystems/, Documentation/networking/).
  • kernel.org/doc/html/latest/ hosts rendered versions of the kernel documentation.
  • For syscall semantics, grep the kernel source: the implementation IS the specification when man pages are ambiguous.
  • tools/testing/selftests/ in the kernel tree contains test programs that demonstrate expected API behavior.
Key reference books
  • Advanced Programming in the UNIX Environment (Stevens/Rago, 3rd ed.) -- POSIX API coverage complementing TLPI.
  • UNIX Network Programming, Vol. 1 (Stevens) -- definitive reference for socket programming.
  • Linux Kernel Development (Love, 3rd ed.) -- accessible introduction to kernel internals.
  • Understanding the Linux Kernel (Bovet/Cesati) -- deep dive into kernel data structures and algorithms.
  • The Linux Programming Interface (Kerrisk) -- the book this companion is built around.

Code patterns

Useful commands for finding documentation. 
# Look up a syscall man page
man 2 epoll_wait

# Search for man pages by keyword
man -k inotify
apropos "file descriptor"

# Read the overview/concept pages (section 7)
man 7 signal
man 7 epoll
man 7 namespaces

# Browse kernel documentation online
# https://kernel.org/doc/html/latest/
# https://man7.org/linux/man-pages/

# Search kernel source for syscall implementation
grep -rn "SYSCALL_DEFINE.*epoll_create" fs/eventpoll.c

# Find kernel selftests for a subsystem
ls tools/testing/selftests/epoll/

Production checklist

Habits for staying current with Linux systems knowledge.
  • Read the man page ERRORS section for every syscall you use; it defines what can go wrong.
  • Subscribe to LWN.net for kernel development news; new syscalls and behavior changes appear there first.
  • When behavior seems undocumented, search LKML archives for the commit that added the feature.
  • Keep man-pages updated (apt install manpages-dev or equivalent); stale pages cause real bugs.
  • When in doubt, read the kernel source -- it is always the ground truth.
