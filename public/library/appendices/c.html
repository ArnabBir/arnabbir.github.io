Appendix C — Casting the NULL Pointer

NULL is defined as ((void*)0) in C, but variadic functions and old-style declarations require careful casting. The modern answer: always use (void*)NULL or explicit casts in variadic calls. On LP64, passing bare 0 where a pointer is expected can silently pass 4 bytes instead of 8.

This appendix explains when NULL casts matter, why the exec family needs (char*)NULL sentinels, and how C23's nullptr keyword finally resolves the ambiguity.

Invariant
In variadic calls, the compiler cannot promote 0 to a pointer -- you must cast explicitly.
Gotcha
On LP64, int is 4 bytes but pointers are 8. Passing plain 0 as a sentinel in execl() is undefined behavior.
Debugging
Compile with -Wsentinel (GCC/Clang) to catch missing or uncast sentinel arguments.

Deep dive

Practical panels: NULL representations, variadic dangers, and the LP64 trap.
How NULL is defined
  • The C standard says NULL is "an implementation-defined null pointer constant." It can be 0, 0L, or ((void*)0).
  • In glibc headers, NULL is typically ((void*)0) in C mode and 0L or __null in C++ mode.
  • A null pointer constant converts implicitly to any pointer type in *non-variadic* function calls and assignments.
  • The key issue: this implicit conversion does NOT happen for variadic arguments beyond the last typed parameter.
The LP64 variadic trap
  • On LP64 (x86-64 Linux), sizeof(int)==4, sizeof(void*)==8. If NULL is defined as plain 0 (an int), passing it to a variadic function pushes only 4 bytes.
  • The callee (e.g., execl) reads 8 bytes for a pointer, consuming 4 bytes of garbage from the stack. This is undefined behavior.
  • Fix: always write (char*)NULL or (char*)0 as the sentinel in execl, execlp, execle.
  • GCC's __attribute__((sentinel)) and -Wsentinel catch this at compile time when the attribute is present.
C23 nullptr and best practices
  • C23 introduces nullptr as a keyword -- a null pointer constant of type nullptr_t that converts to any pointer type.
  • Unlike 0, nullptr cannot be implicitly converted to int, eliminating the variadic ambiguity.
  • Until C23 is widely adopted, the safe pattern is: always cast the sentinel, e.g., execl("/bin/ls", "ls", "-l", (char*)NULL).
  • In C++, use nullptr (available since C++11) instead of NULL or 0 for all pointer contexts.

Code patterns

Correct sentinel usage in execl/execlp. 
/* WRONG: bare 0 on LP64 passes 4 bytes, not 8 -- undefined behavior */
execl("/bin/ls", "ls", "-l", 0);          /* BUG on LP64 */

/* WRONG: NULL may be defined as 0 (an int) on some implementations */
execl("/bin/ls", "ls", "-l", NULL);       /* risky */

/* CORRECT: explicit cast ensures pointer-width sentinel */
execl("/bin/ls", "ls", "-l", (char *)NULL);  /* always safe */
execlp("grep", "grep", "-r", "pattern", ".", (char *)NULL);

/* C23 -- when available */
execl("/bin/ls", "ls", "-l", nullptr);     /* safe in C23 */

/* Compile-time detection (GCC/Clang) */
/* gcc -Wsentinel warns if sentinel attribute is missing cast */

Production checklist

Rules for safe NULL usage in systems code.
  • Always cast NULL to the expected pointer type in variadic function calls: (char*)NULL, (void*)NULL, etc.
  • Enable -Wsentinel and -Wall -Wextra to catch uncast sentinels at compile time.
  • Use __attribute__((sentinel)) on your own variadic functions that expect a NULL terminator.
  • In C++, use nullptr universally; in C23+, use nullptr; in older C, use (type*)NULL.
  • Be aware that mmap failure returns MAP_FAILED ((void*)-1), not NULL -- different sentinel values for different APIs.
