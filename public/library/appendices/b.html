Appendix B — Parsing Command-Line Options

getopt and getopt_long parse command-line arguments following POSIX conventions -- short options (-v), long options (--verbose), option arguments, and the -- separator. They handle the fiddly details of argv iteration so you don't have to.

This appendix covers the getopt API family, the optstring format, the struct option array for long options, and the global variables (optarg, optind, opterr) that control parsing state.

Invariant
getopt() iterates over argc/argv; after parsing, argv[optind] is the first positional argument.
Gotcha
optarg, optind, opterr are globals -- not thread-safe. Reset optind=1 before re-parsing.
Debugging
Set POSIXLY_CORRECT to disable GNU argv permutation; -- always terminates option parsing.

Deep dive

Practical panels: getopt mechanics, long options, and common mistakes.
getopt() mechanics
  • Call getopt(argc, argv, optstring) in a loop until it returns -1. Each call returns one option character.
  • optstring "vo:h" means: -v (no arg), -o (requires arg), -h (no arg). Double colon :: means optional arg (GNU extension).
  • Leading ':' in optstring (":" prefix) changes error handling: getopt returns ':' for missing arg instead of '?'.
  • After the loop, argv[optind] through argv[argc-1] are the remaining positional arguments.
  • GNU getopt permutes argv so options can appear after positional args. POSIXLY_CORRECT disables this.
getopt_long() and struct option
  • getopt_long(argc, argv, optstring, longopts, &longindex) adds --long-option support.
  • struct option: {.name="verbose", .has_arg=no_argument, .flag=NULL, .val='v'} maps --verbose to 'v'.
  • has_arg values: no_argument (0), required_argument (1), optional_argument (2).
  • If .flag is non-NULL, getopt_long sets *flag=val and returns 0 instead of val. Useful for boolean flags.
  • longindex (if non-NULL) receives the index into longopts of the matched option.
Common pitfalls
  • Forgetting to reset optind=1 when parsing argv multiple times (e.g., in test harnesses).
  • Mixing option parsing with side effects (opening files during parse) -- parse first, act second.
  • Not handling '?' (unknown option) or ':' (missing argument) in the switch default.
  • Assuming argv strings are trusted input; for setuid programs, treat argv/envp as attacker-controlled.

Code patterns

Complete getopt_long example with short and long options. 
#include <getopt.h>
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv) {
    int verbose = 0, dry_run = 0;
    const char *output = NULL;

    static struct option long_opts[] = {
        {"verbose",  no_argument,       NULL, 'v'},
        {"output",   required_argument, NULL, 'o'},
        {"dry-run",  no_argument,       NULL, 'n'},
        {"help",     no_argument,       NULL, 'h'},
        {0, 0, 0, 0}
    };

    int c;
    while ((c = getopt_long(argc, argv, "vo:nh", long_opts, NULL)) != -1) {
        switch (c) {
            case 'v': verbose++;       break;
            case 'o': output = optarg; break;
            case 'n': dry_run = 1;     break;
            case 'h':
                fprintf(stderr, "usage: %s [-v] [-n] [-o FILE] [--] args...\n", argv[0]);
                return 0;
            default:
                fprintf(stderr, "Try '%s --help'\n", argv[0]);
                return 2;
        }
    }

    /* Positional arguments: argv[optind] .. argv[argc-1] */
    for (int i = optind; i < argc; i++)
        printf("positional: %s\n", argv[i]);

    if (verbose)  printf("verbose level: %d\n", verbose);
    if (output)   printf("output file: %s\n", output);
    if (dry_run)  printf("dry-run mode\n");
    return 0;
}

Production checklist

Best practices for robust CLI parsing.
  • Parse all options first, then validate constraints (e.g., mutually exclusive flags) before performing any work.
  • Always handle the default/? case in switch to catch unrecognized options and print usage.
  • Support -- to let users pass positional args that start with '-' (e.g., filenames like -myfile).
  • Document every option in --help output; keep short and long names consistent.
  • For setuid/setgid programs, treat argv and envp as untrusted attacker input.
