Appendix F — Solutions to Selected Exercises

Solution patterns for selected exercises -- not complete answers, but the key insights and approaches. The real learning is in implementing and debugging. Every exercise answer shares a common shape: check every return value, handle EINTR, test edge cases, and verify with strace.

This appendix provides reusable code patterns (write_all, error wrappers, EINTR retry loops) and a methodology for approaching systems exercises: implement first, then compare; measure before optimizing; code defensively.

Invariant
Check every return value. An unchecked syscall failure is a latent bug waiting for production.
Gotcha
Assuming happy-path semantics: read() can return short, write() can return short, signals can interrupt anything.
Debugging
Use strace to verify your implementation matches expectations; use ulimit to test resource exhaustion paths.

Deep dive

Practical panels: solution methodology, common patterns, and testing strategies.
Solution methodology
  • Implement first, then compare with reference solutions. The learning is in the struggle, not the answer.
  • Start with the simplest correct version -- no optimizations, no clever tricks. Get it right, then make it fast.
  • Focus on error handling and edge cases: what happens on EOF? On EINTR? On EAGAIN? On disk full?
  • Use strace to verify that your syscall sequences match expectations. Unexpected syscalls reveal bugs.
  • Measure before optimizing: use time, perf stat, or strace -c to find actual bottlenecks.
The write_all pattern
  • write() can return fewer bytes than requested (short write), especially on pipes, sockets, and nonblocking fds.
  • write_all() loops until all bytes are written, handling EINTR (retry) and short writes (advance buffer pointer).
  • This pattern is so common it should be a utility function in every systems project.
  • The same pattern applies to read: read_all() loops until the buffer is full or EOF is reached.
Testing strategies
  • Use ulimit -n 10 to force fd exhaustion and test EMFILE handling.
  • Send signals during blocking operations: kill -USR1 <pid> to trigger EINTR paths.
  • Use strace -e fault=write:error=ENOSPC to simulate disk-full conditions without filling a disk.
  • Write deterministic test cases: fixed input, expected output, compare with diff.
  • Test with /dev/full (always returns ENOSPC on write) and /dev/zero (infinite zeros on read).

Code patterns

Common patterns used in solutions: write_all and error wrapper. 
/* write_all: handle short writes and EINTR */
ssize_t write_all(int fd, const void *buf, size_t len) {
    const char *p = buf;
    while (len > 0) {
        ssize_t n = write(fd, p, len);
        if (n > 0)          { p += n; len -= n; continue; }
        if (errno == EINTR)  { continue; }
        return -1;  /* real error */
    }
    return p - (const char *)buf;
}

/* err_exit: print context + errno message and exit */
void err_exit(const char *msg) {
    perror(msg);
    exit(EXIT_FAILURE);
}

/* Usage in exercise solutions */
int fd = open(path, O_WRONLY | O_CREAT | O_TRUNC | O_CLOEXEC, 0644);
if (fd == -1) err_exit("open");
if (write_all(fd, data, data_len) == -1) err_exit("write");
if (close(fd) == -1) err_exit("close");

Production checklist

Discipline that separates correct solutions from fragile ones.
  • Check every return value -- read, write, close, dup2, fork, exec. No exceptions.
  • Handle EINTR in every blocking syscall with a retry loop.
  • Use write_all/read_all wrappers for all bulk I/O to handle short transfers.
  • Test with resource limits (ulimit), signal injection (kill), and fault injection (strace -e fault=).
  • Verify with strace -f -tt -T that syscall sequences match your mental model.
