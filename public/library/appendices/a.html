    APPENDIX A / F · Tracing System Calls

    Trace evidence without inventing causes

    A slow read appears in strace, and a report blames the kernel's call stack.

    ConceptAPI contractWorked tracePracticeSources

    The underlying idea

    strace observes system-call boundaries and signals using tracing facilities. Duration includes waiting and scheduling effects; it does not directly decompose CPU time inside the kernel. Tracing perturbs execution and can expose sensitive arguments. A useful investigation correlates a bounded trace with an application hypothesis.

    Contract and implementation boundary

    Use -f to follow children, -tt for timestamps, and -T for syscall duration. Filter the syscall set to the question. strace -k requests user-space stack traces where supported, not kernel stack traces. Kernel stack investigation requires appropriate kernel tracing or profiling tools and permissions.

    Contract references: strace.1 · ptrace.2. Check the documented return convention and platform notes before using an interface.

    Where reasoning goes wrong

    Summing syscall elapsed durations across concurrent threads can exceed wall time. A failed open can be an intentional search probe rather than the incident's cause. Truncated arguments and unfinished/resumed lines require careful interpretation.

    Worked reasoning trace

    Assumptions: Two threads block concurrently for about one second each.

    1. Starting state

      strace reports one second elapsed for each blocking syscall.

    2. Operation

      Add the syscall durations.

    3. Expected observation

      Two seconds of summed wait does not imply two seconds of wall time or kernel CPU.

    Tradeoff: Tracing exposes boundaries but perturbs timing and does not establish causality alone.

    This is a hand-authored prediction, not captured runtime output.

    Original practice problem

    On Linux run strace -f -e trace=process,read,write ./processes on this companion's own lab. Predict fork/clone-family creation, child termination, and waiting before reading the trace. Record unavailable tracing permissions rather than claiming an absent event never happened.
