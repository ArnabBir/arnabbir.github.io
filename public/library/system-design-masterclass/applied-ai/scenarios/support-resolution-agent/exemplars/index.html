    Five Scored Exemplars¶

    Practice home | Rubric

    These excerpts represent 60-minute evidence. Scores follow dimensions A-J and apply caps after arithmetic.

    Scores below use only the visible excerpts under the 60-minute rubric, not imagined complete artifacts. The headings retain old anchors and may name an aspiration above the earned level. In exemplar 5, 84/day and 3,360/day bound the expected unknown count under an execution fraction at most one, not realized incident maxima. The $1.008M/day is nominal requested value at the supplied mean, not a hard risk ceiling. Scores are repository-specific reviewer judgments, not externally validated hiring cutoffs.

    Exemplar 1: Unsafe autonomous chatbot¶

    Put account history and policy documents in the prompt. The model chooses whether to call refund(amount, account) and retries failures. Redis remembers completed calls. Confidence below 0.7 goes to a human. Track containment and response latency.

    Annotation¶

    Evidence Consequence
    Model directly chooses unrestricted effect No deterministic authority; 17-point cap
    Generic retry after failure Can duplicate an ambiguous refund
    Transcript/Redis as state No durable resumable workflow
    Confidence controls escalation Confidence is neither risk nor policy
    Only containment and latency Hides customer harm and financial loss

    Score: A0 B0 C0 D0 E0 F0 G1 H0 I0 J0 = 1/40. Final: 1/40, below target.

    Exemplar 2: Useful happy path¶

    A classifier picks intent, RAG supplies answers, and a rules service checks $50. A workflow calls billing with an idempotency key and sends a response. High-risk cases go to billing review. We log prompts and tool calls and test answer quality before launch.

    Annotation¶

    It introduces rules, idempotency, retrieval, and a human route. It does not define request-hash conflicts, cumulative reservation, durable step state, unknown outcomes, indirect injection, queue lifecycle, privacy-safe audit, or business counter-metrics.

    Score: A2 B0 C1 D1 E0 F1 G1 H1 I1 J0 = 8/40. No workload calculation or migration is stated. An unsafe timeout retry or unreserved amount check triggers the 17 cap, but arithmetic is lower. Final: 8/40, below target.

    Exemplar 3: Borderline L5¶

    This is a borderline-L5 aspiration, not the scored result: the visible evidence below earns 17/40, below target. The heading is retained for existing links.

    The model produces a structured ResolutionProposal; deterministic policy code reloads the account, applies regional policy, checks amount and risk, and either creates an approval or a refund command. Commands have stable idempotency keys. A relational case record stores status and an outbox emits events. Customer and retrieved text are delimited as data; only approved sources are searched. Tool parameters are schema validated.

    A billing timeout moves the case to pending and a worker queries later. Humans see account, policy, citations, and proposed action. We measure unsafe actions, containment, latency, and reviewer overrides.

    Annotation¶

    The authority line and tool boundary are sound. pending lacks explicit unknown evidence precedence and reservation lifetime. It omits request-hash conflict, compensation, queue leases/expiry, indirect injection controls beyond delimiting, capacity arithmetic, recovery headroom, event consumer semantics, and migration.

    Score: A3 B0 C2 D2 E2 F2 G2 H2 I2 J0 = 17/40. The missing atomic reservation also invokes the 17 cap. Versioned step state, payload conflict, quantitative capacity and migration cannot be inferred from a relational case record and an outbox. Final: 17/40, below target.

    Exemplar 4: Strong L5¶

    ResolutionCase is canonical; workflow version and step attempts make resume deterministic. The model can classify, retrieve, rank evidence, and draft, but cannot set eligibility, amount, risk, approval, identity, or final state. The gateway reloads case version 17, policy 43, risk reasons, charge currency, and available limit. In one transaction it reserves 2,400 minor units, inserts cmd_7 with a stable key and request hash, advances to EXECUTING, and writes an outbox event. The adapter returns the stored response for same-key/same-hash and rejects a changed payload.

    A timeout advances to OUTCOME_UNKNOWN; it retains reservation and the customer sees "still verifying," never "failed." Callback and resolver observations race through a conditional transition. A proved rejection releases capacity; an applied refund resolves the case. A conflict or 30-minute age creates one deduplicated BILLING_REVIEW task. Ticket mutations use inverse commands where valid; messages get corrections; refunds are never described as rolled back.

    Approved sources are versioned and cited, yet still treated as untrusted data. Retrieval is account scoped; model context excludes credentials and cross-account identifiers. The gateway uses fixed schemas, short-lived capability tokens, output validation, and deny-by-default egress. Offline suites cover claim support, policy agreement, tool simulation, direct/indirect injection, languages, amount bands, and missed escalation. Production alerts include oldest unknown, reconciliation value mismatch, approval p95 age, unsafe-action rate, repeat contact, and outbox age.

    Annotation¶

    This is independently safe and operable. It does not quantify supplied workload, size resolver recovery, define regional fencing, or give migration and organizational gates.

    Score: A4 B0 C4 D4 E4 F3 G3 H3 I3 J0 = 28/40 raw. The 60-minute migration/leadership cap is 32 and cannot raise 28. Capacity calculations and migration are absent; grounding, human-queue and evaluation policy are coherent but not fully quantified. Final: 28/40, strong L5.

    Exemplar 5: Strong L6¶

    I bound autonomy as a financial control, not a model feature. At peak-day volume, 210,000 conversations are eligible and 42,000 request refunds, giving nominal requested value of $1.008M/day at the supplied mean, before denials. If every request made one Billing call, expected ambiguity would be 84/day normally and 3,360/day during an 8% incident; actual forecasts multiply by the measured request-to-call rate. These expectations are not worst-case reserve requirements. If unknowns arrive at 6/s while isolated resolvers complete 2/s for 20 minutes, backlog grows by 4,800; at 8/s with 2/s continuing arrivals it drains in 800 seconds. Refund admission reserves resolver and human-review capacity, and the kill switch stops new autonomous commands without stopping reconciliation.

    The model produces a typed proposal from minimum account context and versioned evidence. Deterministic workflow owns transitions; policy/risk owns eligibility; billing owns refund truth; humans own exceptions. The command transaction binds case version, policy decision, approval, amount/currency, stable operation ID, request hash, reservation, and outbox. Unknown is durable. Evidence precedence is authenticated callback or query corroborated by billing ledger; disagreement quarantines. Home-region epoch fences stale command writers; replicas serve marked-stale reads.

    We shadow on historical and live holdback traffic, then enable answer drafting, ticket tags, approved low-risk mutations, and finally refunds in $5/$20/$50 cohorts. Gates include zero duplicate or over-limit effects, injection attack success below the approved bound with no canary-secret leak, policy agreement lower confidence bound above target, unknown age within budget, reviewer override, seven-day repeat contact, complaints, and autonomous loss. Rollback records workflow generation, disables new authority, preserves valid commands, drains unknowns, and routes cases to humans. Support owns policy outcomes, Billing owns command truth/reconciliation, AI Platform owns model/retrieval evaluation, Security owns adversarial gates, and SRE owns workflow availability. A risk council sets daily autonomous-value and loss budgets.

    Start with a partitioned relational workflow/outbox boundary. Split retrieval independently now because it has no action authority. Split audit cold storage when retention cost dominates; split command execution only after measured write isolation or team ownership requires it, preserving stable contracts and pending states. Reject free-form tools and active-active refund writes; reverse only if a certified typed adapter exists or a globally fenced single-command owner is proven under game day.

    Annotation¶

    The response combines exact capacity, bounded autonomy, authoritative contracts, incident containment, human operations, security evaluation, migration, and named decision rights. It explains reversibility rather than adding distributed components for appearance.

    Score: A4 B4 C4 D4 E4 F3 G3 H4 I3 J4 = 37/40. Grounding, reviewer staffing/leases and evaluation-set/judge details still have room for deeper evidence; the explicit risk, failure, migration and ownership mechanisms establish L6. Final: 37/40, strong L6.
