    Multimodal Document Pipelines¶

    A document is not a string. It may contain born-digital text, scanned pages, reading order, tables, formulas, charts, photographs, annotations, audio, and timing. A production pipeline preserves these modalities and their relationships while producing searchable, replayable, and citation-safe derivatives.

    Evidence vocabulary¶

    • [Source] is supported by a dated source in Sources.
    • [Derived] follows from stated inputs.
    • [Design] is a recommended production contract.
    • [Measure] requires local validation by media type, language, and quality slice.

    Design target¶

    Assume a compliance corpus containing PDFs, scans, spreadsheets, slide decks, images, meeting recordings, and transcripts. Users search and ask questions across all content. Answers must cite a page region or audio time range, preserve ACLs, and be reproducible after parser upgrades.

    Invariants¶

    1. Raw source bytes are immutable and content-addressed.
    2. Every derivative names its source version, parent artifact, transformation, implementation version, parameters, and output digest.
    3. OCR never silently replaces extractable born-digital text.
    4. Reading order, geometry, table structure, image references, and audio timing remain available after text extraction.
    5. A citation resolves against the exact immutable rendition used to create it.
    6. Reprocessing creates a new pipeline run and derivative set; it does not mutate prior evidence.
    7. Partial pages and modality-specific failures are explicit, queryable states.
    8. ACL, retention, legal hold, and deletion propagate to every derivative and cache.
    9. Replay performs no external side effect except writing idempotently named derivatives.

    Architecture¶

    flowchart LR
    I[Source intake] --> B[(Immutable blob store)]
    I --> M[Malware and format checks]
    M --> D[Document classifier]
    D --> T[Native text extraction]
    D --> O[OCR and handwriting path]
    D --> L[Layout analysis]
    D --> A[Audio extraction and ASR]
    D --> V[Image and chart analysis]
    T --> G[Document graph]
    O --> G
    L --> G
    A --> G
    V --> G
    G --> C[Modality-aware chunking]
    C --> X[Search and RAG indexes]
    G --> P[(Lineage catalog)]
    X --> P

    The document graph is the canonical derived representation. Plain text is one projection. Search chunks, thumbnails, table rows, image captions, and transcripts derive from graph nodes and keep stable source anchors.

    Intake and classification¶

    Do not trust filename extensions or caller-provided MIME types. Detect format from bytes, reject unsupported encryption or corruption explicitly, bound archive expansion, scan for malware, and isolate parsers from network and host credentials.

    Classify each page or stream before choosing extraction:

    Input condition Primary path Secondary path
    born-digital text with valid glyph mapping native extraction OCR sampled for discrepancy checks
    image-only scan OCR layout and image segmentation
    mixed scan plus text layer compare native text and OCR select by region with provenance
    table-heavy page layout plus table structure OCR cells if needed
    image/chart-heavy page image region extraction OCR labels and optional description
    recording audio decode plus ASR diarization and alignment if policy permits

    [Measure] No parser is universally best. Route by measured quality and failure rate on representative document slices, not by format name alone.

    Canonical document graph¶

    {
  "document_id": "contract-184",
  "source_version": "sha256:raw-bytes",
  "rendition_id": "render-7",
  "pages": [
    {
      "page_id": "p-12",
      "width": 612.0,
      "height": 792.0,
      "coordinate_space": "PDF_POINTS_TOP_LEFT",
      "nodes": [
        {
          "node_id": "n-440",
          "kind": "PARAGRAPH",
          "bbox": [72.0, 124.0, 540.0, 188.0],
          "reading_order": 17,
          "text": "Payment is due within 30 days.",
          "text_digest": "sha256:...",
          "confidence": 0.992,
          "derived_by": "native-extractor-5.1"
        },
        {
          "node_id": "n-441",
          "kind": "TABLE",
          "bbox": [72.0, 220.0, 540.0, 410.0],
          "table_ref": "table-9",
          "derived_by": "table-parser-3.4"
        }
      ]
    }
  ]
}

    The coordinate convention and rendition are part of the contract. A bounding box without coordinate space, page dimensions, and rotation cannot be reproduced reliably. Preserve parser confidence as a signal, not proof of correctness.

    PDF_POINTS_TOP_LEFT is this application's normalized coordinate convention, not a claim about native PDF user space. Persist crop box, rotation, scale, origin and the invertible raw-to-rendition transform. Test a rotated/cropped page round trip; matching numeric boxes across two coordinate systems does not establish a correct citation.

    OCR and reading order¶

    OCR has distinct stages: image normalization, orientation detection, region detection, line recognition, language selection, confidence estimation, and post-processing. Store stage outcomes so a low-quality page is not confused with a missing page.

    OCR policy¶

    1. Render a deterministic page image from the immutable source using a versioned renderer and DPI.
    2. Detect rotation and deskew within bounded parameters; retain the transform matrix.
    3. Detect text regions and reading order.
    4. Recognize text using declared language packs and model versions.
    5. Preserve token or line geometry and confidence.
    6. Compare with native text where both exist; do not concatenate duplicates.
    7. Normalize Unicode for indexing while retaining original recognized text and mappings.
    8. Quarantine pages below quality thresholds for high-risk use cases.

    [Source] Tesseract documentation describes an OCR engine and page-segmentation modes, but using it does not establish correctness for a corpus. [Measure] Evaluate character error rate and word error rate by language, scan source, font, rotation, handwriting, and compression.

    Reading order¶

    Text extraction that sorts only by y then x fails on columns, sidebars, headers, footnotes, and floating figures. Model reading order as edges:

    Node(id, page, kind, bbox, content_ref)
Edge(from_node, to_node, relation)
relation in {NEXT, CONTAINS, CAPTION_OF, FOOTNOTE_OF, LABELS, CONTINUES_ON}

    Cycles in NEXT are invalid. Repeated headers and footers can be marked boilerplate but remain addressable. Human-visible citations should prefer page and region, not an unstable chunk number.

    Tables¶

    A table is structure, not lines of tab-separated OCR text. Preserve cells, spans, headers, row groups, footnotes, and coordinates.

    {
  "table_id": "table-9",
  "page_id": "p-12",
  "bbox": [72.0, 220.0, 540.0, 410.0],
  "rows": 3,
  "columns": 4,
  "cells": [
    {"cell_id": "c1", "row": 0, "column": 0, "row_span": 1, "column_span": 2, "role": "COLUMN_HEADER", "text": "Service"},
    {"cell_id": "c2", "row": 1, "column": 0, "row_span": 1, "column_span": 1, "role": "DATA", "text": "Storage"}
  ],
  "parser_version": "table-parser-3.4",
  "confidence": 0.94
}

    Index at multiple granularities: table summary, header-qualified rows, and selected cells. Include header context when chunking a row. Never present a computed answer from cells without citing the table region and preserving units, footnotes, and effective date.

    Evaluate table detection, structure recognition, cell text, header association, and downstream question answering separately. [Source] Table Transformer applies object detection to table detection and structure recognition; it does not define a complete production lineage or citation contract.

    [Primary implementation, verified 2026-09-08] The Table Transformer repository explicitly requires separate OCR or native text extraction to populate HTML/CSV text. Detecting correct cells is not recognizing their contents. Tesseract's quality guidance also calls out table segmentation limitations; parser confidence and table AP cannot substitute for cell-value and header-association tests.

    Images, charts, and diagrams¶

    Extract image regions and retain their page geometry, surrounding text, captions, alt text, and object digest. Do not generate a description when the image is decorative or when policy forbids external model processing.

    flowchart TD
    R[Image region] --> C{Caption available?}
    C -->|Yes| L[Link caption and nearby references]
    C -->|No| D{Description permitted and useful?}
    D -->|No| K[Keep searchable metadata only]
    D -->|Yes| G[Generate bounded description]
    G --> V[Validate labels numbers and uncertainty]
    L --> X[Image-aware index record]
    K --> X
    V --> X

    Generated image descriptions are derived interpretations. Label model and prompt versions and do not treat them as source truth. Charts require special handling: OCR axis labels and legends, retain the image, and avoid asserting exact values unless extraction can be verified. A visual question may need the original crop sent to a multimodal model under the same ACL and data policy.

    Audio and speech¶

    Audio processing can include demultiplexing, channel selection, voice activity detection, speech recognition, timestamp alignment, speaker segmentation, and optional speaker identification. Each step has a different privacy and accuracy profile.

    {
  "segment_id": "meeting-9:s-188",
  "source_version": "sha256:audio-bytes",
  "start_ms": 81240,
  "end_ms": 87910,
  "channel": 0,
  "speaker_label": "SPEAKER_02",
  "speaker_identity": null,
  "text": "The migration begins on Monday.",
  "words": [
    {"text": "migration", "start_ms": 82610, "end_ms": 83120, "confidence": 0.91}
  ],
  "asr_model": "asr-6",
  "alignment_version": "align-2"
}

    [Source] Whisper reports multilingual speech-recognition and translation experiments using large-scale weak supervision. This supports the ASR model family, not a claim about local word-error rate or timestamp quality.

    Treat diarization labels as session-local unless an independently authorized identity system maps them. Voice biometrics and speaker identification introduce additional consent and biometric-data obligations. Redaction must affect audio clips, transcripts, embeddings, search caches, and replay artifacts.

    Modality-aware chunking¶

    Do not flatten first and chunk later. Construct chunks from graph boundaries:

    function build_chunks(document_graph, max_tokens):
    for section in document_graph.sections_in_reading_order:
        units = paragraphs + header_qualified_table_rows + captions + transcript_segments
        pack adjacent compatible units until max_tokens
        never split a table cell or detach a caption from its figure reference
        emit chunk with node_ids, source anchors, modality, ACL, and digest

    Define an oversized-unit branch: a single cell or transcript segment can exceed max_tokens. Preserve the full unit as an addressable artifact, then use explicitly linked subspans with repeated header context, a validated extract, or quarantine/abstention. Do not violate the hard token bound to preserve an indivisible unit or retry packing forever.

    Use overlap only when a boundary loses required context. For 800-token chunks with 200-token overlap, long-document duplication is approximately:

    stride = 800 - 200 = 600 tokens
duplication factor = 800 / 600 = 1.333
overhead = 33.3%

    [Derived] That overhead multiplies embedding work and index storage before metadata and index structures. See the calculations workbook.

    Lineage and replay¶

    flowchart LR
    E0[Raw entity sha256 A] -->|render v7| E1[Page image sha256 B]
    E1 -->|OCR v12| E2[Text nodes sha256 C]
    E1 -->|layout v4| E3[Geometry graph sha256 D]
    E2 -->|merge v6| E4[Document graph sha256 E]
    E3 -->|merge v6| E4
    E4 -->|chunk v9| E5[Chunks sha256 F]
    E5 -->|embed v3| E6[Index records epoch 42]

    [Source] W3C PROV defines entities, activities, agents, derivation, generation, usage, and invalidation for interoperable provenance. [Design] The schema below specializes those ideas for deterministic document processing.

    {
  "run_id": "run-01H...",
  "stage": "OCR",
  "attempt": 2,
  "input_artifacts": [{"id": "page-image-12", "digest": "sha256:B"}],
  "implementation": {"name": "ocr-worker", "version": "12.3.0", "model_digest": "sha256:M"},
  "parameters_digest": "sha256:P",
  "environment_digest": "sha256:E",
  "started_at": "2026-09-06T12:00:00Z",
  "ended_at": "2026-09-06T12:00:04Z",
  "status": "SUCCEEDED",
  "outputs": [{"id": "text-nodes-12", "digest": "sha256:C"}],
  "metrics": {"pages": 1, "regions": 31, "mean_confidence": 0.93}
}

    Replay selects immutable input digests and an explicit pipeline bundle. It writes to a new run namespace, compares output digests and semantic metrics, and never overwrites the active graph. Bitwise reproduction may fail across nondeterministic accelerator kernels or libraries; record environment and compare declared semantic invariants instead of claiming universal bitwise determinism.

    Pipeline API¶

    POST /v1/document-runs
Idempotency-Key: doc:contract-184:sha256-raw:pipeline-12
Content-Type: application/json

{
  "source_id": "contract-184",
  "source_version": "sha256:raw-bytes",
  "pipeline_bundle": "pipeline-12",
  "purpose": "INDEX_BUILD",
  "tenant_id": "tenant-7"
}

    {
  "run_id": "run-01H...",
  "state": "QUEUED",
  "input_digest": "sha256:raw-bytes",
  "pipeline_bundle": "pipeline-12",
  "status_url": "/v1/document-runs/run-01H..."
}

    The status response reports every stage as PENDING, RUNNING, SUCCEEDED, PARTIAL, QUARANTINED, FAILED_RETRYABLE, FAILED_FINAL, or SKIPPED_BY_POLICY. Page-level errors are arrays, not one free-text message.

    Capacity calculation¶

    Suppose intake is 500,000 pages/day, 35% require OCR, OCR sustains 2.5 pages/s per worker at target DPI, and the design reserves 40% capacity for bursts and worker loss:

    OCR pages/day = 500,000 * 0.35 = 175,000
mean OCR demand = 175,000 / 86,400 = 2.03 pages/s
usable worker throughput = 2.5 * (1 - 0.40) = 1.5 pages/s
minimum workers = ceil(2.03 / 1.5) = 2

    [Derived] Two workers cover only the stated daily mean with reserve. Peak-hour arrival, long-tail pages, retries, language-model routing, and zone redundancy may require more. If 60% arrives in an 8-hour window, peak-window demand is 105,000 / 28,800 = 3.65 pages/s, requiring ceil(3.65 / 1.5) = 3 workers before N+1 policy.

    Storage example for 500,000 pages/day with a 250 KB normalized page image and 40 KB graph/text derivative:

    daily derivative bytes = 500,000 * 290 KB = 145 GB decimal
30-day hot derivatives = 4.35 TB decimal before replicas and indexes

    Measure actual distributions. High-resolution images and audio dominate averages quickly.

    Quality evaluation¶

    Layer Metric or test Important slices
    format detection correct route and rejection reason mislabeled, encrypted, malformed
    native extraction text coverage and order fonts, ligatures, columns
    OCR CER, WER, region recall language, scan age, rotation, handwriting
    layout region precision/recall, reading-order accuracy columns, sidebars, footnotes
    table detection, structure, cell text, header links merged cells, borderless tables
    image region/caption linkage and grounded description charts, screenshots, decorative art
    audio WER, timing error, diarization error where applicable noise, overlap, accents, channels
    lineage anchor resolution and digest verification every parser and replay version
    retrieval Recall@K by modality table, image, transcript, paragraph
    citation exact page/region/time support parser-version and rendition changes

    Do not average away a safety-critical modality. A pipeline can have excellent paragraph OCR and unusable table numbers. Freeze representative files with rights and privacy controls, expected structures, and adjudication history.

    Observability and failures¶

    Monitor bytes and pages discovered, stage queue age, worker saturation, per-format latency, retry amplification, zero-output success, confidence distributions, graph validation errors, duplicate artifacts, quarantine age, source-to-index lag, lineage resolution failures, replay divergence, deletion backlog, and cost per page/minute.

    Failure Evidence and discriminator Recovery
    parser returns empty success nonempty bytes, zero nodes, no explicit empty classification quarantine and retry with known-good parser
    OCR duplicates native text overlapping geometry and near-identical strings from two paths region-level source selection and deduplication
    reading order corrupt correct tokens but invalid sequence against labeled pages rollback layout/ordering stage
    table flattened incorrectly cell text exists but header associations fail retain table image and reprocess structure
    citation box drifts citation rendition differs from active viewer rendition render immutable cited rendition
    audio timestamps shift transcript text stable but alignment version changed retain old timed segments and migrate citations
    replay changes output same inputs, different implementation/environment digest compare declared invariants; do not overwrite
    delete misses thumbnails lineage inventory contains live derivatives after tombstone deny immediately, then purge and verify graph closure

    Practice provenance-safe ingestion in Lab 06.

    Security and privacy¶

    • Sandbox native parsers, OCR, codecs, and archive extraction with CPU, memory, file, and wall-time limits.
    • Disable parser network egress unless a narrowly scoped stage requires it.
    • Reject path traversal, active content, decompression bombs, oversized dimensions, and unsupported encryption.
    • Treat recognized text, image descriptions, and transcripts as untrusted input to downstream models.
    • Keep raw content and credentials out of general logs; store digests and protected evidence references.
    • Enforce source ACL during derivative reads, indexing, retrieval, replay, and operator debugging.
    • Classify biometric, health, financial, and secret content before external processing.
    • Bind temporary model-provider access to approved data classes and retention contracts.
    • Apply redaction and deletion to every node reachable in the lineage graph.

    Migration strategy¶

    1. Freeze the old pipeline bundle and representative evaluation corpus.
    2. Run the new parser or model into a separate derivative namespace.
    3. Validate graph schema, counts, geometry, lineage closure, ACLs, deletion, and quality slices.
    4. Build a new search epoch from only the new graph manifest.
    5. Shadow retrieval and citation resolution; compare source spans, not unstable chunk IDs.
    6. Canary by document class and tenant risk.
    7. Atomically activate the compatible document-graph and index epoch.
    8. Retain old renditions for citation stability and rollback under retention policy.
    9. Repoint or migrate citations only through an explicit verified mapping.
    10. Purge old derivatives after rollback, legal, and reproducibility windows close.

    Interview exercise¶

    Design ingestion for 10 million historical insurance documents plus 20,000 hours of call audio per month. PDFs mix native text, scans, handwriting, tables, and photographs. Investigators need page-region and audio-time citations. The organization upgrades OCR quarterly and must delete a customer's data across all derivatives.

    Explain classification, OCR/native arbitration, layout and table models, image and audio treatment, document graph, chunking, lineage, replay, capacity, security, evaluation, migration, and deletion proof.

    L5 and L6 signals¶

    L5¶

    • Models documents as structured multimodal graphs instead of flattened text.
    • Preserves coordinates, reading order, cell structure, timestamps, and immutable source anchors.
    • Computes OCR throughput or derivative storage with explicit assumptions.
    • Separates quality metrics by stage and modality.
    • Makes partial extraction and zero-output failures observable.
    • Replays into new immutable namespaces and migrates citation-safe epochs.

    L6¶

    • Establishes cross-team schemas for entities, activities, anchors, renditions, and deletion closure.
    • Governs parser/model qualification by language, document class, and risk.
    • Quantifies regional backlog recovery and reserved capacity economics.
    • Defines long-term citation compatibility and evidence-retention policy.
    • Names owners and exception authority for quarantine, external processing, biometric data, and migration.

    Final design checklist¶

    • Raw bytes and every derivative have immutable digests.
    • Native text and OCR are selected by region with provenance.
    • Layout, tables, images, and audio survive as structured nodes.
    • Citations resolve to exact page regions or audio time ranges.
    • Pipeline state distinguishes partial, quarantined, retryable, and final failure.
    • Capacity covers peak mix, retries, reserve, and derivative storage.
    • Replay records implementation, parameters, environment, inputs, and outputs.
    • ACL, retention, redaction, and deletion traverse the lineage graph.
