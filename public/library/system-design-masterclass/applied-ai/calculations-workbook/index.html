    Applied AI Calculations Workbook¶

    These 44 solved problems make assumptions, formulas, units, and decision limits explicit. Decimal GB uses 10^9 bytes; GiB uses 2^30 bytes. Dollar values are fixture assumptions, not prices or performance claims for a vendor.

    Token, context, and throughput¶

    1. Context fit¶

    Problem: A 16,384-token window receives 900 system, 700 user, 4,800 retrieval, and 1,600 history tokens. Reserve 2,000 output and 10% of the window as headroom. Does it fit?

    Solution: Headroom is ceil(16,384*0.10)=1,639. Commitment is 900+700+4,800+1,600+2,000+1,639=11,639. Spare is 16,384-11,639=4,745 tokens.

    Answer: Yes; 4,745 tokens remain.

    2. Chunk budget¶

    Problem: After fixed content and reserves, 5,250 tokens remain. Each chunk is at most 750 tokens. How many whole chunks fit?

    Solution: floor(5,250/750)=7.

    Answer: Seven chunks.

    3. Truncation needed¶

    Problem: A request commits 19,200 tokens to a 16,384-token window. How many tokens must be removed?

    Solution: 19,200-16,384=2,816.

    Answer: Remove at least 2,816 tokens while preserving mandatory policy and output reserve.

    4. Generated-token demand¶

    Problem: Traffic is 3 requests/s with mean 600 generated tokens/request.

    Solution: 3*600=1,800 generated tokens/s.

    Answer: 1,800 generated tokens/s; input processing must be budgeted separately.

    5. Required GPUs¶

    Problem: Demand is 1,800 generated tokens/s. A GPU sustains 125 tokens/s at the target SLO. Keep 20% reserve.

    Solution: Usable per GPU is 125*0.8=100 tokens/s. GPUs required are ceil(1,800/100)=18.

    Answer: 18 GPUs under these assumptions.

    6. Batch throughput¶

    Problem: Eight sequences each generate 400 tokens in 32 seconds.

    Solution: Total is 8*400=3,200 tokens. Throughput is 3,200/32=100 tokens/s.

    Answer: 100 aggregate generated tokens/s, not 100 per sequence.

    7. Output duration¶

    Problem: A request generates 480 tokens at 60 tokens/s after 0.7 s time-to-first-token.

    Solution: If TTFT already includes the first of 480 tokens and 60 tokens/s describes subsequent token intervals, remaining decode time is (480-1)/60=7.9833 s. Model time is 0.7+7.9833=8.6833 s; using 480/60 is a fluid approximation.

    Answer: About 8.7 seconds rounded, assuming the stated TTFT excludes gateway and queue time. A client-observed TTFT often includes both; do not add them twice.

    8. Admission from token rate¶

    Problem: Usable capacity is 2,400 output tokens/s; mean output is 800 tokens/request.

    Solution: 2,400/800=3 requests/s.

    Answer: At most 3 requests/s at the mean; tails and class mix still require queue bounds.

    Memory and GPU arithmetic¶

    9. Parameter memory¶

    Problem: What is raw weight memory for 7 billion parameters at 2 bytes/parameter?

    Solution: 7e9*2=14e9 bytes = 14 GB = 13.04 GiB.

    Answer: 14 GB, about 13.04 GiB, before runtime overhead.

    10. Quantized weight memory¶

    Problem: A 13-billion-parameter model uses 4 bits/parameter plus 8% metadata.

    Solution: Raw is 13e9*4/8=6.5 GB. With metadata: 6.5*1.08=7.02 GB.

    Answer: About 7.02 GB; kernels and activations add more.

    11. KV cache per token¶

    Problem: A model has 32 layers, 8 KV heads, head dimension 128, 2-byte elements, and key plus value.

    Solution: 2*32*8*128*2=131,072 bytes/token = 128 KiB/token.

    Answer: 128 KiB per cached token per sequence.

    12. KV cache per sequence¶

    Problem: Use Problem 11 at 8,000 cached tokens.

    Solution: 131,072*8,000=1,048,576,000 bytes = 0.977 GiB.

    Answer: About 0.98 GiB per sequence.

    13. Resident sequences¶

    Problem: Twelve GiB is available for KV cache; each sequence needs 0.977 GiB.

    Solution: floor(12/0.977)=12 sequences.

    Answer: 12 sequences in the simplified model; allocator fragmentation can reduce this.

    14. Memory reserve¶

    Problem: A 48 GiB GPU uses 30 GiB weights/runtime and requires 15% total-memory reserve. How much remains for KV and activations?

    Solution: Reserve is 48*0.15=7.2 GiB. Remaining is 48-30-7.2=10.8 GiB.

    Answer: 10.8 GiB.

    15. Tensor-parallel weight share¶

    Problem: Sixty GB of weights are evenly sharded across four GPUs with 10% per-GPU overhead on the shard.

    Solution: Base shard is 60/4=15 GB; with overhead 15*1.10=16.5 GB.

    Answer: 16.5 GB/GPU, excluding replicated state and communication buffers.

    16. Utilization headroom¶

    Problem: A pool provides 4,000 tokens/s raw and runs at 3,100 tokens/s. Policy limit is 80%.

    Solution: Limit is 4,000*0.8=3,200. Policy headroom is 3,200-3,100=100 tokens/s.

    Answer: 100 tokens/s of policy headroom, although raw headroom is 900.

    Cost and economics¶

    17. GPU-hour cost per million tokens¶

    Problem: One GPU costs $3/hour and sustains 150 generated tokens/s.

    Solution: Hourly output is 150*3,600=540,000 tokens. Cost/million is 3/540,000*1,000,000=$5.56.

    Answer: $5.56 per million generated tokens at full measured throughput.

    18. Request cost¶

    Problem: Input costs $2/million tokens and output $8/million. A request has 3,000 input and 500 output tokens.

    Solution: Input is 3,000/1e6*2=$0.006; output is 500/1e6*8=$0.004.

    Answer: $0.010/request.

    19. Daily cost¶

    Problem: Ten requests/s run all day at $0.006/request.

    Solution: Requests/day are 10*86,400=864,000. Cost is 864,000*0.006=$5,184.

    Answer: $5,184/day.

    20. Cache savings¶

    Problem: Daily input spend is $2,000 at one uniform uncached rate. A safe prefix cache covers 35% of input tokens and cached input costs 20% of normal; ignore cache-write premiums and changes in traffic.

    Solution: New spend is 2,000*((1-.35)+.35*.20)=2,000*.72=$1,440.

    Answer: Save $560/day, before cache infrastructure cost.

    21. Fallback premium¶

    Problem: Normal request cost is $0.01. During a 2-hour incident, 25 requests/s fall back at $0.04.

    Solution: Requests are 25*7,200=180,000. Increment is 180,000*(.04-.01)=$5,400.

    Answer: $5,400 incremental incident cost.

    22. Evaluation run cost¶

    Problem: Evaluate 12,000 cases twice. Each attempt averages 2,500 input at $1/million and 300 output at $5/million.

    Solution: Attempt cost is .0025*1 + .0003*5=$0.004. Attempts are 24,000. Total is 24,000*.004=$96.

    Answer: $96.

    Retrieval and ranking¶

    23. Precision@5¶

    Problem: Three of the top five documents are relevant.

    Solution: Precision@5=3/5=0.60.

    Answer: 0.60.

    24. Recall@5¶

    Problem: The corpus judgments contain six relevant documents; top five retrieves three.

    Solution: Recall@5=3/6=0.50.

    Answer: 0.50.

    25. Reciprocal rank¶

    Problem: The first relevant result appears at rank 4.

    Solution: RR=1/4=0.25.

    Answer: 0.25.

    26. Mean reciprocal rank¶

    Problem: First relevant ranks for four queries are 1, 2, none, and 4.

    Solution: MRR=(1+1/2+0+1/4)/4=1.75/4=0.4375.

    Answer: 0.4375.

    27. DCG@3¶

    Problem: Graded relevance at ranks 1-3 is [3,1,2]; use sum((2^rel-1)/log2(rank+1)).

    Solution: 7/log2(2) + 1/log2(3) + 3/log2(4) = 7+0.631+1.5=9.131.

    Answer: DCG@3 is about 9.131.

    28. nDCG@3¶

    Problem: Use Problem 27; ideal order is [3,2,1].

    Solution: Ideal DCG is 7+3/log2(3)+1/log2(4)=7+1.893+0.5=9.393. nDCG=9.131/9.393=0.972.

    Answer: nDCG@3 is about 0.972.

    29. RRF score¶

    Problem: A document ranks 2 lexically and 5 semantically. Use RRF constant 60.

    Solution: 1/(60+2)+1/(60+5)=1/62+1/65=0.03151.

    Answer: About 0.03151; it is a fusion score, not a probability.

    30. Candidate ceiling¶

    Problem: Candidate generation retrieves 80 of 100 relevant documents before reranking.

    Solution: Maximum final recall is 80/100=0.80; reranking cannot recover absent documents.

    Answer: Recall ceiling is 0.80.

    31. ANN work reduction¶

    Problem: Exact search compares 2 million vectors; ANN compares 40,000 candidates.

    Solution: Reduction is 1-40,000/2,000,000=0.98.

    Answer: 98% fewer comparisons, without implying 98% lower latency.

    32. Embedding storage¶

    Problem: Store 10 million 768-dimensional float32 vectors, ignoring metadata/index overhead.

    Solution: 10e6*768*4=30.72e9 bytes=30.72 GB=28.61 GiB.

    Answer: 30.72 GB raw.

    33. Chunk overlap overhead¶

    Problem: A long document uses 800-token chunks with 200-token overlap. Approximate duplication factor?

    Solution: Stride is 800-200=600. For a long stream, factor is 800/600=1.333.

    Answer: About 33.3% token duplication, excluding boundaries.

    Evaluation and confidence¶

    34. Accuracy interval¶

    Problem: A fixed evaluation set sampled independently from the target population has 850 correct of 1,000. Estimate the population accuracy with a normal 95% interval; the observed set accuracy itself is exactly 85%.

    Solution: p=.85; SE=sqrt(.85*.15/1000)=.01129; margin 1.96*.01129=.0221.

    Answer: Approximately [0.8279,0.8721]; use a suitable binomial interval for formal decisions.

    35. Difference in proportions¶

    Problem: Baseline is 80% on 1,000 independent cases and candidate 84% on another 1,000. Approximate unpaired SE.

    Solution: SE=sqrt(.8*.2/1000 + .84*.16/1000)=.01716. Delta is .04; 95% interval is .04 +/- .0336=[.0064,.0736].

    Answer: Estimated improvement 4 points, interval about 0.64 to 7.36 points; paired data needs paired analysis.

    36. Required zero-failure sample¶

    Problem: With zero observed failures, use the rule of three to bound failure probability below 1% at about 95% confidence.

    Solution: Upper bound is approximately 3/n. Require 3/n<=.01, so n>=300.

    Answer: At least 300 independent representative trials with zero failures.

    For an exact one-sided 95% binomial upper bound, p_upper = 1 - 0.05^(1/n). At n=300 this is about 0.009936; the exact minimum for a bound strictly below 1% is 299. The rule of three is a conservative approximation here, not proof of zero risk or coverage of untested attack classes. See NIST's binomial interval construction, verified 2026-09-08; the one-sided zero-failure formula follows by solving (1-p)^n = 0.05.

    37. Safety-slice gate¶

    Problem: Overall pass is 93%, but a mandatory high-risk slice is 87/100 against a 90% minimum.

    Solution: Slice rate is 87%, below the fixed 90% gate.

    Answer: Reject release despite the overall score.

    38. Abstention precision¶

    Problem: A system abstains on 40 cases; 30 are truly unanswerable.

    Solution: Abstention precision is 30/40=.75.

    Answer: 0.75; also measure recall of unanswerable cases and answer utility.

    Reliability, queues, and incidents¶

    39. Workflow reliability¶

    Problem: Four mandatory independent steps each succeed with 99.5% probability.

    Solution: .995^4=.98015.

    Answer: About 98.015% all-step success; shared dependencies violate independence.

    40. Retry amplification¶

    Problem: Ten thousand logical requests have 20% one-retry rate and no further retries.

    Solution: Attempts are 10,000 + 2,000=12,000; amplification 12,000/10,000=1.2.

    Answer: 1.2 attempts/logical request.

    41. Queue growth¶

    Problem: Arrival demand is 2,500 tokens/s and service capacity 2,000 tokens/s for 3 minutes.

    Solution: Growth is 500 tokens/s. Backlog is 500*180=90,000 tokens.

    Answer: 90,000 queued tokens, before abandonments or shedding.

    42. Backlog drain¶

    Problem: A 90,000-token backlog remains after arrivals fall to 1,500 tokens/s against 2,000 capacity.

    Solution: Spare is 500 tokens/s. Drain time is 90,000/500=180 s.

    Answer: 3 minutes if capacity and arrivals remain stable.

    43. Little's Law¶

    Problem: Mean admitted rate is 4 requests/s and mean system time is 6 s.

    Solution: L=lambda*W=4*6=24 mean concurrent requests.

    Answer: Mean concurrency 24; do not substitute p99 latency for the mean.

    44. Idempotent unknown outcomes¶

    Problem: One thousand logical writes produce 1,120 attempts after lost acknowledgements. The implementation is intended to deduplicate by stable operation key, but an audit finds 2 extra committed effects.

    Solution: Attempt amplification is 1,120/1,000=1.12. Duplicate-effect rate is 2/1,000=.002=0.2%.

    Answer: 1.12 attempts/operation and 0.2 extra effects per 100 logical writes; investigate the two invariant violations. This denominator is logical writes, not all committed effects or the number of writes affected by duplicates.

    Source notes¶

    • Retrieval definitions follow Manning, Raghavan, and Schutze, Introduction to Information Retrieval.
    • RRF follows Cormack, Clarke, and Buettcher.
    • DCG and nDCG follow Jarvelin and Kekalainen.
    • Context and KV arithmetic follow the decoder attention structure in Attention Is All You Need; actual architectures and serving implementations differ.
    • Risk and evaluation framing follows NIST AI RMF 1.0.
    • HTTP retry and idempotent-method semantics are defined in RFC 9110; application idempotency keys require an explicit application contract.
