    Applied AI Failure Cards¶

    Use these cards during design review and incidents. A symptom is not a cause. Preserve request, model, prompt, index, corpus, policy, and tool versions before changing the system. Each card names evidence that can confirm or falsify the hypothesis.

    1. Context overflow¶

    Trigger: Input growth plus output reserve exceeds the model context limit.

    Symptoms: Rejection, silent truncation, missing instructions, or short output.

    Evidence and discriminator: Record token counts by category before submission and the exact truncation decision. If counts fit but behavior changes, investigate tokenizer/version drift or a different model limit.

    Contain and recover: Reject predictably or remove lowest-priority content under a published policy. Never drop safety policy or silently consume output reserve.

    Prevent: Per-class budgets, tokenizer regression tests, and headroom.

    2. KV-cache exhaustion¶

    Trigger: Concurrent cached tokens exceed available accelerator memory.

    Symptoms: Admission stalls, eviction, out-of-memory errors, or latency cliffs.

    Evidence and discriminator: Compare active sequences, cached tokens, bytes/token, allocator state, and batch shape. Low GPU compute with high KV occupancy points to memory, not arithmetic throughput.

    Contain and recover: Stop admission, reduce sequence/output caps, drain, and preserve recovery reserve.

    Prevent: Token-weighted admission and measured memory envelopes.

    3. Tokenizer drift¶

    Trigger: Gateway and serving model use different tokenizer or template versions.

    Symptoms: Budget mismatch, unexpected truncation, cost variance, or invalid offsets.

    Evidence and discriminator: Tokenize frozen strings with both version digests and compare IDs/counts. Identical text with divergent counts isolates tokenization/template drift.

    Contain and recover: Pin compatible versions or budget with the serving tokenizer.

    Prevent: Golden token fixtures in release gates.

    4. Gateway fallback policy bypass¶

    Trigger: Routing or fallback executes before data-class and authorization policy.

    Symptoms: Restricted requests reach a disallowed model or region during outage.

    Evidence and discriminator: Join logical request, policy decision, route reason, provider attempt, and region. An authoritative dispatch record showing execution without an allow decision confirms the invariant breach. A missing sampled trace or delayed audit event alone does not: first check evidence completeness, and contain the uncertain path while reconstructing it.

    Contain and recover: Disable fallback, revoke route capability, and assess affected request IDs.

    Prevent: Deny-by-default routing and policy-order integration tests.

    5. Fallback cost runaway¶

    Trigger: Cheap-model failure shifts all traffic to an expensive route.

    Symptoms: Spend spike despite stable request volume.

    Evidence and discriminator: Compare attempts, token mix, route reasons, and unit cost by model. Stable tokens with changed route mix separates price from demand growth.

    Contain and recover: Apply class budgets, degrade optional work, and cap fallback duration.

    Prevent: Precomputed incident cost envelopes and spend admission.

    6. Approximate index recall collapse¶

    Trigger: Probe depth, partitioning, filters, or data distribution changes.

    Symptoms: Relevant sources disappear while index latency improves.

    Evidence and discriminator: Compare ANN results with exact search on the same frozen queries and corpus version. Stable exact recall plus falling ANN overlap implicates candidate search.

    Contain and recover: Increase search effort or route affected slices to exact/previous index.

    Prevent: Recall@k gates by slice and dual-index rollback.

    7. Metadata filter before/after mismatch¶

    Trigger: A selective ACL or tenant filter is applied only after ANN candidates are chosen.

    Symptoms: Empty result sets despite relevant authorized documents.

    Evidence and discriminator: Count candidates before and after filtering and compare a filter-aware exact query. High prefilter hits with zero authorized postfilter hits exposes candidate starvation.

    Contain and recover: Use filter-aware search, or partition by security domain. Bounded overfetch may improve completeness inside an already authorized isolation boundary; it does not fix unauthorized candidate exposure or cross-tenant graph interference. The pinned pgvector v0.8.6 filtering documentation, verified 2026-09-08, describes post-scan filters and bounded iterative scans explicitly.

    Prevent: Filter-selectivity benchmarks and authorization invariants.

    8. RRF ranking regression¶

    Trigger: Rank constant, source depth, tie-break, or list weighting changes.

    Symptoms: Hybrid ranking changes with no lexical/vector model change.

    Evidence and discriminator: Persist both input rank lists and recompute every RRF contribution. If recomputation differs, fusion code/config is causal.

    Contain and recover: Restore the versioned fusion rule.

    Prevent: Golden rank-list fixtures and deterministic ties.

    9. Reranker candidate ceiling¶

    Trigger: Candidate stage omits relevant documents.

    Symptoms: Reranker quality plateaus despite model improvements.

    Evidence and discriminator: Measure candidate Recall@N before reranking. Missing judged documents prove the reranker cannot recover them.

    Contain and recover: Increase or diversify candidate generation within latency limits.

    Prevent: Gate candidate recall separately from final ranking.

    10. Stale corpus/index split¶

    Trigger: Corpus publication and index activation are not atomic or version-aligned.

    Symptoms: Answers cite deleted, old, or not-yet-approved text.

    Evidence and discriminator: Join answer citations to the exact source and index manifests pinned by that request, plus its current authorization decision. A source absent from that pinned corpus indicates inconsistent lineage. A citation to a retained old version after a later activation is not by itself a fault; verify the request freshness and citation-retention contract before declaring split state.

    Contain and recover: Pin reads to a coherent epoch or roll back the index manifest while preserving the independent latest authorization and tombstone overlay.

    Prevent: Immutable manifests and atomic activation.

    11. Ingestion parser silent empty¶

    Trigger: Parser failure is interpreted as a valid zero-content document.

    Symptoms: Source disappears without an explicit deletion.

    Evidence and discriminator: Compare fetched bytes, parser status, prior chunk count, and new manifest. Nonempty input plus zero chunks is suspicious, not conclusive: a valid blank PDF or image-only document may contain bytes but no extracted text. Require an explicit validated-empty classification or quarantine; never silently publish an empty replacement after a parser error.

    Contain and recover: Quarantine the version and retain the last valid manifest.

    Prevent: Minimum-content checks and explicit empty/delete states.

    12. ACL propagation failure¶

    Trigger: Chunks or cached answers lose source access metadata.

    Symptoms: Cross-tenant retrieval or citations.

    Evidence and discriminator: Trace principal, source ACL, chunk ACL, filter, cache key, and returned IDs. A returned ID outside the principal's authorized set proves leakage.

    Contain and recover: Disable affected retrieval/cache path and revoke exposed derivatives.

    Prevent: Security-domain indexes, principal-bound cache keys, and deny tests.

    13. Deletion tombstone lag¶

    Trigger: Physical index/cache purge lags a deletion request without immediate logical filtering.

    Symptoms: Deleted source remains retrievable.

    Evidence and discriminator: Compare tombstone time with retrieval, cache, and purge logs. Retrieval after tombstone confirms enforcement failure even if purge is pending.

    Contain and recover: Enforce tombstones at read time and invalidate caches.

    Prevent: Deletion SLOs with sampled end-to-end probes.

    14. Evaluation leakage¶

    Trigger: Evaluation cases or answers contaminate prompts, training, tuning, or manual iteration.

    Symptoms: Offline uplift does not reproduce on fresh or temporal holdouts.

    Evidence and discriminator: Audit case lineage, access, timestamps, near-duplicate hashes, and tuning history. Performance concentrated in exposed cases supports leakage.

    Contain and recover: Freeze changes and rerun on an isolated holdout.

    Prevent: Access-controlled sets, temporal splits, and contamination scans.

    15. Aggregate metric hides slice harm¶

    Trigger: Release uses only a weighted overall score.

    Symptoms: Overall quality rises while a language, tenant, risk, or answerability slice regresses.

    Evidence and discriminator: Recompute the fixed metric by predeclared slices with sample counts and uncertainty.

    Contain and recover: Stop or roll back the affected cohort.

    Prevent: Mandatory noninferiority gates for critical slices.

    16. Release on noise¶

    Trigger: A positive point estimate is treated as proof without uncertainty or sufficient sample size.

    Symptoms: Repeated A/B decisions alternate direction.

    Evidence and discriminator: Compute a confidence interval or paired test on frozen outcomes. An interval crossing the decision boundary means evidence is inconclusive.

    Contain and recover: Hold release or run the preregistered larger evaluation.

    Prevent: Power planning, paired cases, and fixed gates.

    17. Judge-model drift¶

    Trigger: Automated evaluator version changes without calibration.

    Symptoms: Historical candidates receive new scores with unchanged outputs.

    Evidence and discriminator: Re-score a frozen calibration set by judge version and compare with adjudicated human labels.

    Contain and recover: Restore the calibrated judge or require human review for disputed slices.

    Prevent: Versioned rubrics, judge prompts, and calibration thresholds.

    18. Citation looks valid but is unsupported¶

    Trigger: Presence or formatting of a citation is scored instead of entailment and exact span support.

    Symptoms: Answers cite a real source that does not support the claim.

    Evidence and discriminator: Map each atomic claim to quoted source spans and versions. Valid ID plus absent support isolates grounding failure.

    Contain and recover: Abstain, narrow the claim, or retrieve supporting evidence.

    Prevent: Claim-level citation precision and support review.

    19. Agent loop exhausts budget¶

    Trigger: Planner repeats searches or reflections without a decreasing measure or stop rule.

    Symptoms: Rising steps, tokens, latency, and cost without progress.

    Evidence and discriminator: Inspect step trace, repeated normalized arguments, budget counters, and progress state. Repetition with no new evidence confirms nonprogress.

    Contain and recover: Stop, return bounded partial state, and avoid autonomous retries.

    Prevent: Step/token/time/tool budgets and repeated-action detection.

    20. Tool timeout after commit¶

    Trigger: The effect commits but its acknowledgement is lost.

    Symptoms: Caller sees timeout; retry may duplicate an effect.

    Evidence and discriminator: Reconcile by stable operation key at the tool's authority boundary. Before reconciliation the caller's outcome is unknown; an authoritative committed record resolves it to committed, not failed.

    Contain and recover: Query first; retry only with the same key and payload digest when the receiving system's retention and concurrency contract makes that retry safe. A stale negative lookup is not proof of absence. Stripe's idempotency contract, verified 2026-09-08, permits a new operation after a key is pruned.

    Prevent: Atomic idempotency records and tested lost-ack behavior.

    21. Idempotency-key payload conflict¶

    Trigger: A caller reuses one key for different normalized arguments.

    Symptoms: Old result returned for new intent or second effect created.

    Evidence and discriminator: Compare stored and incoming payload digests for the key.

    Contain and recover: Reject the conflict and require explicit reconciliation; never overwrite history.

    Prevent: Server-side key/digest binding and retention contracts.

    22. Replay repeats a side effect¶

    Trigger: Durable recovery records decisions but not terminal tool results.

    Symptoms: Resumed run performs an already-completed write.

    Evidence and discriminator: Fold ordered ledger events and compare tool operation keys with effect records. Missing result plus existing effect isolates the gap.

    Contain and recover: Reconcile the operation key before advancing.

    Prevent: Durable step state plus independently idempotent tools.

    23. Indirect prompt injection¶

    Trigger: Retrieved or tool-returned text instructs the model to exceed its authority.

    Symptoms: Unauthorized tool proposals, destination changes, or attempted data disclosure.

    Evidence and discriminator: Preserve trust labels, retrieved spans, proposal, policy decision, and tool call. A denied proposal shows defense working; an executed ungranted capability is an incident.

    Contain and recover: Remove write capabilities, rotate exposed credentials, preserve evidence, and assess effects.

    Prevent: Treat content as data; typed least-privilege tools, egress policy, approvals, and red-team tests.

    24. Capacity retry storm¶

    Trigger: Slow inference causes clients, gateway, and workflow to retry independently.

    Symptoms: Attempts rise faster than logical requests; queues and timeouts worsen after capacity loss.

    Evidence and discriminator: Compare logical requests, attempts by layer, token demand, queue age, and admitted throughput. Attempt amplification with stable logical arrivals identifies retries.

    Contain and recover: Choose one retry owner, shed before queueing, honor deadlines, and reserve recovery capacity.

    Prevent: End-to-end retry budgets and overload drills.

    25. Output-token tail overload¶

    Trigger: Output length distribution shifts while request rate remains stable.

    Symptoms: Decode occupancy, queue age, and cost rise without input-volume growth.

    Evidence and discriminator: Compare output-token histograms and finish reasons by prompt/model version. Stable requests with longer outputs separates length from traffic growth.

    Contain and recover: Lower class-specific output caps and degrade optional generation.

    Prevent: Token-weighted capacity plans and output-length gates.

    26. Unsafe incident fallback¶

    Trigger: Operators disable grounding, authorization, or safety checks to regain throughput.

    Symptoms: Latency improves while unsupported or unauthorized outcomes rise.

    Evidence and discriminator: Compare policy and pipeline versions with invariant counters. Improvement coincident with bypassed controls confirms unsafe recovery.

    Contain and recover: Restore mandatory controls; shed or refuse instead.

    Prevent: Preapproved degraded modes that preserve safety invariants.

    Source notes¶

    • Risk, measurement, and governance framing: NIST AI RMF 1.0.
    • Adversarial and prompt-injection taxonomy: NIST AI 100-2e2025 and OWASP Top 10 for LLM Applications.
    • Retrieval architecture: Lewis et al., Retrieval-Augmented Generation.
    • Operational ML debt and hidden coupling: Sculley et al., Hidden Technical Debt in Machine Learning Systems.
    • Retry/idempotent method semantics: RFC 9110. Application operation keys remain an explicit service contract.
