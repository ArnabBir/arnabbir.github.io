    Lab 01: Trace One Request End to End¶

    Lab index | Next: Command Evidence

    Outcome¶

    Build a phase timeline for one HTTP request and separate measured time from inferred DNS, connect, server, and transfer time. Explain why a warm localhost trace cannot predict a production p99.

    Safety boundary¶

    Use only 127.0.0.1. The fixture serves synthetic text and handles a few requests. Do not replace the URL with a production endpoint. No root access, Docker, or public network is needed.

    Supplied fixture transcript¶

    $ curl --noproxy '*' --max-time 2 -sS -o /dev/null -w 'code=%{http_code} dns=%{time_namelookup} connect=%{time_connect} first_byte=%{time_starttransfer} total=%{time_total}\n' 'http://127.0.0.1:18081/?delay_ms=120'
code=200 dns=0.000025 connect=0.000142 first_byte=0.121031 total=0.121118

$ curl --noproxy '*' --max-time 2 -sS 'http://127.0.0.1:18081/?delay_ms=0'
request_id=2 delay_ms=0 body_bytes=2048

    Treat these numbers as supplied data if curl is unavailable.

    Portable localhost path¶

    Start the server in terminal A:

    python3 - <<'PY'
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from urllib.parse import parse_qs, urlparse
import threading, time

count = 0
lock = threading.Lock()
class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        global count
        q = parse_qs(urlparse(self.path).query)
        try:
            delay = max(0, min(int(q.get("delay_ms", ["0"])[0]), 1000))
        except ValueError:
            self.send_error(400, "delay_ms must be an integer"); return
        with lock:
            count += 1
            request_id = count
        time.sleep(delay / 1000)
        prefix = f"request_id={request_id} delay_ms={delay} body_bytes=2048\n".encode()
        body = prefix + b"x" * (2048 - len(prefix))
        self.send_response(200)
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)
    def log_message(self, fmt, *args):
        print(time.strftime("%H:%M:%S"), fmt % args, flush=True)

with ThreadingHTTPServer(("127.0.0.1", 18081), Handler) as server:
    server.serve_forever()
PY

    In terminal B, use curl if present:

    curl --noproxy '*' --max-time 2 -sS -o /dev/null -w 'code=%{http_code} dns=%{time_namelookup} connect=%{time_connect} first_byte=%{time_starttransfer} total=%{time_total}\n' 'http://127.0.0.1:18081/?delay_ms=120'

    Pure Python alternative:

    python3 - <<'PY'
import http.client, time
t0 = time.perf_counter()
c = http.client.HTTPConnection("127.0.0.1", 18081, timeout=2)
t1 = time.perf_counter(); c.request("GET", "/?delay_ms=120")
r = c.getresponse(); t2 = time.perf_counter(); body = r.read(); t3 = time.perf_counter()
print(f"setup_object_ms={(t1-t0)*1000:.3f}")
print(f"request_to_headers_ms={(t2-t1)*1000:.3f}")
print(f"body_read_ms={(t3-t2)*1000:.3f} status={r.status} bytes={len(body)}")
c.close()
PY

    Optional enhanced commands¶

    curl -v exposes request and response headers. curl --trace-time --trace-ascii - adds event timestamps but may reveal sensitive headers. A packet capture is not needed; if authorized on a disposable host, capture only loopback metadata and avoid payload retention.

    Tasks¶

    1. Record tool versions and run ID.
    2. Run delays of 0, 40, and 120 ms three times each.
    3. Compute connect - dns, first_byte - connect, and total - first_byte for the supplied trace.
    4. Label each result as direct measurement or derived value.
    5. Predict a 300 ms delay, inject it, and compare actual first-byte time.
    6. Stop the server, repeat one request, and preserve the failure.
    7. Restart the server and prove recovery with a 200 response.

    Expected observations¶

    • The configured server delay mostly appears between connection completion and first byte.
    • DNS time is near zero because the request uses a numeric loopback address.
    • Body transfer is small and local, so it is usually much shorter than server delay.
    • After shutdown, connection establishment fails; there is no HTTP status.

    Calculations¶

    Subtract adjacent cumulative curl timestamps to obtain non-overlapping DNS, connect, post-connect, and body-transfer phases. Keep the result in seconds until the final conversion to milliseconds.

    Failure injection¶

    First inject latency with delay_ms=300. Then stop terminal A with Ctrl-C to inject refusal. Keep these failure classes separate: a slow HTTP response proves a connection and server existed; refusal means the HTTP exchange never began.

    Evidence limitations¶

    Loopback removes real resolver, router, congestion, packet-loss, proxy, and TLS behavior. A single process timestamp does not isolate server queue from server work. Three samples do not estimate p99. Curl's phase clocks are cumulative and tool-specific.

    The Python object's construction does not connect: request() lazily opens the connection. Its request-to-headers timer includes that setup. Curl's time_starttransfer measures time to the first response byte, not completion of all response headers. Do not equate the two measurements exactly.

    Source: curl write-out timing variables and Python HTTPConnection.

    Cleanup¶

    Press Ctrl-C in terminal A. Verify cleanup:

    python3 - <<'PY'
import socket
s = socket.socket(); s.settimeout(0.2)
error = s.connect_ex(("127.0.0.1", 18081))
print("connected" if error == 0 else f"not-connected errno={error}")
s.close()
PY

    A nonzero result proves only that this probe did not connect. Record the errno; connection refusal is stronger evidence of no listener than a timeout or another socket error.

    Answer key 
    connect phase = 0.000142 - 0.000025 = 0.000117 s = 0.117 ms
post-connect to first byte = 0.121031 - 0.000142 = 0.120889 s = 120.889 ms
body transfer = 0.121118 - 0.121031 = 0.000087 s = 0.087 ms
unaccounted labels do not imply separate clocks; curl timestamps are cumulative

    The 120 ms fixture delay dominates post-connect time. The trace supports: "For this request from this client process, connection setup completed quickly and the first response byte arrived about 121 ms after start." It does not support: "the network added 121 ms" or "the service p99 is 121 ms." The stopped-server result should be recorded as a connection failure with no HTTP response.

    L5 extension¶

    Draw the production path and assign an owner, timeout, metric, and request identifier to DNS, connect, TLS, proxy queue, service queue, work, and transfer.

    L6 extension¶

    Define an organization-wide phase-timing schema. Address clock source, sampling, high-cardinality IDs, proxy spans, privacy, protocol changes, and how teams distinguish client abandonment from completed side effects.

    Completion checklist¶

    • Captured baseline and two injected failures
    • Calculated non-overlapping phase differences with units
    • Distinguished measurement from inference
    • Proved recovery after restart
    • Recorded at least three evidence limitations
    • Stopped the localhost server
