    12. Concurrent LLD Problems: Solved Workbook¶

    This workbook combines concurrency reasoning with low-level design. Each solution is intentionally scoped for an interview: it is complete core Java 21 code for the stated contract, not a claim of production readiness. Real systems also need metrics, configuration, abuse controls, persistence, and integration-specific failure policy.

    Goals¶

    • clarify concurrent APIs before choosing classes;
    • isolate mutable state and write explicit invariants;
    • locate races and linearization points;
    • design cancellation, backpressure, and shutdown as first-class behavior;
    • construct deterministic tests with injected time and dependencies; and
    • evaluate solutions with a repeatable interview rubric.

    LLD answer framework¶

    1. Scope: callers, workload, ordering, durability, and failure semantics.
    2. Contract: method results, blocking, timeout, and cancellation behavior.
    3. State: ownership, invariants, and legal transitions.
    4. Coordination: library primitive and lock granularity.
    5. Proof: linearization point, happens-before edge, and deadlock argument.
    6. Operations: bounded resources, overload, observability, and shutdown.
    7. Tests: force races with controlled clocks, barriers, and fakes.

    1. Thread-safe token-bucket rate limiter¶

    Prompt¶

    Design an in-process limiter that admits an operation only when one token is available. Tokens refill continuously at a configured rate up to a fixed capacity. Multiple threads may call it concurrently. Support a non-blocking attempt and a timed blocking attempt.

    Clarified API and scope¶

    • One limiter represents one bucket. Per-user limiting composes buckets in a registry.
    • tryAcquire() does not wait for refill, but may briefly block acquiring the bookkeeping lock. It is not a lock-free or strict immediate-return API.
    • acquire(timeout) waits until one token is available, the deadline expires, or the caller is interrupted.
    • Time is monotonic. The implementation is local to one process and provides no distributed quota.
    • Fractional refill is retained as nanosecond-scaled credit.

    Invariants and class design¶

    • 0 <= storedNanos <= capacityNanos.
    • lastRefillNanos stores the latest monotonic clock tick; elapsed time uses wrap-safe subtraction.
    • State refill and token consumption happen under one lock.
    • Waiting does not reserve a future token; contenders recheck the predicate.
    import java.time.Duration;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.TimeUnit;
import java.util.function.LongSupplier;

public final class TokenBucket {
    private static final long TOKEN = 1_000_000_000L;
    private final long capacityNanos;
    private final long refillPerSecond;
    private final LongSupplier nanoTime;
    private final ReentrantLock lock = new ReentrantLock(true);
    private final Condition changed = lock.newCondition();
    private long storedNanos;
    private long lastRefillNanos;

    public TokenBucket(long capacity, long refillPerSecond, LongSupplier nanoTime) {
        if (capacity <= 0 || refillPerSecond <= 0) throw new IllegalArgumentException();
        this.capacityNanos = Math.multiplyExact(capacity, TOKEN);
        this.refillPerSecond = refillPerSecond;
        this.nanoTime = nanoTime;
        this.storedNanos = capacityNanos;
        this.lastRefillNanos = nanoTime.getAsLong();
    }

    public boolean tryAcquire() {
        lock.lock();
        try { return consumeIfAvailable(); }
        finally { lock.unlock(); }
    }

    public boolean acquire(Duration timeout) throws InterruptedException {
        if (timeout.isNegative()) throw new IllegalArgumentException("negative timeout");
        long timeoutNanos;
        try { timeoutNanos = timeout.toNanos(); }
        catch (ArithmeticException tooLarge) { timeoutNanos = Long.MAX_VALUE; }
        long deadline = nanoTime.getAsLong() + timeoutNanos;
        boolean acquired = lock.tryLock(timeoutNanos, TimeUnit.NANOSECONDS);
        if (!acquired) return false;
        try {
            if (timeoutNanos == 0) return consumeIfAvailable();
            while (true) {
                long remaining = deadline - nanoTime.getAsLong();
                if (remaining <= 0) return false;
                if (consumeIfAvailable()) return true;
                long untilToken = nanosUntilToken();
                changed.awaitNanos(Math.min(remaining, untilToken));
            }
        } finally { lock.unlock(); }
    }

    private boolean consumeIfAvailable() {
        refill();
        if (storedNanos < TOKEN) return false;
        storedNanos -= TOKEN;
        return true;
    }

    private void refill() {
        long now = nanoTime.getAsLong();
        long elapsed = Math.max(0, now - lastRefillNanos);
        if (elapsed == 0) return;
        long credit;
        try { credit = Math.multiplyExact(elapsed, refillPerSecond); }
        catch (ArithmeticException overflow) { credit = capacityNanos; }
        storedNanos = Math.min(capacityNanos, saturatedAdd(storedNanos, credit));
        lastRefillNanos = now;
    }

    private long nanosUntilToken() {
        long missing = TOKEN - storedNanos;
        long whole = missing / refillPerSecond;
        return Math.max(1, whole + (missing % refillPerSecond == 0 ? 0 : 1));
    }

    private static long saturatedAdd(long a, long b) {
        return Long.MAX_VALUE - a < b ? Long.MAX_VALUE : a + b;
    }
}

    Races, linearization, and cost¶

    The check and decrement must not be split; otherwise two callers can spend one token. A successful call linearizes at storedNanos -= TOKEN; a failed immediate call linearizes at the underflow check after refill. Operations are O(1). One lock makes the bucket a contention point, which is inherent for one strict quota. Sharding changes semantics by allowing bounded oversubscription.

    Liveness, cancellation, and shutdown¶

    acquire computes one overflow-safe absolute deadline before attempting the lock. Wrap-safe subtraction from the monotonic clock charges lock contention and every spurious or refill wake to the same budget. The zero-timeout path uses timed tryLock(0, NANOSECONDS) so pre-existing interruption and the fair-lock policy are respected even for an immediate attempt. It wakes on its computed refill time; no background thread is required. The condition also permits an extension where administrative refill or close calls signalAll. A closable version would guard a closed flag under the lock, signal all waiters, and reject future acquisition.

    Deterministic tests¶

    Use a fake LongSupplier backed by an AtomicLong. Drain the initial capacity, advance exactly one token interval, and assert one success. Start 100 callers behind a barrier against a one-token bucket and assert exactly one success. For timed waiting, coordinate clock advancement with a test-only wake method or a controllable condition abstraction; never wait on wall-clock seconds.

    Extensions and tradeoffs¶

    • Add tryAcquire(long permits) with overflow-safe arithmetic.
    • Store per-key buckets in a bounded, expiring registry; define eviction races.
    • Return retry-after duration for caller backoff.
    • For distributed enforcement, use server-side atomic state and accept latency/availability tradeoffs.
    • Fixed-point arithmetic is deterministic; a double implementation is shorter but accumulates rounding error.

    Evaluation rubric (10 points)¶

    • 2: clear burst and refill semantics;
    • 2: atomic refill plus consumption and bounded credit;
    • 2: monotonic injectable time and overflow awareness;
    • 2: interruption/deadline behavior and contention analysis;
    • 2: race-focused deterministic tests and distributed-scope caveat.

    2. TTL cache with stale-expiry protection¶

    Prompt¶

    Design a concurrent in-memory cache with per-entry TTL. Reads must never return an expired entry. A background sweeper may remove expired entries, but an old expiry record must never delete a newer value for the same key.

    Clarified API and invariants¶

    • put(key, value, ttl) replaces the key with a distinct immutable entry.
    • get(key) returns empty after expiration and may lazily remove the entry.
    • remove(key) conditionally removes the entry it observed.
    • TTL zero is rejected; expiry uses monotonic time.
    • The map contains at most one current entry per key. An expiry task can delete only the exact entry instance it was created for.
    import java.time.Duration;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.DelayQueue;
import java.util.concurrent.Delayed;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantReadWriteLock;
import java.util.function.LongSupplier;

public final class TtlCache<K, V> implements AutoCloseable {
    private static final long MAX_TTL_NANOS = Long.MAX_VALUE / 2;

    private static final class Entry<V> {
        private final V value;
        private final long expiresAt;
        Entry(V value, long expiresAt) {
            this.value = value;
            this.expiresAt = expiresAt;
        }
        V value() { return value; }
        long expiresAt() { return expiresAt; }
    }

    private static final class Expiry<K, V> implements Delayed {
        final K key;
        final Entry<V> expected;
        final LongSupplier nanoTime;
        Expiry(K key, Entry<V> expected, LongSupplier nanoTime) {
            this.key = key;
            this.expected = expected;
            this.nanoTime = nanoTime;
        }
        @Override public long getDelay(TimeUnit unit) {
            return unit.convert(expected.expiresAt() - nanoTime.getAsLong(), TimeUnit.NANOSECONDS);
        }
        @Override public int compareTo(Delayed other) {
            Expiry<?, ?> that = (Expiry<?, ?>) other;
            long difference = expected.expiresAt() - that.expected.expiresAt();
            return Long.compare(difference, 0);
        }
    }

    private final ConcurrentHashMap<K, Entry<V>> entries = new ConcurrentHashMap<>();
    private final DelayQueue<Expiry<K, V>> expiries = new DelayQueue<>();
    private final ReentrantReadWriteLock lifecycle = new ReentrantReadWriteLock();
    private final LongSupplier nanoTime;
    private final Thread sweeper;
    private volatile boolean running = true;
    private boolean closed;

    public TtlCache(LongSupplier nanoTime) {
        this.nanoTime = nanoTime;
        this.sweeper = Thread.ofPlatform().name("ttl-cache-sweeper").start(this::sweep);
    }

    public void put(K key, V value, Duration ttl) {
        if (key == null || value == null) throw new NullPointerException();
        long ttlNanos;
        try { ttlNanos = ttl.toNanos(); }
        catch (ArithmeticException tooLarge) {
            throw new IllegalArgumentException("TTL is too large", tooLarge);
        }
        if (ttlNanos <= 0 || ttlNanos > MAX_TTL_NANOS)
            throw new IllegalArgumentException("TTL must be in (0, 2^62) nanoseconds");
        lifecycle.readLock().lock();
        try {
            ensureOpen();
            long expiresAt = nanoTime.getAsLong() + ttlNanos;
            Entry<V> entry = new Entry<>(value, expiresAt);
            entries.put(key, entry);
            expiries.offer(new Expiry<>(key, entry, nanoTime));
        } finally {
            lifecycle.readLock().unlock();
        }
    }

    public Optional<V> get(K key) {
        lifecycle.readLock().lock();
        try {
            ensureOpen();
            while (true) {
                Entry<V> entry = entries.get(key);
                if (entry == null) return Optional.empty();
                if (nanoTime.getAsLong() - entry.expiresAt() < 0)
                    return Optional.of(entry.value());
                if (entries.remove(key, entry)) return Optional.empty();
            }
        } finally {
            lifecycle.readLock().unlock();
        }
    }

    public boolean remove(K key) {
        lifecycle.readLock().lock();
        try {
            ensureOpen();
            Entry<V> entry = entries.get(key);
            return entry != null && entries.remove(key, entry);
        } finally {
            lifecycle.readLock().unlock();
        }
    }

    private void ensureOpen() {
        if (closed) throw new IllegalStateException("cache is closed");
    }

    private void sweep() {
        try {
            while (running) {
                Expiry<K, V> expiry = expiries.take();
                entries.remove(expiry.key, expiry.expected);
            }
        } catch (InterruptedException interrupted) {
            Thread.currentThread().interrupt();
        }
    }

    @Override public void close() throws InterruptedException {
        lifecycle.writeLock().lock();
        try {
            if (!closed) {
                closed = true;
                running = false;
                sweeper.interrupt();
            }
        } finally {
            lifecycle.writeLock().unlock();
        }
        try {
            sweeper.join();
        } finally {
            expiries.clear();
            entries.clear();
        }
    }
}

    Races, linearization, and cost¶

    The critical race is put(k, old), put(k, new), then old expiry. remove(k, expected) uses entry identity to protect the replacement. An expired get retries if removal loses to replacement: returning empty then could invent a cache miss even though an unexpired mapping existed throughout the call. Successful get linearizes at its map read (the later clock check proves it was unexpired then); a miss linearizes at a null read or successful expired-entry removal. put linearizes at map replacement. Map work is average O(1), but put also inserts an O(log n) expiry record; get can retry under replacement contention. Old expiry records remain until due, so frequent replacement can grow the delay queue.

    Signed deadline subtraction assumes elapsed intervals remain below 2^63 ns and compared deadlines are less than that far apart. Bounded TTL alone is insufficient if expired records survive a centuries-long pause. Values and keys must be immutable or separately synchronized; immutable entry wrappers do not freeze user objects. Close interrupted during join rejects future operations and clears data but does not prove sweeper termination; retry close to join it.

    Cancellation, shutdown, and deterministic tests¶

    The lifecycle read/write lock makes admission and close atomic: once close obtains the write lock, no operation can be admitted, and all post-close put, get, and remove calls fail. Close stops the sole sweeper and clears process-local data. A fake clock alone does not wake DelayQueue.take, so unit-test stale protection by exposing package-private expiry logic or by factoring scheduling behind an interface. Test replacement, exact-boundary, wraparound, close-versus-put, and post-close rejection races.

    Extensions and tradeoffs¶

    • Bound memory with weight-based admission/eviction; TTL alone is not a capacity policy.
    • Compact superseded expiry records or use a timing wheel at scale.
    • Add loader single-flight separately; do not hold map internals while loading.
    • Define nulls, refresh, exception caching, and close behavior before adding them.

    Evaluation rubric (10 points)¶

    • 2: precise TTL boundary and injectable monotonic time;
    • 2: stale-expiry protection via identity-based conditional removal;
    • 2: thread-safe map and linearization argument;
    • 2: lifecycle and queue-growth tradeoff;
    • 2: deterministic replacement/expiry race tests.

    3. Dependency-aware task scheduler¶

    Prompt¶

    Given named tasks forming a directed acyclic graph, run a task only after all its dependencies succeed. Run independent tasks concurrently. If one task fails, do not run its transitive dependents. Return a future for the entire execution.

    API, invariants, and class design¶

    • The graph is immutable after construction and validated before execution.
    • Names are unique; every dependency exists; cycles are rejected.
    • Each task starts at most once. RUNNING requires all direct dependencies to be SUCCEEDED.
    • Failure completes dependent futures exceptionally through composition.
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.Executor;

public final class DagScheduler {
    public record Task(String name, Set<String> dependencies, Runnable action) {
        public Task {
            java.util.Objects.requireNonNull(name, "name");
            java.util.Objects.requireNonNull(action, "action");
            dependencies = Set.copyOf(dependencies);
        }
    }

    private final Map<String, Task> tasks;
    private final Executor executor;

    public DagScheduler(List<Task> definitions, Executor executor) {
        Map<String, Task> indexed = new HashMap<>();
        for (Task task : definitions) {
            if (indexed.putIfAbsent(task.name(), task) != null)
                throw new IllegalArgumentException("duplicate task: " + task.name());
        }
        for (Task task : definitions)
            for (String dependency : task.dependencies())
                if (!indexed.containsKey(dependency))
                    throw new IllegalArgumentException("missing dependency: " + dependency);
        detectCycles(indexed);
        this.tasks = Map.copyOf(indexed);
        this.executor = java.util.Objects.requireNonNull(executor, "executor");
    }

    public CompletableFuture<Void> run() {
        Map<String, CompletableFuture<Void>> futures = new HashMap<>();
        for (String name : tasks.keySet()) build(name, futures);
        return CompletableFuture.allOf(futures.values().toArray(CompletableFuture[]::new));
    }

    private CompletableFuture<Void> build(
            String name, Map<String, CompletableFuture<Void>> futures) {
        CompletableFuture<Void> existing = futures.get(name);
        if (existing != null) return existing;
        Task task = tasks.get(name);
        CompletableFuture<?>[] prerequisites = task.dependencies().stream()
                .map(dependency -> build(dependency, futures))
                .toArray(CompletableFuture[]::new);
        CompletableFuture<Void> future = CompletableFuture.allOf(prerequisites)
                .thenRunAsync(task.action(), executor);
        futures.put(name, future);
        return future;
    }

    private static void detectCycles(Map<String, Task> tasks) {
        Set<String> visiting = new HashSet<>();
        Set<String> visited = new HashSet<>();
        for (String name : tasks.keySet()) visit(name, tasks, visiting, visited);
    }

    private static void visit(String name, Map<String, Task> tasks,
                              Set<String> visiting, Set<String> visited) {
        if (visited.contains(name)) return;
        if (!visiting.add(name)) throw new IllegalArgumentException("cycle at: " + name);
        for (String dependency : tasks.get(name).dependencies())
            visit(dependency, tasks, visiting, visited);
        visiting.remove(name);
        visited.add(name);
    }
}

    Races, linearization, and complexity¶

    run constructs its future map on one caller thread, so each task receives one stage. Completion of every prerequisite happens-before dependent stage execution through CompletableFuture. A task starts when the executor begins its action; success linearizes at normal stage completion. Validation and graph construction cost O(V + E); runtime scheduling is O(V + E) plus task work. Throughput is bounded by executor capacity and DAG width.

    Cancellation and shutdown¶

    Cancelling the returned allOf future does not cancel component stages, prevent pending dependents from starting, or interrupt running actions. allOf is not fail-fast: independent branches must finish before its exceptional result is ready. At-most-once is per run() invocation; calling run() twice executes two graphs. A stronger API owns handles, passes cancellation tokens, and stops admission. This class receives an executor and must not shut it down. Recursive validation/building can overflow the stack for a deep DAG; bound graph depth or use iterative topological construction before accepting untrusted graphs.

    Deterministic tests¶

    Use a direct executor to verify topological behavior without threads. For concurrency, make two root actions count down an entered latch and await a release latch; assert both enter before release. Make one root throw and assert its dependent never increments a counter while an independent branch completes. Test missing names, duplicate names, self-cycles, and multi-node cycles.

    Extensions and tradeoffs¶

    • Add task results with typed keys or a result context.
    • Add bounded concurrency, priorities, retries, and per-task timeout only after defining fairness.
    • Persist transitions for crash recovery; futures alone are in-memory orchestration.
    • Dynamic DAG mutation needs a different consistency model and cycle-validation strategy.

    Evaluation rubric (10 points)¶

    • 2: validated immutable DAG and cycle detection;
    • 2: at-most-once scheduling after all dependencies;
    • 2: independent parallelism and failure propagation;
    • 2: cancellation/executor ownership caveat;
    • 2: deterministic ordering, overlap, and failure tests.

    4. Concurrent event bus¶

    Prompt¶

    Design an in-process event bus. Subscribers register for one exact event class. Publishing dispatches to the current subscriber snapshot without holding registry locks while user code runs. Return a future that reports handler failure.

    API and invariants¶

    • Registration returns an idempotent subscription handle.
    • Exact runtime class matching avoids ambiguous hierarchy ordering.
    • One publish observes one immutable handler snapshot.
    • Removing a handler prevents future snapshots from including it; an already captured publish may still invoke it.
    • Handler order is registration order within a snapshot. Concurrent publications may overlap.
    import java.util.List;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.CompletionException;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.concurrent.Executor;
import java.util.concurrent.atomic.AtomicBoolean;
import java.util.function.Consumer;

public final class EventBus {
    public interface Subscription extends AutoCloseable {
        @Override void close();
    }

    private static final class Handler<E> {
        private final Consumer<E> consumer;
        Handler(Consumer<E> consumer) {
            this.consumer = java.util.Objects.requireNonNull(consumer);
        }
        Consumer<E> consumer() { return consumer; }
    }
    private final ConcurrentHashMap<Class<?>, CopyOnWriteArrayList<Handler<?>>> handlers =
            new ConcurrentHashMap<>();
    private final Executor executor;

    public EventBus(Executor executor) { this.executor = executor; }

    public <E> Subscription subscribe(Class<E> type, Consumer<E> consumer) {
        Handler<E> handler = new Handler<>(consumer);
        CopyOnWriteArrayList<Handler<?>> list =
                handlers.computeIfAbsent(type, ignored -> new CopyOnWriteArrayList<>());
        list.add(handler);
        return new Subscription() {
            private boolean active = true;
            @Override public synchronized void close() {
                if (active) {
                    list.remove(handler);
                    active = false;
                }
            }
        };
    }

    public CompletableFuture<Void> publish(Object event) {
        if (event == null) throw new NullPointerException("event");
        List<Handler<?>> snapshot = List.copyOf(
                handlers.getOrDefault(event.getClass(), new CopyOnWriteArrayList<>()));
        return CompletableFuture.runAsync(() -> deliver(snapshot, event), executor);
    }

    private static void deliver(List<Handler<?>> snapshot, Object event) {
        RuntimeException failures = null;
        for (Handler<?> handler : snapshot) {
            try {
                invoke(handler, event);
            } catch (RuntimeException failure) {
                if (failures == null) failures = new RuntimeException("event delivery failed");
                failures.addSuppressed(failure);
            }
        }
        if (failures != null) throw new CompletionException(failures);
    }

    @SuppressWarnings("unchecked")
    private static <E> void invoke(Handler<?> raw, E event) {
        ((Handler<E>) raw).consumer().accept(event);
    }
}

    Empty per-type lists are retained deliberately. A naive isEmpty followed by conditional map removal can orphan a subscriber added between those operations. Safe cleanup would use atomic per-key coordination; retaining a small empty registry entry keeps this teaching implementation clear.

    Handler wrappers intentionally use identity, not record equality. Registering the same consumer twice around another handler must allow closing the second registration without removing the first and changing callback order. Subscription close serializes through actual removal so a completed duplicate close cannot return before unsubscription takes effect.

    Races, linearization, and cost¶

    Subscription linearizes at list.add; unsubscription at successful list removal; publish snapshot selection at List.copyOf. One executor task walks that immutable snapshot serially, so callbacks begin in registration order even on a multithreaded executor. Concurrent publications can still overlap and have no cross-publication order. Publish costs one task and O(s) callback work for s subscribers. Registration/removal copies O(s) storage, making CopyOnWriteArrayList suitable only when publishing greatly outnumbers subscription changes.

    Liveness, cancellation, and shutdown¶

    One stuck handler prevents later handlers in that snapshot and leaves the publish future incomplete. Runtime failures are accumulated so later handlers still run, then reported through the returned future. Apply timeouts, bulkheads, or per-subscriber queues if isolation is required. Cancelling the future does not guarantee interruption of its executor task. The bus does not own the injected executor and does not close it. Rejected execution appears as synchronous failure while constructing the stage; a production API should normalize it into the returned future.

    Deterministic tests¶

    Use a direct executor for order and exception tests. Use a manually queued executor to capture a delivery, unsubscribe after publish, then run it and prove snapshot semantics. Register while another snapshot is captured and verify the new handler only sees later publications. Assert registration order under a multithreaded executor and assert one failing handler completes the future exceptionally after later handlers run.

    Extensions and tradeoffs¶

    • Polymorphic dispatch requires a documented type order and duplicate suppression.
    • Ordering across separate publications requires a per-key serial executor or a tail-future chain; this implementation guarantees order only within each publication snapshot.
    • Weak references reduce leaks but make delivery dependent on GC.
    • Durable delivery, replay, retries, and cross-process transport require a broker, not this bus.

    Evaluation rubric (10 points)¶

    • 2: explicit dispatch and unsubscribe race semantics;
    • 2: no user callback under registry coordination;
    • 2: safe snapshots and exception propagation;
    • 2: executor ownership, overload, and cancellation discussion;
    • 2: deterministic concurrent register/remove/publish tests.

    5. Multithreaded web crawler¶

    Prompt¶

    Crawl pages from a seed URL up to a page limit. Fetch pages concurrently, visit a normalized URL at most once, and follow only URLs accepted by a supplied policy. Support cooperative cancellation and return successfully fetched pages.

    Clarified API and scope¶

    • Fetching is injected and returns page content plus discovered links.
    • URL normalization removes fragments and normalizes URI syntax; application policy decides host/scheme rules.
    • A URL is marked seen before submission, preventing duplicate in-flight fetches.
    • The page limit bounds scheduled unique URLs, not necessarily successful responses.
    • One crawl may run at a time; cancellation is terminal and later crawls are rejected.
    • This educational crawler does not implement robots.txt, politeness delays, DNS protections, persistence, HTML parsing, retries, or canonical-link semantics.
    import java.net.URI;
import java.util.ArrayList;
import java.util.List;
import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.BlockingQueue;
import java.util.concurrent.CancellationException;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorCompletionService;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.LinkedBlockingQueue;
import java.util.concurrent.RejectedExecutionException;
import java.util.concurrent.atomic.AtomicBoolean;
import java.util.concurrent.atomic.AtomicReference;
import java.util.function.Predicate;

public final class ConcurrentCrawler implements AutoCloseable {
    public record Page(URI uri, String body, List<URI> links) {
        public Page { links = List.copyOf(links); }
    }
    public interface Fetcher { Page fetch(URI uri) throws Exception; }

    private record Result(URI uri, Page page, Exception failure) {}
    private static final Result CANCEL_SIGNAL = new Result(null, null, null);

    private static final class CrawlSession {
        final BlockingQueue<Future<Result>> completed = new LinkedBlockingQueue<>();
        final Future<Result> cancelSignal = CompletableFuture.completedFuture(CANCEL_SIGNAL);
        final Set<Future<Result>> tasks = ConcurrentHashMap.newKeySet();

        void cancelTasks() {
            for (Future<Result> task : tasks) task.cancel(true);
        }
    }

    private final ExecutorService workers;
    private final Fetcher fetcher;
    private final AtomicBoolean cancelled = new AtomicBoolean();
    private final AtomicReference<CrawlSession> active = new AtomicReference<>();

    public ConcurrentCrawler(int parallelism, Fetcher fetcher) {
        if (parallelism <= 0) throw new IllegalArgumentException("parallelism");
        this.workers = Executors.newFixedThreadPool(parallelism);
        this.fetcher = fetcher;
    }

    public List<Page> crawl(URI seed, int limit, Predicate<URI> allowed)
            throws InterruptedException {
        if (limit < 0) throw new IllegalArgumentException("negative limit");
        if (cancelled.get()) throw new IllegalStateException("crawler is cancelled");
        if (limit == 0) return List.of();
        CrawlSession session = new CrawlSession();
        if (!active.compareAndSet(null, session))
            throw new IllegalStateException("a crawl is already active");
        if (cancelled.get()) {
            active.compareAndSet(session, null);
            throw new IllegalStateException("crawler is cancelled");
        }
        Set<URI> seen = ConcurrentHashMap.newKeySet();
        List<Page> pages = new ArrayList<>();
        ExecutorCompletionService<Result> completions =
                new ExecutorCompletionService<>(workers, session.completed);
        int inFlight = 0;

        try {
            URI first = normalize(seed);
            if (!cancelled.get() && allowed.test(first) && seen.add(first)
                    && submit(first, completions, session)) {
                inFlight++;
            }

            while (inFlight > 0) {
                Future<Result> completed = completions.take();
                if (completed == session.cancelSignal) break;
                session.tasks.remove(completed);
                inFlight--;
                Result result;
                try { result = completed.get(); }
                catch (CancellationException cancelledTask) { continue; }
                catch (ExecutionException impossible) {
                    throw new IllegalStateException("worker wrapper failed", impossible.getCause());
                }
                if (result.failure() != null) continue;
                pages.add(result.page());
                for (URI rawLink : result.page().links()) {
                    if (seen.size() >= limit || cancelled.get()) break;
                    URI link;
                    try { link = normalize(result.uri().resolve(rawLink)); }
                    catch (IllegalArgumentException invalid) { continue; }
                    if (allowed.test(link) && seen.add(link)
                            && submit(link, completions, session)) {
                        inFlight++;
                    }
                }
            }
            return List.copyOf(pages);
        } finally {
            session.cancelTasks();
            active.compareAndSet(session, null);
        }
    }

    private boolean submit(URI uri, ExecutorCompletionService<Result> completions,
                           CrawlSession session) {
        if (cancelled.get()) return false;
        try {
            Future<Result> task = completions.submit(() -> {
                if (cancelled.get() || Thread.currentThread().isInterrupted())
                    return new Result(uri, null, new InterruptedException());
                try {
                    return new Result(uri, fetcher.fetch(uri), null);
                } catch (InterruptedException interrupted) {
                    Thread.currentThread().interrupt();
                    return new Result(uri, null, interrupted);
                } catch (Exception failure) {
                    return new Result(uri, null, failure);
                }
            });
            session.tasks.add(task);
            if (cancelled.get()) task.cancel(true);
            return true;
        } catch (RejectedExecutionException rejected) {
            if (cancelled.get()) return false;
            throw rejected;
        }
    }

    private static URI normalize(URI uri) {
        String raw = uri.toString();
        int fragment = raw.indexOf('#');
        return URI.create(fragment < 0 ? raw : raw.substring(0, fragment)).normalize();
    }

    public void cancel() {
        if (!cancelled.compareAndSet(false, true)) return;
        CrawlSession session = active.get();
        if (session != null) {
            session.cancelTasks();
            session.completed.offer(session.cancelSignal);
        }
        workers.shutdownNow();
    }

    @Override public void close() throws InterruptedException {
        cancel();
        if (!workers.awaitTermination(10, java.util.concurrent.TimeUnit.SECONDS)) {
            throw new IllegalStateException("crawler did not terminate");
        }
    }
}

    Races, linearization, and complexity¶

    seen.add is the deduplication linearization point and happens before submission by program order. Only the coordinator thread mutates pages and inFlight, avoiding extra locks. The loop terminates when no accepted work remains. For V scheduled pages and E discovered links, coordination is O(V + E) average with O(V) seen state; wall time approaches total fetch work divided by parallelism until remote latency, host limits, or a serial discovery frontier dominates.

    There is a deliberate limit nuance: seen.size() is checked by the sole coordinator, so it cannot overshoot. Failed pages still consume budget. If workers discovered and submitted links directly, check-then-add would overshoot unless admission used an atomic counter with rollback.

    Cancellation and shutdown¶

    cancel commits terminal cancellation, requests interruption of known tasks, and places a signal in the completion queue. Submission racing with cancellation checks again after registering its handle. The signal wakes a coordinator blocked in take, even if a queued task was removed by shutdownNow or a fetcher ignores interruption. It does not bound time spent in the caller-supplied allowed predicate or processing a large result; those must be short/bounded. The returned snapshot contains pages consumed by the coordinator before the signal, not every fetch that happened to finish. Worker termination still depends on cooperative, deadline-bounded fetches; close waits at most ten seconds and reports failure. Caller interruption propagates InterruptedException and cancels session tasks in finally; it does not imply those tasks have exited.

    URI normalization preserves raw escapes: /a%2Fb and /a/b are different resources under RFC 3986 section 2.2. Rebuilding from decoded getPath/getQuery silently merges them and can alter query delimiters. This implementation removes literal fragments and dot segments only; default ports, unreserved escapes, redirect bases, and host policy remain explicit extensions.

    Deterministic tests¶

    Create a fake graph-backed fetcher. Use latches to prove two independent URLs enter fetch concurrently. Include duplicate, relative, fragment-only, cyclic, malformed, off-policy, and failing links. Count fetches per normalized URI and assert at most one. Cancel while one fetcher honors interruption and another deliberately ignores it; assert crawl still returns promptly, then release the latter for cleanup. Separately interrupt the coordinator and assert InterruptedException, not a normal partial result. Use a deadline around every test to turn deadlocks into failures.

    Extensions and tradeoffs¶

    • Add per-host semaphores and delayed politeness scheduling.
    • Keep bounded frontiers and define whether overload blocks, drops, or persists URLs.
    • Separate retryable failures from permanent responses and budget retries.
    • Defend against SSRF by resolving and validating IP ranges on every redirect.
    • Persist frontier and leases for crash recovery; deduplication then needs durable identity.
    • Virtual threads can simplify blocking HTTP concurrency, but host limits and memory bounds remain necessary.

    Evaluation rubric (10 points)¶

    • 2: normalized atomic deduplication and explicit page-limit semantics;
    • 2: bounded worker ownership and completion-driven frontier;
    • 2: failure isolation and termination argument;
    • 2: cooperative cancellation, timeouts, and operational scope;
    • 2: deterministic graph, duplicate, concurrency, and cancellation tests.

    Summary¶

    • A strong concurrent LLD answer starts with API semantics and invariants, not classes.
    • Token buckets serialize one strict quota; partitioning changes the quota guarantee.
    • TTL cleanup must conditionally remove the exact entry it observed.
    • DAG composition naturally propagates dependency failure but needs explicit cancellation policy.
    • Event buses need snapshot and unsubscribe semantics plus bounded handler isolation.
    • Crawlers need atomic deduplication, bounded admission, policy filtering, and cooperative fetch cancellation.
    • Educational completeness is not operational production readiness; state the boundary honestly.
