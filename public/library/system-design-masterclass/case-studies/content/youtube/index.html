    Design YouTube¶

    1. Interview roadmap¶

    We design user video upload, processing, playback, discovery hooks, and moderation. We quantify bytes, define publication invariants, trace resumable upload and adaptive streaming, then examine transcoding, CDN delivery, counters, partitioning, failures, abuse, and L5/L6 expectations.

    2. Product framing and requirements¶

    Creators upload videos, edit metadata, publish with public/unlisted/private visibility, watch on varied networks, and delete content. Viewers receive adaptive playback, captions, thumbnails, likes, and delayed view counts. Search/recommendation are downstream interfaces, not fully designed here; live streaming and ads are excluded.

    SLOs: playback start p95 under 2 seconds on healthy broadband, rebuffer ratio under 1%, playback availability 99.99%, an illustrative annual retained-object durability objective of 99.999999999%, and p95 processing time under fifteen minutes after completion for ten-minute uploads. These are design targets, not verified YouTube service guarantees. Processing may be asynchronous, but no manifest may reference missing segments.

    3. Invariants¶

    1. A completed upload is checksum-verified and durable before acceptance.
    2. Publication exposes only an atomically selected, complete rendition manifest.
    3. Authorization is checked before private manifests or keys are issued.
    4. Source and renditions are immutable; edits create metadata/manifest versions.
    5. Upload completion, processing tasks, likes, and deletes are idempotent.
    6. View events never block playback and are not claimed exactly once.

    4. Capacity estimates¶

    Assume 5 million uploads/day averaging 300 MB: 1.5 PB/day ingress before replication. At 100 million hours watched/day and 3 Mbps average delivered bitrate, CDN egress is roughly 135 PB/day. Peak playback may reach 20 million concurrent sessions. Metadata for one billion videos at 3 KB is only 3 TB; media dominates cost. A ten-minute source may yield six bitrate/resolution ladders totaling about 2-3x source bytes. These numbers require direct object uploads, asynchronous compute, lifecycle tiers, and CDN offload above 95%.

    5. APIs and data model¶

    Canonical metadata controls lifecycle; object storage contains immutable bytes; CDN and counters are projections.

    7. Upload and processing flow¶

    The API allocates an upload with byte/part quotas and short-lived scoped URLs. Clients upload parts in parallel, resume by listing acknowledged checksums, then complete with an ordered part manifest. Completion verifies size, per-part checksum, final digest, and ownership; a transaction creates the video plus workflow outbox. Replays return the same video. Abandoned multipart data expires automatically.

    sequenceDiagram
    autonumber
  participant C as Creator
  participant A as Upload API
  participant O as Object store
  participant W as Workflow
  C->>A: create upload
  A-->>C: scoped part URLs
  C->>O: upload/resume checksummed parts
  C->>A: complete(parts, key)
  A->>O: verify composed source
  A->>A: commit video + outbox
  A-->>C: video ID, PROCESSING
  W->>O: transcode immutable source
  W->>A: atomically publish manifest

    Probe extracts duration/codecs; malware and policy scans run before public availability. A workflow DAG creates mezzanine if needed, bitrate ladder, audio, thumbnails, captions, and manifests. Tasks use deterministic output keys (video,pipeline,task) and conditional completion, so retries duplicate computation but not state. Publication verifies every object/checksum then swaps active_manifest_version atomically. Failed optional captions do not block video; failed mandatory scan or base rendition does.

    8. Playback and adaptive streaming¶

    Playback authenticates visibility, region/age rights, and policy, then returns a short-lived signed HLS/DASH master manifest. The player chooses a conservative initial bitrate and estimates throughput from segment downloads, increasing slowly and decreasing quickly while considering buffer occupancy. Two-to-six-second segments balance switching agility against request overhead. Seek maps to segment boundaries; resume position is an asynchronous user projection.

    sequenceDiagram
    autonumber
  participant V as Player
  participant P as Playback API
  participant C as CDN
  participant O as Origin shield
  V->>P: playback request
  P-->>V: signed manifest + policy expiry
  V->>C: manifest and segment
  alt cache hit
    C-->>V: segment
  else miss
    C->>O: coalesced origin fetch
    O-->>C: immutable segment
    C-->>V: segment
  end

    Segments are content-versioned and cache for months; manifests are shorter-lived. Multi-tier CDN with regional shields prevents origin stampedes. Signed cookies avoid one signature per segment. Popularity prediction prewarms launches; long-tail content stays pull-through. Origin failover uses replicated buckets and checksum validation.

    9. Domain deep dives¶

    Codec ladder: Build per-title ladders from complexity probes rather than fixed bitrates. Cap compute with presets; retain broadly supported H.264 while adding AV1 where expected egress savings exceed encode/storage/device costs. Never remove an old rendition until manifests no longer reference it.

    Views and engagement: Emit session/start/heartbeat/complete events. A policy-defined watch threshold counts a view; deduplicate by event/session within a window and filter bots. Counters are delayed, mergeable projections. Likes use a unique (user,video) row plus transactional outbox; displayed totals may lag.

    Deletion and reprocessing: Mark video unavailable first, revoke playback tokens within their bounded lifetime, purge manifests, then asynchronously erase renditions/source according to retention. Tombstone versions prevent late workflows from republishing. New codec pipelines build alongside old ones, shadow-check, atomically switch, and garbage-collect after token/cache expiry.

    10. Partitioning, consistency, and regions¶

    Hash metadata by video ID; index creator listings separately with cursors. A viral video is a CDN hot object, not a metadata-shard problem. Salt analytics partitions for viral IDs and merge partial aggregates. Queue partitions by video ID preserve workflow ordering, with priority/fairness so one creator cannot monopolize transcoders. Autoscale by queued media-minutes, codec, and GPU type, not task count.

    Metadata writes use home-region single ownership and synchronous multi-zone durability; media replicates asynchronously before regional publication. Playback is active-active from replicated metadata/CDN. Strong consistency is required for lifecycle/version swaps and unique likes; feeds, views, processing progress, and search are eventual. Dependency uncertainty returns unavailable, never a false deletion or privacy grant.

    11. Failure, security, and abuse¶

    Lost completion responses replay safely. Worker death re-leases tasks; poison files enter quarantine after bounded attempts. Queue outage leaves videos processing but does not impair existing playback. CDN failure routes to another provider or shield with traffic budgets. Object corruption is detected by checksums and repaired from replicas. Overload sheds thumbnail variants and new low-priority encodes before playback.

    Validate containers in sandboxes; cap duration, dimensions, decompression, and parser resources. Encrypt storage and transport, scope signed URLs by object/action/expiry, keep private media out of shared caches unless encrypted authorization is enforced, and audit staff access. Rate-limit uploads/comments/views; detect copyright matches, spam, synthetic views, harmful content, and coordinated reports. Appeals and legal holds are explicit states, not ad hoc database edits.

    12. Observability and testing¶

    Measure upload completion/checksum failures, processing latency by stage and media-minute, queue age, rendition success, publication lag, CDN hit/egress/origin load, playback start, fatal errors, bitrate, rebuffer ratio, policy denials, delete propagation, and cost per uploaded/watched minute. Correlate player QoE by ISP/device/codec without logging signed URLs.

    Test multipart resume, completion races, workflow replay, manifest referential integrity, ABR under network traces, malformed media fuzzing, authorization, and tombstone races. Load with Zipfian popularity. Chaos kills encoders, delays replicas, loses queue acknowledgments, corrupts segments, and evacuates CDN regions. Canary every pipeline version on a codec corpus before gradual publication.

    Cost-aware capacity and overload¶

    Transcoding is heterogeneous: a one-hour 4K AV1 job is not equivalent to a one-minute SD thumbnail task. Admission records normalized media-minutes and predicted CPU/GPU seconds. Separate queues by codec and hardware capability, reserve capacity for newly uploaded base renditions, and use weighted tenant fairness. During a celebrity upload burst, produce one widely compatible 360p/720p path first, publish only if product semantics allow partial ladders, then add premium renditions through new manifest versions. Backlog targets determine autoscaling, while maximum spot-instance share bounds interruption risk.

    Storage policy distinguishes source, mezzanine, published rendition, abandoned upload, and superseded pipeline output. Sources may move to colder tiers after processing but must remain recoverable for future codecs. Renditions with negligible watch time can be generated on demand only when startup risk and compute economics justify it. Chargeback dashboards show bytes stored, encoded, and delivered by tenant and codec.

    L6 transcoding control plane and deterministic recovery¶

    Represent each upload as a durable workflow execution keyed by (video_id, source_version, pipeline_version). Its DAG contains probe -> malware/policy scan -> complexity sample -> ladder plan -> parallel encode -> package -> verify -> publish; captions and thumbnails can branch after probe. A task record stores dependency versions, deterministic output key, attempt, lease owner/epoch, input checksum, encoder image digest, parameters, and terminal result checksum. A worker may commit only while holding the current lease epoch. Completion is a compare-and-set from RUNNING to SUCCEEDED, followed by an outbox event, so a lost acknowledgment causes a lookup rather than a second logical output.

    stateDiagram-v2
  [*] --> BLOCKED
  BLOCKED --> READY: dependencies satisfied
  READY --> LEASED: scheduler grants epoch
  LEASED --> RUNNING: worker starts
  RUNNING --> SUCCEEDED: checksum and QC pass
  RUNNING --> RETRY_WAIT: retryable failure
  RETRY_WAIT --> READY: deterministic backoff
  RUNNING --> QUARANTINED: poison input or attempt limit
  LEASED --> READY: lease expires
  RUNNING --> RETRY_WAIT: lease expires and stale completion fenced
  SUCCEEDED --> INVALIDATED: source or pipeline superseded
  INVALIDATED --> [*]
  QUARANTINED --> [*]

    Retries are deterministic at the artifact boundary, not necessarily bit-identical inside every encoder. The logical artifact key is a hash of source checksum, rendition specification, encoder digest, and pipeline version; workers write to an attempt-scoped temporary key, verify duration, segment alignment, decodeability, and checksum, then conditionally install the canonical key. A speculative duplicate either observes the installed result or loses the conditional write. Retry only transient classes such as worker loss, rate limits, or storage timeout; malformed media and repeatable decoder crashes are quarantined. Backoff is derived from task ID plus attempt so replay does not synchronize a fleet-wide retry storm.

    Partial ladders have an explicit publication policy. BASE_READY requires the baseline H.264 audio/video pair, aligned segments, thumbnails, policy approval, and rights state; only then may a manifest version expose 360p/720p. Optional 1080p, 4K, VP9, and AV1 tasks continue and produce a new immutable manifest version. A failed optional rung never leaves a dangling manifest reference. The controller stops retrying a rung when its predicted watch-value saving is below remaining encode cost, but failed mandatory outputs keep the video unpublished. Tombstone and source-version checks occur again at artifact commit and manifest swap, preventing a deleted or replaced upload from being resurrected.

    Per-title VMAF ladder and concrete ABR¶

    The ladder planner samples scene boundaries plus difficult motion, texture, and dark regions, then encodes short clips across resolution/bitrate candidates. It computes VMAF and encode cost per candidate, removes dominated points, enforces device/codec floors, and chooses rungs whose quality gain exceeds a threshold such as 4 VMAF while bitrate grows by roughly 1.4x to 2x. Per-title constraints cap maximum source resolution, reject upscaling, preserve a low-bandwidth rung, and account for grain or animation where aggregate VMAF can mislead. Periodic subjective review calibrates VMAF thresholds, and planner/metric versions are recorded so a ladder can be reproduced.

    For example, a 1080p animation probe might produce (360p, 0.35 Mb/s, VMAF 82), (480p, 0.60, 90), (720p, 1.10, 95), (1080p, 1.80, 97), and (1080p, 3.00, 98). The 3 Mb/s point costs 67% more for one VMAF point and is removed; a noisy sports title might retain 0.5, 1.2, 2.8, and 5.5 Mb/s instead. If one million viewing hours move from a fixed 3 Mb/s rendition to an equal-quality 1.8 Mb/s rendition, delivery falls by about 540 TB (1.2 Mb/s * 3,600 s * 1,000,000 / 8), easily justifying extra analysis encodes for a popular title.

    At each segment boundary the client maintains harmonic-mean throughput over the last five successful downloads, applies a 15% safety margin for uncertainty, and combines it with buffer state. Let safe_bw = 0.85 * harmonic_mean; choose the highest rung below safe_bw, but use these guards: below 8 seconds of buffer, step down immediately; from 8 to 20 seconds, never step up; above 20 seconds, step up only one rung after two consecutive eligible segments; above 35 seconds, normal selection applies. Abandon an in-flight segment if its projected completion would drain the buffer and a lower rung can arrive sooner. Startup chooses a device/region prior capped at 720p and measures from the first media segment.

    Numerically, samples of 6, 5, 4, 3, and 2 Mb/s have a harmonic mean near 3.45 Mb/s and safe_bw near 2.93 Mb/s. With 24 seconds buffered the player selects at most a 2.8 Mb/s rung and requires two confirmations before switching up; if the latest throughput drops to 1.4 Mb/s and buffer reaches 7 seconds, emergency selection caps the rolling estimate by that latest sample, so it immediately selects a rung below 1.19 Mb/s. Operations compare rebuffer ratio, start time, bitrate, switch frequency, and watch abandonment by player algorithm cohort; a QoE regression automatically halts rollout independently of server health.

    Rights lifecycle and media capacity¶

    Rights are versioned intervals and predicates over owner, territory, age, product surface, monetization mode, device class, and allowed operations. The lifecycle is DRAFT -> SCHEDULED -> ACTIVE -> EXPIRED, with side transitions to BLOCKED, TAKEDOWN_PENDING, TAKEN_DOWN, APPEALED, and REINSTATED. Upload ownership does not imply universal playback rights. Playback binds the policy version and earliest rights expiry into a short-lived token; emergency takedown increments a deny epoch consumed by manifest authorization and token refresh. Every segment request, including a cache hit, must validate the scoped access token/cookie and its current policy or documented expiry bound; withholding the manifest alone does not protect a known segment URL. Encryption with controlled key delivery can provide an additional boundary. Previously downloaded or decrypted bytes cannot be recalled, and purge is defense in depth. Legal holds preserve evidence without making content playable, and every automated match, manual override, appeal, and territorial change is append-only audited.

    Capacity uses media-seconds by codec/preset and delivered bitrate by geography. Suppose peak ingest is 500 hours/minute and the mix is 70% short H.264 at 6x real time, 20% HD VP9 at 1.5x, and 10% 4K AV1 at 0.25x. One minute of arrivals needs 350/6 + 100/1.5 + 50/0.25 = 325 encoder-hours, or 19,500 encoder-minutes. Sustaining arrivals therefore requires 19,500 continuously busy equivalent workers; at 65% target utilization and an additive 25% capacity margin, provision 19,500 / 0.65 * 1.25 = 37,500 worker equivalents. These rates cover one output path per input; producing multiple rungs adds their encode work. Scheduler reservations guarantee baseline H.264, while premium codecs consume elastic or spot capacity and are shed first.

    CDN planning starts with peak traffic, cache hit, and shield amplification. Ten million concurrent viewers averaging 2.5 Mb/s require 25 Tb/s edge egress. At a 97% edge hit ratio, naive miss traffic is 750 Gb/s; regional shields with a 90% hit ratio reduce origin to about 75 Gb/s. Capacity must still reserve for correlated cold misses, so origin and inter-CDN failover are tested at a lower assumed edge hit such as 90%, not the steady-state average. Operators alarm on queued media-minutes by hardware class, deadline miss forecast, lease churn, QC failure fingerprint, partial-ladder age, edge/shield hit ratio, origin saturation, and rights-deny propagation. During shortage: protect playback, takedowns, and baseline encodes; pause backfills; then shed premium ladders and nonessential derivatives. A regional CDN evacuation uses weighted traffic ramps and origin budgets rather than instant global failover.

    Metadata and discovery integration¶

    Search and recommendation consume a transactional outbox event containing video ID, metadata version, policy state, and active manifest version. They are projections and may lag; playback still checks canonical visibility. Title edits coalesce, while delete/block events use priority lanes. A subscriber stores the greatest version per video, making redelivery and reordering harmless. Thumbnail URLs include content versions so updates do not rely on global cache purge.

    Comments and subscriptions would be separate bounded contexts: they can fail without affecting playback. This boundary prevents a broad social-product outage from consuming upload or playback pools and gives each feature an independent abuse model.

    13. Tradeoffs and final design¶

    Proxy uploads simplify clients but make API bandwidth the bottleneck; direct scoped multipart upload wins. Synchronous transcoding gives immediate answers but couples latency and expensive compute; durable workflows win. One universal ladder is operationally easy but wastes quality/bytes; per-title encoding is justified at watch scale.

    Final design: direct verified upload to immutable object storage, transactional metadata/outbox, idempotent DAG transcoding, atomic complete-manifest publication, policy-gated signed playback, adaptive segmented delivery through multi-tier CDN, and asynchronous engagement. Immutable versions make retries, rollback, replication, and deletion races tractable.

    • How does completion avoid publishing partial multipart data?
    • How would live streaming alter manifests and latency?
    • When is AV1 economically justified?

    • Which QoE signal matters more than server latency?

    15. Level expectations¶

    L5 candidates should separate upload, processing, storage, metadata, CDN, and analytics; design resumability, ABR, retries, hot-video delivery, and privacy. L6 candidates should quantify media economics, model workflow state/fencing, define publication/deletion bounds, plan codec migrations, regional rights, overload priorities, moderation operations, and client-observed QoE.

    16. Five-minute summary¶

    Media bytes dominate: direct checksummed multipart uploads into object storage and asynchronously transform immutable sources. Completion atomically creates canonical video state and an outbox; deterministic workflow tasks probe, scan, transcode a per-title bitrate ladder, create thumbnails/captions, verify artifacts, then swap a complete manifest version. Playback authorizes and returns short-lived HLS/DASH access; players adapt bitrate while CDN/shields serve immutable segments at above 95% hit rate.

    Hash metadata by video, salt viral analytics, scale encoders by queued media-minutes, and preserve fair capacity. Lifecycle swaps are strongly consistent; views and progress are eventual/idempotent. Deletion marks unavailable first and tombstones the version before purge, defeating stale workers. Protect parsers, URLs, private cache behavior, moderation, and synthetic metrics. Operate from player QoE, publication lag, queue age, origin load, and cost per watched minute.
