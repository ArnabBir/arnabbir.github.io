    Metrics Monitoring Platform¶

    1. Interview roadmap¶

    We will design a platform that ingests numeric time series, supports dashboards and ad hoc queries, and evaluates alerts. We define cardinality and alert correctness first, estimate points and storage, separate metadata/control functions from ingestion/query data planes, then explore write routing, compression, downsampling, query fan-out, alert evaluation, and multi-region operation.

    2. Product framing¶

    Services emit counters, gauges, histograms, and summaries tagged with dimensions such as region and status. Engineers query recent high-resolution data, retain coarse history, build dashboards, and receive alerts. Metrics favor aggregate numerical analysis over exact event retrieval. Logs and traces are linked but stored elsewhere. The platform may drop low-priority telemetry under extreme overload; it must make loss visible and protect critical alerts.

    3. Requirements¶

    Functional requirements:

    • Ingest tagged samples through push and scraping gateways.
    • Query selectors, ranges, aggregations, rates, percentiles, and groupings.
    • Define recording rules, dashboards, and alert rules with routing and silences.
    • Discover metric names and labels with tenant isolation.
    • Apply retention, downsampling, quotas, and deletion policies.

    Non-functional requirements:

    • 20 million samples/s peak, 100 million active series, 30-day raw and 13-month downsampled retention.
    • Ingest acknowledgment p99 under 500 ms; dashboard query p99 under 3 seconds.
    • Alerts evaluated every 30 seconds with under 60-second notification delay.
    • 99.99% ingest availability and explicit completeness indicators.

    Arbitrary log search and exact billing are out of scope.

    4. Correctness invariants¶

    1. Tenant A cannot write, discover, query, or alert on tenant B's series.
    2. A series identity is metric name plus a canonical sorted label set.
    3. Duplicate samples with the same series and timestamp resolve deterministically; retries do not multiply counters.
    4. Query results identify partial data rather than silently presenting it as complete.
    5. Alert state transitions use a stable rule version and suppress duplicate notifications within the configured policy.
    6. Retention and deletion eventually remove all indexed and object data within a stated compliance SLO.

    5. Capacity estimates¶

    At 20 million samples/s and an effective 2 bytes/sample after delta-of-delta timestamps, XOR values, and block compression, samples require 3.5 TB/day. Indexes, labels, replicas, and object overhead can triple that to roughly 10 TB/day raw. Thirty days is 300 TB. Ingest batches of 1,000 samples reduce request rate to 20,000/s. One hundred million active series at 200 bytes of head metadata require 20 GB logical, distributed and replicated. A dashboard with 20 panels, each scanning 10,000 series over 1,000 points, could process 200 million points; query budgets and recording rules are mandatory.

    6. Data model¶

    Series(tenant_id, fingerprint, metric_name, labels, created_at)
Sample(series_id, timestamp_ms, value)
Block(tenant_id, shard, min_time, max_time, object_uri, checksum,
      resolution, compaction_level)
RuleGroup(group_id, tenant_id, interval, version, rules[], owner)
AlertInstance(rule_id, label_fingerprint, state, active_since,
              last_evaluated, last_notified, value)

    Recent mutable samples live in write-ahead logs and in-memory head blocks. Immutable compressed blocks in object storage are canonical for retained history. A metadata index maps label matchers and time ranges to series and blocks. Rule definitions are canonical in a transactional control database.

    7. Interfaces¶

    POST /v1/metrics:write              Content-Encoding: snappy
GET  /v1/query?expr=&time=
GET  /v1/query_range?expr=&start=&end=&step=
GET  /v1/labels/{name}/values?match=&cursor=
PUT  /v1/rule-groups/{id}           If-Match: version
POST /v1/silences

    Write batches include tenant identity, source ID, sequence, and samples. Responses report accepted, rejected, and throttled counts. Queries carry deadlines, maximum resolution, and partial-response policy. Pagination uses label/value cursors. Remote-read and remote-write protocols support agents, but server-side limits override client hints.

    8. High-level architecture¶

    flowchart LR
  Agents --> Gateway[Regional ingest gateways]
  Gateway --> Distributor
  Distributor --> Ing1[Ingester shards]
  Distributor --> Ing2[Ingester replicas]
  Ing1 --> Obj[(Object storage blocks)]
  Ing2 --> Obj
  Query[Query frontend] --> Qry[Query workers]
  Qry --> Ing1
  Qry --> Obj
  Qry --> Index[(Series/block index)]
  Rules[Rule evaluators] --> Query
  Rules --> Notify[Notification router]
  Control[Control plane] --> Gateway
  Control --> Rules

    The control plane manages tenants, quotas, schemas, rule versions, and placement. The write data plane validates and shards samples. The query data plane plans and merges reads. Immutable object blocks decouple compute from storage, while recent heads supply low latency.

    9. Ingestion hot path¶

    Gateways authenticate, decompress with ratio limits, normalize labels, reject timestamps beyond allowed skew, and enforce samples, bytes, and active-series quotas. A fingerprint hashes the canonical label set for routing/indexing, but full tenant, metric name, and labels are retained and compared so a hash collision cannot merge distinct series. Distributors use consistent hashing to send each series to a replication set. An acknowledgment requires a configurable quorum of ingesters to append to local WAL; asynchronous object upload is not on the hot path.

    Ingester heads append ordered chunks. Slightly out-of-order samples fit a bounded reorder window; older samples enter a separate patch block or are rejected. Duplicate timestamp policy is deterministic, such as the maximum (source_generation, source_sequence, source_id) under a specified total ordering for that series, with ties requiring identical bytes. Local arrival order at independent replicas is not deterministic; alternatively reject conflicting writers under a fenced single-source contract. WAL segments replicate across zones and replay after restart. Once a time window closes, ingesters encode immutable blocks, upload them, and publish metadata.

    10. Compression, compaction, and retention¶

    Within a series chunk, delta-of-delta compresses regular timestamps and XOR encoding compresses slowly changing floating values. Blocks contain postings indexes for label pairs, chunk metadata, bloom filters where useful, and checksums. Background compactors merge small overlapping blocks, deduplicate samples, and produce larger non-overlapping blocks per shard and time range. Compaction uses leases and output manifests so duplicate workers are harmless.

    Downsampling generates 1-minute and 1-hour aggregates including count, sum, min, max, and mergeable histogram buckets. Averages alone lose weighting; percentiles cannot be averaged. Lifecycle rules delete raw blocks after 30 days and retain aggregates. Tombstones hide deleted series immediately from queries; compaction physically removes bytes later.

    Downsampling is type-specific. A counter needs reset-aware increases and boundary samples; the arithmetic mean or sum of cumulative counter readings cannot reconstruct its rate. Histogram buckets must use compatible boundaries or an explicit common coarsening before merging, and a summary's precomputed quantiles are not aggregatable. These boundaries follow Prometheus histogram/summary guidance (accessed 2026-09-08). If a retained tier lacks the required information, reject or label an approximate query rather than claim raw-resolution equivalence.

    11. Query planning and execution¶

    The frontend parses and bounds the expression, chooses raw or downsampled resolution based on requested step, and splits long ranges by time and series shard. Workers fetch postings, prune blocks, scan chunks, execute vector operations, and stream partial aggregates to a reducer. Associative functions such as sum push down well; non-associative operations retain sufficient intermediate state.

    Cache immutable block indexes, query plans, and final results keyed by tenant, expression, range, step, and block generation. Recent ranges are not cached long. Deduplicate concurrent identical dashboard queries. Enforce scanned-series, samples, wall-time, and concurrency budgets; return a typed limit error rather than exhaust the cluster.

  Parse --> Plan[Choose resolution and split]
  Plan --> S1[Recent head query]
  Plan --> S2[Object block shard 1]
  Plan --> S3[Object block shard N]

  S2 --> Merge
  S3 --> Merge
  Merge --> Result[Result + completeness metadata]

    12. Alerting and recording rules¶

    Rule groups are assigned by consistent hash to evaluators with fenced leases. One evaluator executes a group sequentially at each interval against a fixed rule version and evaluation timestamp. Recording rules write derived series back with source and timestamp deduplication. Alert conditions progress inactive -> pending -> firing; for: 5m requires continuous true evaluations, with an explicit tolerance for missing evaluations. Missing or partial data is an explicit unknown state, not an implicit healthy result; each rule defines whether to hold state, reset its pending timer, or emit a separate telemetry-loss alert.

    Notification routers group by labels, inhibit child symptoms, apply silences, and deduplicate using (alert fingerprint, state, route, repeat interval). They persist a pending delivery intent before sending, then record confirmed or unknown outcome. Marking an intent delivered before the network call can lose the alert on crash; an unknown response may duplicate unless the receiver honors the same idempotency key. HA evaluator replicas may both send during partitions; router deduplication bounds duplicates.

    13. Cardinality, partitioning, and overload¶

    Partition writes by tenant and series fingerprint, with many virtual tokens and zone-aware replicas. Object blocks also include time windows so queries parallelize. One high-volume series cannot split naturally; enforce per-series sample rates or shard instrumentation counters with an explicit aggregation label. Cardinality explosions usually come from labels such as request ID. Gateways maintain sketches and per-label budgets, reject new series before existing ones, and show top contributors.

    Under overload, preserve critical tenants and rule queries, then interactive dashboards, then bulk queries. Drop or sample explicitly designated low-priority metrics at gateways and increment durable loss counters outside the affected path. Backpressure agents through retry-after and bounded local buffers; never permit unbounded queues.

    14. Consistency and idempotency¶

    Writes are quorum durable in recent replicas, then eventually visible in object blocks. Queries merge heads and blocks by series/timestamp and deduplicate overlap during compaction. A write retry with the same source sequence is ignored; without a sequence, identical timestamp/value duplicates collapse but conflicting values follow documented policy. Metadata discovery may lag samples.

    Rule updates use optimistic concurrency and take effect atomically per group. An evaluation captures rule version and data cutoff. Alert notifications are at least once with deduplication, not exactly once. Query responses include watermark and missing-shard warnings.

    15. Failures and recovery¶

    • Agent disconnect: bounded disk buffer and age-based shedding; expose dropped samples.
    • Ingester crash: quorum replicas serve; WAL replay restores head; ring tokens remain fenced.
    • Object store slowdown: retain closed blocks locally within a limit and throttle low-priority ingestion before disk fills.
    • Index corruption: rebuild from immutable block manifests.
    • Compactor duplication: deterministic output ranges and manifest compare-and-swap select one result.
    • Query worker loss: retry only failed shards within deadline and mark partial when allowed.
    • Rule evaluator loss: lease reassignment may repeat an evaluation; stable timestamps deduplicate outputs.
    • Notification provider outage: bounded durable retry queues and escalation-channel isolation.

    16. Multi-region strategy¶

    Agents write to the nearest region and optionally duplicate critical series to a second region. Independent regional ingestion avoids WAN dependence. Global object storage replication provides disaster recovery, but block catalogs include region and generation to avoid double counting. Global queries fan out only when requested and merge by replica labels or deduplication metadata.

    Alert rules normally evaluate in one home region against local data. A standby evaluates in shadow and takes over after a fenced epoch. For region-loss alerts, an external witness monitors both regions. Control metadata replicates, while tenant residency policies constrain metric movement.

    17. Security and abuse prevention¶

    Use workload identity and tenant claims at every hop, encryption in transit and at rest, and scoped object-store credentials. Label and expression parsers have depth, regex, and expansion limits. Prevent query-of-death patterns before execution through cost estimation. Audit rule, silence, dashboard permission, and retention changes. Metrics often leak customer IDs in labels, so provide linting, hashing guidance, deletion, and restricted metadata discovery.

    18. Observability and testing¶

    The monitoring system must monitor itself through an independent minimal path. Track accepted/dropped samples, active-series churn, WAL fsync latency, replication shortfall, block upload and compaction lag, query scanned samples, cache efficacy, partial responses, rule lateness, alert delivery, and tenant quota rejection. Synthetic canary series traverse write, query, rule, and notification paths.

    Property tests cover label canonicalization and block merge deduplication. Golden tests validate query semantics and downsample equivalence. Load tests model churn and adversarial regex, not only steady counters. Fault tests kill ingesters after acknowledgment, corrupt blocks, delay object storage, and partition evaluators. Shadow rule evaluation compares versions before rollout. Restore drills rebuild indexes solely from object manifests.

    19. Tradeoffs and final design¶

    Quorum WAL acknowledgment balances durability and latency; object-store acknowledgment would be slower. Local storage databases simplify reads but couple retention to compute. Immutable blocks reduce cost and enable independent query scaling. Precomputed recording rules spend write/storage to reduce repeated query cost. High availability alert replicas increase duplicate risk. Downsampling saves cost but cannot reconstruct raw quantiles.

    The final design uses regional gateways, a consistent-hash replicated ingester ring with WAL-backed heads, immutable object blocks, separate metadata indexes, horizontally scaled query workers, and fenced rule evaluators. Control-plane quotas and versions are off the sample hot path. Completeness metadata, tiered overload, and independent synthetic monitoring make degradation visible.

    20. Interview questions and expectations¶

    Questions: Why is cardinality more dangerous than sample rate? How do heads and compacted blocks avoid duplicates? How do you compute percentiles after downsampling? What protects alerts when query traffic spikes? How is partial data represented? What changes for out-of-order samples?

    An L5 candidate should estimate samples and storage, shard series, batch writes, compress data, build range queries, and explain alerts. An L6 candidate should budget cardinality, separate planes and workloads, design completeness semantics, compaction fencing, regional alert ownership, cost controls, deletion, and self-monitoring independence.

    21. Five-minute summary¶

    The platform ingests 20 million tagged samples per second into regional gateways that authenticate, canonicalize labels, enforce cardinality quotas, and route each series to zone-replicated ingesters. Quorum WAL append acknowledges writes; recent head chunks later become compressed immutable object blocks. Compactors deduplicate, merge, downsample with mergeable statistics, and enforce retention. Query frontends estimate cost, choose resolution, split by time and series shard, merge heads with blocks, and report partial results explicitly. Fenced evaluators run versioned rule groups; notification routers group and deduplicate alerts. Independent regions avoid WAN coupling, with home-region alert ownership and replicated blocks for recovery. Priority isolation protects alerts from expensive dashboards. Synthetic end-to-end series, adversarial-cardinality tests, and restore drills verify the design.
