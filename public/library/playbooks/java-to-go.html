Module 01 / Start thinking in Go

Lesson 001
A program without a class

FoundationCore / Go 1.23+

Go lets you start with a function. An executable uses package main and a function named main. The usual Go toolchain builds a native executable; a Go runtime still provides services such as garbage collection.

Your Java bridge

Think of main as your Java entry point, but without a surrounding Main class. Native compilation does not mean there is no runtime.

Complete program
package main

import "fmt"

func main() {
    fmt.Println("Hello, Go learner!")
}

Notice: Println writes the greeting followed by a newline. The capital P also matters: it makes the name accessible from another package.

Avoid this trap

Do not begin by inventing a class hierarchy. Start with the data and the functions you need.

Try it before moving on

Change the program so it prints two separate lines: Java first, then Go.

Reveal the answer

Call fmt.Println twice, in order. You do not need a second class, object, or method.

Go
fmt.Println("Java")
fmt.Println("Go")

Lesson 002
Your first five commands

FoundationCore / Go 1.23+

Use a supported Go toolchain from the official installation page. Save lesson 1 as main.go in a new folder. The commands below create a module, format code, run it, build it, and test packages.

Your Java bridge

go.mod has some of the dependency-management role of a Maven pom. go test and go build are standard tools, not framework features.

Shell commands
go mod init example.com/hello
go fmt ./...
go run .
go build -o hello .
go test ./...

Notice: Run these inside the project folder. On Windows the executable may be named hello.exe. No tests yet is different from failing tests.

Avoid this trap

go run compiles and runs; it is not an interpreter. Do not repeatedly initialize a module that already has go.mod.

Try it before moving on

Which command creates an executable without starting it? Which command reports the installed Go version?

Reveal the answer

go build creates the executable. go version prints the toolchain version. Use go help to inspect commands locally.

Lesson 003
Package is not module

FoundationCore / Go 1.23+

A package is a set of source files compiled together, normally in one directory. A module is a versioned collection of packages rooted at go.mod. Imports identify packages, not individual files.

Your Java bridge

A Java package can span a project. In Go, directory boundaries are central: two subdirectories are two packages, even if their package clauses use the same name.

Concept sketch
hello/
  go.mod                 # module example.com/hello
  main.go                # package main
  greeting/
    greeting.go          # package greeting

Notice: The main package imports example.com/hello/greeting. It does not import greeting.go.

Avoid this trap

Do not put package main and package greeting in the same directory. External test packages are a special testing convention taught later.

Try it before moving on

If the module path is example.com/shop, what is the import path for a package in the tax directory?

Reveal the answer

example.com/shop/tax. The module path supplies the prefix; the subdirectory supplies the suffix.

Lesson 004
Declare versus assign

FoundationCore / Go 1.23+

var can declare variables at package scope or inside functions. Inside a function, := declares variables and infers their types. = changes existing variables. Type inference is still static typing.

Your Java bridge

Java var is the nearest analogy to inferred local types. In Go the short declaration uses :=, not a keyword.

Function body
count := 2
count = 5
count, limit := 7, 10
fmt.Println(count, limit)

Imports for the snippet: fmt.

Notice: This prints 7 10. The last declaration reuses count in this block and introduces limit.

Avoid this trap

:= requires at least one new non-blank variable in the same block. A variable in an outer block may instead be shadowed.

Try it before moving on

After x := 1, can you write x := 2 in the same block? Repair it.

Reveal the answer

No: there is no new variable. Use x = 2. The distinction helps you notice where storage is introduced.

Go
x := 1
x = 2

Lesson 005
Zero values are useful

FoundationCore / Go 1.23+

A variable declared without an initializer gets its type's zero value. Numbers become zero, booleans false, strings empty, and pointers, slices, maps, channels, functions, and interfaces nil.

Your Java bridge

Java requires definite assignment for local variables. Go gives locals zero values, but a zero value is not automatically useful for every operation.

Function body
var count int
var ready bool
var name string
var p *int
fmt.Printf("%d %t %q %v\n", count, ready, name, p)

Imports for the snippet: fmt.

Notice: The result is 0 false "" <nil>. %q makes the empty string visible.

Avoid this trap

A nil map can be read but not assigned an entry. A nil channel blocks on send or receive. You will practice both later.

Try it before moving on

What is the zero value of a struct containing an int and a bool?

Reveal the answer

Each field gets its own zero value: 0 and false. Zero initialization applies recursively to structs and arrays.

Lesson 006
Numbers do not silently widen

FoundationCore / Go 1.23+

int and int64 are different types. Convert explicitly before mixing typed numeric values. int has 32 or 64 bits, depending on the implementation. For a fixed-width representation, choose a fixed-width type.

Your Java bridge

Java can promote int to long in an expression. Go makes the conversion visible. Both languages have integer division when both operands are integers.

Function body
var a int = 7
var b int64 = 2
fmt.Println(int64(a) + b)
fmt.Println(a / 2)
fmt.Println(float64(a) / 2)

Imports for the snippet: fmt.

Notice: The output is 9, then 3, then 3.5. Converting after integer division would be too late.

Avoid this trap

Explicit conversion is not a range check. Narrowing integers can lose information; converting a runtime float to int truncates toward zero. ++ is a statement, not an expression.

Try it before moving on

For x := 257, what does uint8(x) produce? Does const x = 257 allow the same conversion?

Reveal the answer

The variable conversion produces 1. Converting the constant to uint8 fails at compile time because 257 is not representable.

Lesson 007
Constants and typed states

FoundationCore / Go 1.23+

A const value is computed at compile time. An untyped constant can fit different numeric contexts if its value is representable. iota is a counter inside a constant declaration, not a Java-style enum object.

Your Java bridge

final prevents reassignment, but a Java final value need not be a compile-time constant. Go const is more restrictive.

Function body
type Status int
const (
    Pending Status = iota
    Running
    Done
)
fmt.Println(Pending, Running, Done)

Imports for the snippet: fmt.

Notice: The values are 0 1 2, all with the defined type Status. A separate String method could provide readable labels.

Avoid this trap

Status(99) is still possible. Validate values from outside the program. Renumbering iota values can break stored or wire representations.

Try it before moving on

Can const started = time.Now() compile? What should you use instead?

Reveal the answer

No. time.Now runs at runtime. Use started := time.Now() in a function, or an appropriately initialized var.

Lesson 008
If and early return

FoundationCore / Go 1.23+

An if condition must be boolean. Parentheses are optional; braces are required. A short setup statement before the semicolon can keep a temporary variable local to an if and its else branch.

Your Java bridge

This resembles Java if, but there is no ternary operator. Prefer a small if or a helper function instead of a clever substitute.

Function body
if n := len("go"); n > 0 {
    fmt.Println("length:", n)
} else {
    fmt.Println("empty")
}

Imports for the snippet: fmt.

Notice: This prints length: 2. n is not available after the if statement.

Avoid this trap

Keep the opening brace on the same line. Go inserts semicolons at many line endings.

Try it before moving on

Write an if that prints "valid" only when age is at least 18 and active is true.

Reveal the answer

Use && for short-circuit AND. You do not need active == true.

Go
if age >= 18 && active {
    fmt.Println("valid")
}

Lesson 009
Switch without surprise fallthrough

FoundationCore / Go 1.23+

A switch chooses one matching case. It does not automatically run the next case. A switch without an expression is a clean way to select the first true condition.

Your Java bridge

Unlike traditional Java colon-style switch statements, you normally do not write break after every case.

Function body
score := 75
switch {
case score >= 90:
    fmt.Println("excellent")
case score >= 60:
    fmt.Println("pass")
default:
    fmt.Println("retry")
}

Imports for the snippet: fmt.

Notice: Only pass is printed. Case order matters when conditions overlap.

Avoid this trap

fallthrough exists but deliberately executes the next case body without checking its expression. Do not use it just because an older Java habit suggests it.

Try it before moving on

What happens if the score >= 60 case comes before score >= 90 and score is 95?

Reveal the answer

The earlier case wins, so it prints pass. Put more specific conditions before broader ones.

Lesson 010
For is also while

FoundationCore / Go 1.23+

Go has one looping keyword: for. It supports a three-part loop, a condition-only loop, and an unbounded loop. You can often translate a Java while directly into a condition-only for.

Your Java bridge

Java has for, while, and do-while. Go has no dedicated while or do-while keyword.

Function body
n := 3
for n > 0 {
    fmt.Println(n)
    n--
}
for i := 0; i < 2; i++ {
    fmt.Println("i", i)
}

Imports for the snippet: fmt.

Notice: The first loop prints 3, 2, 1. The second prints i 0 and i 1.

Avoid this trap

for {} runs until something exits it. A server loop must still have a shutdown plan.

Try it before moving on

Write a condition-only loop that doubles n, starting at 1, until n is at least 16.

Reveal the answer

Update n inside the body so the condition eventually becomes false.

Go
n := 1
for n < 16 {
    n *= 2
}

Lesson 011
Range gives you copies

FoundationCore / Go 1.23+

When ranging over a slice, the first result is its index and the second is a copy of the element. Use _ to discard an unwanted result. To change a slice element, use the index.

Your Java bridge

Java enhanced-for also gives you a local variable. In Go, a struct element is copied; changing that local struct does not update the slice.

Function body
nums := []int{2, 4, 6}
for _, n := range nums {
    n *= 10
}
for i := range nums {
    nums[i] *= 10
}
fmt.Println(nums)

Imports for the snippet: fmt.

Notice: The output is [20 40 60]. Only the second loop changes the slice.

Avoid this trap

With Go 1.22+ language semantics, loop variables declared with := are per iteration. Predeclared variables assigned with = are still reused.

Try it before moving on

How would you print only the values, without the index?

Reveal the answer

Use for _, n := range nums and print n. Discarding a value does not change what the range expression iterates over.

Lesson 012
Break, continue, and labels

FoundationCore / Go 1.23+

continue skips the rest of the current iteration. break leaves a loop or switch. A label lets you target an outer loop, but a helper function is often easier to read.

Your Java bridge

Go labels are comparable to Java labeled breaks. They are not an invitation to write complicated jumps.

Function body
outer:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if i+j == 2 {
            fmt.Println(i, j)
            break outer
        }
    }
}

Imports for the snippet: fmt.

Notice: The first matching pair is 0 2. break outer leaves both loops.

Avoid this trap

A plain break inside a switch nested in a loop leaves the switch, not the loop. goto exists with restrictions; avoid it in ordinary application logic.

Try it before moving on

What changes if break outer becomes an unlabeled break?

Reveal the answer

Only the inner loop ends. The outer loop continues, so later pairs can also be printed.

Lesson 013
Shadowing changes which variable you mean

FoundationCore / Go 1.23+

A declaration in an inner block may create a new variable with the same name as an outer variable. That is shadowing, not reassignment. Read := especially carefully near error handling.

Your Java bridge

Go permits common forms of local shadowing that Java rejects for nested local scopes. Do not assume the same name means the same storage.

Function body
name := "outside"
if true {
    name := "inside"
    fmt.Println(name)
}
fmt.Println(name)

Imports for the snippet: fmt.

Notice: This prints inside and then outside. Replacing the inner := with = would change the outer variable.

Avoid this trap

An inner err := can hide a named return error. Prefer explicit return values instead of relying on a distant named error variable.

Try it before moving on

How do you update the outside variable from the inner block?

Reveal the answer

Use name = "inside". Assignment searches for the visible existing variable instead of declaring a new one.

Lesson 014
A string is bytes, not a character array

FoundationCore / Go 1.23+

A Go string is an immutable sequence of bytes. len counts bytes, and indexing returns a byte. Text is commonly UTF-8, but a string can contain arbitrary bytes, including invalid UTF-8.

Your Java bridge

Java String APIs are based on UTF-16 code units. Neither Java length nor Go len is automatically the number of characters a reader sees.

Function body
s := "café"
fmt.Println(len(s))
fmt.Printf("%x\n", s[3])
fmt.Println(len([]rune(s)))

Imports for the snippet: fmt.

Notice: café occupies five UTF-8 bytes. Its fourth byte is c3. The rune conversion has four code points.

Avoid this trap

You cannot assign s[0] = 'C'. Convert to mutable bytes or runes, edit, and create a new string.

Try it before moving on

For s := "Go", what are len(s) and s[0]? Which formatting verb displays the byte as a character?

Reveal the answer

Java to Go / Values and types

Class and constructor

Go: a struct for data, methods for behavior, and ordinary functions such as NewStore for construction. There is no special constructor syntax or automatic class hierarchy.

Reference semantics

Java passes values, including object-reference values. Go also passes values. A copied Go struct copies its fields; a copied pointer, slice, or map value can still lead to shared data. Copy is not automatically deep copy.

Null and zero

Go has type-specific zero values. nil is available only for certain types, such as pointers, maps, slices, channels, interfaces, and functions. A string zero value is an empty string, not nil.

Inheritance and interfaces

Go favors composition and embedding. Interfaces are satisfied by method sets, without implements. Embedding promotes members; it does not create a Java-style subtype hierarchy.

Generics

Go type parameters use constraints. They are not Java use-site wildcards. Prefer a concrete function until a type relationship needs to be expressed. Version-specific generic methods are discussed in lesson 64.

GLOSSARY

Vocabulary / Data and APIs

Backing array

The element storage a slice describes. Two different slice values can refer to the same storage.

Capacity

For a slice, the extent to which it can grow from its current start without requiring a larger backing array. Length is the number of currently visible elements.

Defined type and alias

A defined type introduces a distinct type. An alias names an existing type without creating a new one. byte is an alias of uint8; rune is an alias of int32.

Method set

The methods associated with a type for operations such as interface satisfaction. A value type and its pointer type can have different method sets.

Receiver

The explicit value or pointer placed before the method name in its declaration. It is the value before the dot at the call site, not the return type.

Constraint

An interface used to describe allowed type arguments. Constraint-only interfaces with type terms are not ordinary runtime value types.

Zero value

The initial value produced when a variable has no explicit initializer. A useful zero value is an API design goal, not a guarantee for every custom type.

GLOSSARY

Vocabulary / Concurrent work

Data race

Conflicting concurrent memory accesses without the required synchronization, where at least one writes. Race-free does not automatically mean logically correct or deadlock-free.

Happens-before

A relation used by the memory model to reason about ordering and visibility through program order and synchronization.

Backpressure

A mechanism that prevents producers from outrunning downstream capacity indefinitely. Bounded queues, blocking admission, or explicit rejection are design choices.

Join

Waiting until owned concurrent work has actually finished. Cancellation alone does not perform a join.

Goroutine leak

Work that remains alive after its purpose or owner is gone, often blocked on a channel, I/O, or missing cancellation path.

Idempotency

A contract under which retrying an operation does not create an additional intended effect. The exact identity, payload rules, scope, and retention must be defined.

Linearization point

The conceptual instant at which a concurrent operation takes effect. In the reference store, the locked check-and-insert section establishes atomic creation relative to other store calls.

FINISH BY BUILDING

A practical mastery rubric

Foundation evidence

Without running code, predict copies, aliases, scopes, zero values, and error flow. Explain the difference between byte indexes, code points, and displayed characters. Revisit lessons 1-48 until your explanations are precise.

Core evidence

Implement a small package with documented contracts, narrow interfaces, meaningful table tests, and reproducible commands. Handle reader/writer failures and cleanup. Choose generics only where they clarify a real type relationship.

Concurrency evidence

For every goroutine, identify its owner, stop condition, and join. State the maximum number of active and queued tasks. Explain why the synchronized state is visible when read. Demonstrate cancellation and error tests under the race detector.

Production evidence

Trace one request through input bounds, authentication, authorization, state changes, retries, observability, and shutdown. Separate local guarantees from distributed guarantees. Profile a real bottleneck before optimizing.

Advanced evidence

Read unfamiliar standard-library source, form a performance hypothesis, design a reproducible experiment, and write a change proposal that names its risks. Review another engineer's implementation rather than only your own.

Completion is not certification

Reading every card is a useful milestone. Independent implementations, failure analysis, peer review, and operating experience are stronger evidence. Keep a short notebook of wrong predictions and the rules that corrected them.

AFTER THE LAST LESSON

Keep learning in small loops

A repeatable study session

Open one card, make one prediction, write one small test, and explain one result. On a later session, answer without reopening the solution. Move to the next card only after the explanation makes sense.

When you get stuck

Reduce the example to the smallest program that preserves the confusion. Write down expected versus observed behavior. Check the relevant specification or package contract, then add a regression test for the corrected understanding.

An optional capstone rotation

First rebuild the CLI. Next rebuild the task API and write a durable-state design without claiming it exists yet. Finally rebuild the worker engine and add a streaming variant. Review tradeoffs after each one.

Contributing a lesson
